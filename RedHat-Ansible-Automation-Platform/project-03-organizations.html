1. The Production Story

Day 3 at ABC Bank. A ticket lands from the Cards & Payments team: they want their own engineers to run their own playbooks against their own servers — but they must never be able to see the Core Banking team's Credentials, Inventories, or Job history, and vice versa. Compliance has flagged this explicitly: "Cards and Core Banking are separate audit domains. There must be a hard boundary between them inside AAP, not just a naming convention."

Our Team Lead tells us this is exactly what an Organization is for, and hands us the task of creating one for the Cards & Payments team before their engineers get onboarded next week.

2. Why Organizations Exist

An Organization is the single biggest container in AAP. Every other object we will learn — Users, Teams, Credentials, Projects, Inventories, Job Templates — belongs to exactly one Organization. Think of an Organization as a separate floor of the bank with its own locked door: what happens on the Core Banking floor is invisible to someone standing on the Cards & Payments floor, unless they've explicitly been given a key.

Without OrganizationsWith Organizations
Every team's Credentials and Inventories sit in one shared poolEach team's objects are contained within their own boundary
A naming convention ("prod-cards-...") is the only separation, and it's easy to break by accidentThe platform itself enforces the separation — a Cards engineer literally cannot see Core Banking's Credentials in the UI
Hard to answer "who could have accessed this?" during an auditAudit answer is immediate: only members of that Organization

3. The Organizations Screen

Where: left nav, under Access → Organizations. Who uses it: only Automation Admins — this is a platform-governance screen, not something a regular engineer touches. What you see: a table listing every Organization, with columns for Name, and counts of Users, Teams, and linked resources.

When we use this screenOnly when onboarding a genuinely new team/business unit onto AAP, or auditing which resources belong to which business unit. We do not create a new Organization for every project or every application — that's what Teams and Inventories are for, which we cover in Projects 05 and 09.

4. Every Field Explained (Add Organization form)

FieldWhat it meansABC Bank example
NameThe Organization's display name. Must be unique across the whole platform.ABC-Bank-Cards-Payments
DescriptionFree text — used by auditors and new joiners to understand the Organization's purpose at a glance."Owns all automation for Cards issuance and payment switch servers."
Instance GroupsWhich pool of execution capacity (which execution nodes) this Organization's jobs are allowed to run on — ties directly back to the Automation Mesh zones from Project 02.Cards' jobs pinned to the DMZ execution node group
Galaxy CredentialsWhich content source (Automation Hub) this Organization is allowed to pull Collections from.ABC Bank's internal approved Hub only
Max HostsA licensing/capacity cap — the maximum number of managed hosts this Organization can register.Set generously above their current 400 Cards servers, with headroom
Common mistakeLeaving Instance Groups unset. If left blank, the Organization can use any available execution node platform-wide — which quietly defeats the network-zone isolation we built with Automation Mesh in Project 02. Always pin it explicitly for a regulated bank environment.

5. Hands-On: Creating the Cards & Payments Organization

  • Click Access → Organizations.
  • Click the "Add" button top right of the list.
  • Type the Name: ABC-Bank-Cards-Payments — we always prefix with the bank name and business unit, per ABC Bank's naming standard, so it's unambiguous in a platform shared across many teams.
  • Type a Description explaining the scope, as shown in the table above — future auditors and new joiners will thank you.
  • Under Instance Groups, select the DMZ execution node group — Cards & Payments servers sit in the DMZ zone, per the mesh diagram from Project 02.
  • Click Save. The Organization now exists but is empty — no Users, Teams, or resources yet. We add the first Users to it in Project 04.
Production tipCreating the Organization is normally a five-minute task. The real work is the conversation beforehand with the business team and Compliance about exactly what should and shouldn't be visible across the boundary — get that agreement in writing before you click Save.

7. ABC Bank's Overall Organization Design

OrganizationBusiness Unit Covered
ABC-Bank-Core-BankingLedger, core transaction processing servers
ABC-Bank-Cards-PaymentsCard issuance, payment switch
ABC-Bank-Internet-BankingCustomer-facing web and mobile backend servers (DMZ)
ABC-Bank-Infra-SharedShared infrastructure services — DNS, monitoring, jump servers — used by the platform team itself
Why not one Organization for the whole bank?A single shared Organization would mean every team sees every other team's Credentials and Inventories in the UI, even if RBAC later blocks them from running jobs — Compliance rejected this outright during the design review, insisting on hard separation at the Organization level.

10. Interview Prep — Say This Out Loud

"What is an Organization in AAP, and why does it matter for a bank?"

It's the top-level tenant boundary — every Credential, Inventory, Project, and Template belongs to exactly one Organization, and the platform itself enforces that a user in one Organization cannot see another's resources. For a bank, this is how Compliance's "hard separation between business units" requirement gets technically enforced, not just documented.

"Does adding a user to an Organization give them access to run jobs?"

No — Organization membership alone grants nothing. Actual permissions come from RBAC roles assigned on top, which we cover in Project 19. Organization is the boundary; RBAC is the key.

11. Wrap-Up

Key Learnings

  • Organization is the top-level, platform-enforced tenant boundary in AAP.
  • Every other object belongs to exactly one Organization.
  • Membership in an Organization is not the same as having permission to do anything inside it.
