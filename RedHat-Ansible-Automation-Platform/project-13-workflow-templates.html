PROJECT 13 OF 30 · RESOURCES LAYER

Workflow Templates

Chaining Job Templates together with real branching logic — success goes one way, failure goes another.

1. The Production Story

Day 13 at ABC Bank. Ravi brings a real multi-step requirement from the Release team: before deploying a new build to the Cards application servers, they always run a pre-deployment health check first. If that check fails, deployment must not proceed, and someone must be notified immediately. If it passes, deploy, then run a post-deployment smoke test. Today, this was three separate manual steps an engineer coordinated by hand, watching each one before deciding whether to run the next.

A single Job Template can't express "do this, then branch based on success or failure." Today we build a Workflow Template that does exactly that.

2. Why One Job Template Isn't Enough Here

A Job Template runs exactly one playbook. A Workflow Template is a different object entirely — a visual graph of nodes, where each node can be a Job Template, another nested Workflow, an Approval gate (Project 20), or a few other node types, connected by On Success, On Failure, and Always links. This is how we express "only deploy if the health check passed" without writing any custom glue code.

3. The Workflow Visualizer

Where: Resources → Templates → Add → Add Workflow Template, which opens a dedicated drag-and-drop canvas called the Workflow Visualizer. Who uses it: Automation Admins design workflows; engineers with Execute access launch the whole chain with one click, same as a Job Template. What you see: a canvas where you add a Start node, then click the "+" to attach the first real node, then keep branching.

5. Node Types We'll Use

Node TypeWhat it does
Job Template nodeRuns an existing Job Template — like our Project 12 health check.
Workflow nodeRuns another Workflow Template nested inside this one — for reusing a common sub-sequence.
Approval nodePauses the workflow until a human explicitly approves or denies — covered fully in Project 20.
Set Stats nodeA lightweight node that just sets a variable value, useful for passing small pieces of data between nodes.

6. Hands-On: Building the Deployment Workflow

  • Click Resources → Templates → Add → Add Workflow Template.
  • Name: Cards - Deployment Pipeline; Organization: ABC-Bank-Cards-Payments. Click Save — this opens the Visualizer.
  • Click the "+" on the Start node. Choose Node Type = Job Template, select Cards - Linux Health Check (built in Project 12). Click Save.
  • Hover over that node → click the small green "+" (On Success branch). Add a second node, Job Template = Cards - Deploy Application Build (a template our Application team already built separately).
  • Hover over the health-check node again → click the small red "+" (On Failure branch). Add a Job Template node = Notify - Send Slack Alert, so the team is paged immediately if the pre-check fails, instead of deployment silently continuing.
  • Hover over the deploy node → On Success → add one more node: Job Template = Cards - Post-Deploy Smoke Test.
  • Click Save on the Visualizer toolbar. The full chain is now one launchable object.

Production tipNotice deployment is structurally impossible unless the health check succeeds — this isn't a process instruction engineers have to remember, it's enforced by the graph itself.

7. Convergence & Multiple Paths

Workflows can also converge — two different upstream nodes both feeding into one downstream node, which by default only runs once all its required upstream branches have completed. This becomes useful once we cover Approval Nodes (Project 20), where, say, both a technical health check and a manager's Approval must succeed before a production node runs.

9. Troubleshooting

SymptomLikely Cause
Workflow runs the deploy node even though the health check failedThe link between the two nodes was set to "Always" instead of "On Success" — check the branch type in the Visualizer
A node never starts even though its parent succeededConvergence — it may be waiting on a second parent branch that hasn't completed yet
Whole workflow shows as failed even though every node succeededCheck for a node still in a Denied/Pending Approval state (Project 20) further down the graph

10. Interview Prep — Say This Out Loud

"What's the difference between a Job Template and a Workflow Template?"

A Job Template runs exactly one playbook. A Workflow Template is a graph of nodes — Job Templates, nested Workflows, Approval gates — connected by On Success/On Failure/Always links, letting you express multi-step processes with real branching logic in a single launchable object.

"How would you make sure a deployment never runs if a pre-check fails?"

Connect the pre-check node to the deployment node using an On Success link only, and route On Failure to a separate alerting node — this makes the safety gate structural rather than relying on an engineer remembering to check manually.

11. Wrap-Up

Key Learnings

  • Workflow Templates chain Job Templates (and other node types) with real success/failure branching.
  • Branch type (On Success / On Failure / Always) is what actually enforces process safety, not documentation or training.
  • Nodes can converge, waiting on multiple upstream branches — this becomes essential with Approval Nodes.
