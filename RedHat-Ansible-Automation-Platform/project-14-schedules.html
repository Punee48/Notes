Schedules

Making the health check run itself every night, without Priya having to remember to click Launch.

1. The Production Story

Day 14 at ABC Bank. Our Team Lead points out a gap: the Cards - Linux Health Check template is excellent, but it only runs when someone remembers to launch it. Compliance wants proof that health checks run every night at 11 PM IST, without depending on a human's memory. Today we make that automatic with a Schedule.

2. Why Schedules, Not a Cron Job

ABC Bank's old process used a plain Linux cron job on a jump server calling ansible-playbook directly — invisible to the Controller, with no audit trail and no RBAC. An AAP Schedule triggers a real Job Template launch through the platform itself, which means every scheduled run appears in Job history exactly like a manual one — same audit trail, same Job Output, same notifications.

3. The Schedules Screen

Where: two places — a dedicated Views → Schedules screen listing every schedule platform-wide, and a "Schedules" tab inside any individual Template. Who uses it: Automation Admins, and Team Leads with edit access to their own templates.

5. Hands-On: Scheduling the Health Check

  • Open Resources → Templates → Cards - Linux Health Check → Schedules tab → Add.
  • Name: Nightly Cards Health Check
  • Start Date/Time: today's date, 23:00.
  • Time Zone: select Asia/Kolkata explicitly — never leave this on a default you haven't checked.
  • Repeat Frequency: Daily, every 1 day.
  • Click Save. The template now runs itself every night at 11 PM IST, appearing in Job history exactly like a manual launch, tagged as triggered by "Schedule" instead of a username.

6. Scheduling a Template That Has Prompts

If a Job Template is configured to prompt for a Survey answer or a Limit at launch time (we cover Surveys fully in Project 18), a Schedule must supply fixed values for those prompts up front, since nobody is present at 11 PM to answer them interactively. AAP shows these as extra fields directly on the Schedule creation form when they apply.

7. Time Zones — A Frequent Mistake

Common mistakeLeaving Time Zone on whatever the Controller server's OS default happens to be (often UTC), while assuming it means IST. A "23:00" schedule created without checking this can silently run at 4:30 AM IST instead of 11 PM — always explicitly select Asia/Kolkata for ABC Bank's local schedules rather than trusting the default.

10. Interview Prep — Say This Out Loud

"Why use AAP Schedules instead of a plain cron job calling ansible-playbook?"

A cron job bypasses the platform entirely — no audit trail, no RBAC, no centralized log. An AAP Schedule triggers a real Job Template launch through the Controller, so every scheduled run shows up in Job history exactly like a manual one, fully auditable.

"What's a common mistake people make when setting up a Schedule?"

Not explicitly setting the Time Zone field and assuming it matches local time — if it defaults to UTC, an "11 PM" schedule can silently run at the wrong hour locally.

11. Wrap-Up

Key Learnings

  • Schedules trigger real, auditable Template launches through the Controller — unlike an invisible cron job.
  • Always explicitly set the Time Zone field rather than trusting a default.
  • Templates with Survey prompts need fixed values supplied directly on the Schedule.
