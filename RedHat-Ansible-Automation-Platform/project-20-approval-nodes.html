Approval Nodes

Putting a real human sign-off, not just a Slack message, between "health check passed" and "production deployment happens."

1. The Production Story

Day 20 at ABC Bank. Our Deployment Pipeline workflow from Project 13 automatically deploys the moment the pre-check passes — fully automated, no human in the loop at all. The Release Manager raises a concern during a governance review: "For Cards production specifically, our change process requires a named approver to explicitly sign off before any deployment, even if the automated check is green. That has to be enforced by the tool, not by a step in a document nobody reads."

Today we add an Approval Node to the workflow — the point where automation pauses and waits for Ravi (a member of the Cards-Payments-Approvers Team from Project 19) to explicitly click Approve.

2. Why a Human Gate Belongs Inside the Workflow

We could ask engineers to "pause and get sign-off before continuing," but that relies on discipline and memory — exactly the kind of manual step ABC Bank moved away from throughout Projects 01–19. An Approval Node makes the pause structural: the workflow itself cannot proceed past that node until someone with the Approve role clicks Approve, and every decision — who approved, when, and any comment left — is permanently recorded in the workflow's Job history.

3. Adding an Approval Node in the Visualizer

Where: inside the Workflow Visualizer we used in Project 13 — when adding a new node, "Approval" is one of the Node Type options alongside Job Template and Workflow. Who uses it: Automation Admins place it while designing the workflow; anyone with the Approve role on that specific node uses it at runtime.

5. Hands-On: Gating the Deployment Pipeline

  • Open Resources → Templates → Cards - Deployment Pipeline → the Visualizer.
  • Hover over the health-check node's On Success branch → click "+" → change the destination. Instead of linking straight to the Deploy node, insert a new node first.
  • Node Type: Approval; Name: Cards Production Deployment Sign-Off; Timeout: 4 hours.
  • Re-link: Health Check → On Success → Approval Node → On Success → Deploy node (the On Failure branch to the Slack alert node stays exactly as it was in Project 13).
  • Grant the Approve role on this node to the Cards-Payments-Approvers Team (Access tab on the node, same mechanism as Project 19).
  • Save. The pipeline is now: automated pre-check → human sign-off → automated deploy → automated smoke test.

6. What the Approver Actually Sees

  • Ravi gets a Notification (Project 15, tied to this node's "Approval Requested" trigger) telling him a workflow is waiting.
  • He opens Views → Jobs, finds the running workflow, and sees it paused at the Approval Node with the Description text we wrote above.
  • He clicks Approve or Deny, optionally leaving a comment (e.g. "Confirmed with change ticket CHG0012345").
  • The workflow immediately continues down the matching branch — this decision, timestamp, and comment are now a permanent part of the Job's audit record.

7. Timeout Behavior — A Critical Detail

Common mistakeLeaving Timeout unset (infinite). If Ravi is on leave and nobody else has the Approve role, a workflow could sit paused indefinitely, silently blocking a release with no one aware it's stuck. ABC Bank sets a 4-hour timeout that auto-denies and notifies the Release Manager, forcing a conscious decision to re-trigger rather than an invisible stall.

10. Interview Prep — Say This Out Loud

"How would you enforce a mandatory human sign-off before a production deployment in AAP?"

Insert an Approval Node into the Workflow between the pre-check and the deployment node, grant the Approve role only to the intended approvers via RBAC, and set a reasonable timeout so the workflow doesn't stall indefinitely if nobody responds.

"What happens if an Approval Node times out?"

It's treated as a denial by default — the workflow follows the Denied/Timed Out branch rather than silently hanging, which is why setting a sensible timeout instead of leaving it infinite matters for production reliability.

11. Wrap-Up

Key Learnings

  • Approval Nodes make a human sign-off structural, not just procedural.
  • Who can approve is entirely governed by RBAC's Approve role on that specific node.
  • Always set a timeout — an infinite wait can silently stall a release.
