8. Capstone Interview — Full Walkthrough

"Describe, end to end, how you'd onboard a new business unit onto AAP."

Start with the tenant boundary — create the Organization, then Teams split by responsibility (engineers, approvers, admins). Build the Credentials using dedicated service accounts, connect a Git-backed Project pinned to release tags, structure the Inventory with role-based Groups, and build Job Templates for the core operations (health check, deploy, patch, compliance). Wire these into a Workflow with an Approval gate and ServiceNow/Slack notifications, schedule the recurring operational jobs, and finally validate the whole thing against a least-privilege RBAC review before go-live.

"What would you do differently if you were designing this from scratch today, knowing everything you now know?"

A strong answer references specific lessons: building the multi-dimensional health check (Project 25) from day one instead of starting with a disk-only check; deciding the Team structure (Project 05) before onboarding any Users, rather than restructuring later; and setting Execution Environment version pinning (Project 16) as a standard from the very first template.
