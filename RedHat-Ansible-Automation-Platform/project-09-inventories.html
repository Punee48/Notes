Inventories

Telling AAP exactly which servers exist — the last missing ingredient before we can finally build a real Job Template.

1. The Production Story

Day 9 at ABC Bank. We now have a User, a Team, a Credential, and a Project synced from Git. Ravi asks the obvious next question: "Fine, but which servers does any of this actually run against? Nobody has told AAP that our Cards & Payments estate has 42 Linux application servers and 12 Windows servers."

Our Team Lead nods — this is today's task. We are going to create the Inventory object: the list of managed nodes, grouped sensibly, that every future Job Template will target.

2. Why Inventory Is Its Own Object

In plain Ansible, an inventory is usually just a text file (/etc/ansible/hosts or a project-local inventory.ini) sitting on whichever laptop happens to run the command. In AAP, Inventory is promoted to a first-class, centrally managed object — because the whole point of the platform is that "which servers exist" should not depend on which engineer's laptop you're standing at.

3. The Inventories Screen

Where: left nav, under Resources → Inventories. Who uses it: Automation Admins create and maintain Inventories; engineers select one on a Job Template but rarely edit it directly. What you see: a list of Inventories, each tagged with its Organization and a host count.

4. Inventory Types We'll Use

Static Inventory

Hosts and Groups added manually or pasted in — what we'll build today for the Cards & Payments estate.

Smart Inventory

A saved filter/search across existing Hosts (e.g. "all hosts with OS = RHEL9") rather than a separately maintained list — useful once our host count grows large.

Dynamic (Sourced) Inventory

Automatically pulled from an external system — AWS, Azure, VMware — instead of typed in by hand. Previewed below; we build one fully in a later cloud-focused project.

  • Name: Cards-Payments-Servers
  • Organization: ABC-Bank-Cards-Payments
  • Instance Groups: select the DMZ execution node group.
  • Click Save. The Inventory exists but is empty — we add Groups and Hosts to it in Project 10 and Project 11.
Production tipWe deliberately split this into three projects (Inventory shell today, Hosts in Project 10, Groups in Project 11) — in real onboarding work, this is genuinely how it goes: you agree the container first with the business, then populate it carefully, because a wrong host in the wrong inventory could mean a playbook targets the wrong production server.

7. A Look Ahead: Dynamic Inventory Sources

Typing in 42 Linux servers by hand today is manageable — but ABC Bank's Cloud Infrastructure team is migrating workloads to AWS next quarter, and nobody wants to manually update an inventory every time an EC2 instance is launched or terminated. A Dynamic (Sourced) Inventory instead queries AWS directly at sync time and builds the host list automatically, tagged by whatever EC2 tags the Cloud team already uses (e.g. Environment=production, Application=cards).

8. Inventory Sync — What Happens Underneath

Even for our static Inventory today, "sync" is a meaningful concept once we add a Source later. For now, understand the general shape: whenever an Inventory has a Source configured, AAP calls out to that source, retrieves the current host list, and reconciles it against what's already stored — adding new hosts, removing ones that no longer exist, and preserving any host variables we've manually set.

11. Interview Prep — Say This Out Loud

"What is an Inventory in AAP, and why isn't it just a text file like plain Ansible?"

It's a centrally managed, auditable list of managed hosts belonging to an Organization, instead of a file sitting on one engineer's laptop. It can be static (typed in), Smart (a saved filter), or Dynamic (auto-populated from a cloud provider), and every Job Template references it by name rather than a local file path.

"What's the difference between a static and a dynamic inventory, and when would you use each?"

Static is manually maintained — fine for a small, stable estate. Dynamic queries an external source like AWS at sync time and builds the host list automatically, which is essential once infrastructure is elastic and hosts come and go on their own.

12. Wrap-Up

Key Learnings

  • Inventory in AAP is a centrally managed object, not a laptop-local file.
  • Static, Smart, and Dynamic are the three inventory types, each suited to a different situation.
  • Instance Group pinning on an Inventory reinforces the network-zone isolation from Automation Mesh.
