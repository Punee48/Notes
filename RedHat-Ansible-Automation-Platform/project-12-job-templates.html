2. Why Job Template Is the Object Everyone Clicks

A Job Template is a saved combination: this Playbook, from this Project, against this Inventory, using this Credential, with these options. Once saved, an engineer with Execute permission never has to know or choose any of those underlying pieces again — they just find the template by name and click Launch. This is precisely why we spent 11 projects building the ingredients first: a Job Template is only as good as the objects it references.

5. The Real Playbook Behind This Template

This is a more complete version of the health-check playbook from Project 01 — now correctly targeting our linux_servers Group and reading the patch_group host variable we set in Project 10.

---
# File: playbooks/linux_healthcheck.yml
- name: Cards Payments Linux Health Check  # Shown as the Play name in AAP Job Output
  hosts: linux_servers                       # Targets the Group we built in Project 11 — no hostnames hardcoded
  gather_facts: yes

  tasks:
    - name: Report which patch group this host belongs to
      ansible.builtin.debug:
        msg: "{{ inventory_hostname }} is in patch_group {{ patch_group }}"  # Reads the Host Variable from Project 10

    - name: Check disk space
      ansible.builtin.command: df -h
      register: disk_output

    - name: Fail if root partition is over 90% full
      ansible.builtin.assert:                # A real health check should actually assert a pass/fail condition, not just print output
        that:
          - "'90%' not in disk_output.stdout"  # Simplified condition for teaching purposes
        fail_msg: "Root partition is critically full"
        success_msg: "Disk space healthy"
Why this version is better than Project 01'sUsing assert instead of only debug means this playbook now has a real pass/fail signal — the Job Output will show a genuine failure if disk space is critical, which is what lets this template eventually be trusted inside a Workflow (Project 13) or a Schedule (Project 14).

6. Hands-On: Building the Template, Click by Click

  • Click Resources → Templates → Add → Add Job Template.
  • Name: Cards - Linux Health Check
  • Job Type: leave as Run.
  • Inventory: click the picker, select Cards-Payments-Servers.
  • Project: select Cards-Payments-Playbooks — this must be selected before the Playbook dropdown populates.
  • Playbook: select playbooks/linux_healthcheck.yml from the now-populated dropdown.
  • Credentials: click the picker, select Cards-Payments-Linux-SSHKey.
  • Execution Environment: select ABC-Bank-Linux-EE.
  • Under Options, check "Enable Privilege Escalation." Leave "Concurrent Jobs" unchecked.
  • Click Save. The template now exists — but nobody except us can see it yet.

8. Granting the Cards-Payments-Engineers Team Access

  • Open the template → click the "Access" (or "Team Access") tab.
  • Click "Add" → select Team → choose Cards-Payments-Engineers (built in Project 05).
  • Choose role: "Execute." This lets every member launch the template, but not edit its Inventory/Project/Credential wiring.
  • Save. Priya and Ravi can now see and launch this template — this is the RBAC "Execute" role we previewed conceptually back in Project 05, now made concrete.

11. Interview Prep — Say This Out Loud

"Walk me through building a Job Template from scratch."

Talk through the sequence: pick the Inventory, pick the Project (which must sync successfully first), pick the specific playbook file from that Project, attach the right Credential, pick the Execution Environment, configure options like privilege escalation and concurrency, save, then grant a Team Execute access so engineers can actually use it.

"What's the difference between a 'Run' and a 'Check' job type?"

Run executes the playbook normally, making real changes. Check performs a dry run (equivalent to ansible-playbook's --check flag), reporting what would change without actually changing anything — useful for validating a new or edited playbook before trusting it against production.

12. Wrap-Up

Key Learnings

  • A Job Template is a saved combination of Inventory + Project + Playbook + Credential + options.
  • Team Access (Execute role) is what actually lets engineers see and launch it — building the template alone isn't enough.
  • Using assert gives a playbook a real pass/fail signal, which matters once it's used inside Workflows or Schedules.
