Chapter 1 — The Shell Universe

Understanding what Bash is, why it matters, and your first script

● Beginner
📖 Story

Imagine you just joined a DevOps team at a startup called CloudNova. Your first task: manually SSH into 50 servers every morning, check disk usage, restart failed services, and send a report email. You spend 3 hours doing it manually. Your senior engineer watches you, smiles, and says: "Write a Bash script. It'll do all that in 2 seconds." That's Bash — your automation superpower.

What is Bash?

Bash (Bourne Again Shell) is a command-line interpreter — a program that reads commands you type (or write in a file) and executes them. It's the default shell on most Linux distros and macOS (pre-Catalina). A shell script is simply a text file containing a sequence of these commands.

🐚 Shell

An interface between you and the kernel. Takes commands, gives them to the OS, returns results.

📜 Script

A text file of commands executed in sequence. Think of it as a recipe for your computer.

🔧 Automation

Replace repetitive manual steps with a single command. The core power of scripting.

⚡ Shebang

#!/bin/bash — the first line that tells the OS which interpreter to use.

Your First Script

hello_cloudnova.sh 
#!/bin/bash
# This is a comment — Bash ignores lines starting with #
# Every script starts with a shebang (#!/bin/bash)

# Print a greeting
echo "Welcome to CloudNova! Starting system check..."

# Show current date/time
echo "Today is: $(date)"

# Show who is logged in
echo "Logged in as: $(whoami)"

# Show hostname
echo "Server: $(hostname)"
$ chmod +x hello_cloudnova.sh   # make it executable
$ ./hello_cloudnova.sh
Welcome to CloudNova! Starting system check...
Today is: Mon Jun 9 10:42:31 IST 2026
Logged in as: devops
Server: prod-server-01
💡 Key Commands to Know

chmod +x script.sh — makes script executable. bash script.sh — run without making executable. ./script.sh — run executable script. which bash — find Bash location.

🎯 Interview Question (4 YOE)

Q: What is the difference between #!/bin/bash and #!/usr/bin/env bash?
A: #!/bin/bash hardcodes the path. #!/usr/bin/env bash searches $PATH for bash — more portable across systems where bash may not be at /bin/bash (e.g., macOS with Homebrew, or some containers).

Chapter 2 — Variables & Data Types

Store, retrieve, and manipulate data in your scripts

● Beginner
📖 Story

Back at CloudNova, you need to write a script that deploys an app to different environments (dev, staging, prod). The app name, version, and environment keep changing. Instead of hardcoding everything, you use variables — named containers that hold values you can swap easily.

Variable Basics

variables.sh 
#!/bin/bash

# ── DECLARING VARIABLES ──────────────────────
# NO spaces around = sign! (This is the #1 beginner mistake)
APP_NAME="cloudnova-api"
VERSION="2.4.1"
PORT=8080
IS_PROD=false

# ── ACCESSING VARIABLES ──────────────────────
# Use $ prefix to read the value
echo "Deploying: $APP_NAME"
echo "Version: $VERSION"
echo "Port: $PORT"

# ── CURLY BRACES ─────────────────────────────
# Use ${VAR} when concatenating or avoiding ambiguity
echo "App folder: ${APP_NAME}_v${VERSION}"
# Output: App folder: cloudnova-api_v2.4.1

# ── COMMAND SUBSTITUTION ──────────────────────
# Capture output of a command into a variable
CURRENT_USER=$(whoami)
TODAY=$(date +%Y-%m-%d)
DISK_USAGE=$(df -h / | awk 'NR==2 {print $5}')

echo "Deployed by $CURRENT_USER on $TODAY"
echo "Disk used: $DISK_USAGE"

# ── READONLY VARIABLES ───────────────────────
# Constants that can't be changed
readonly MAX_RETRIES=3
readonly DB_HOST="db.cloudnova.internal"

# ── UNSET VARIABLES ──────────────────────────
TEMP_VAR="I'm temporary"
unset TEMP_VAR
echo "After unset: '$TEMP_VAR'"  # prints empty

Special Variables (Critical for Interviews!)

special_vars.sh 
#!/bin/bash
# Run as: ./special_vars.sh arg1 arg2 arg3

echo "Script name:       $0"   # ./special_vars.sh
echo "First argument:    $1"   # arg1
echo "Second argument:   $2"   # arg2
echo "All arguments:     $@"   # arg1 arg2 arg3
echo "Arg count:         $#"   # 3
echo "Process ID (PID):  $$"   # current script PID
echo "Last exit code:    $?"   # 0 = success, non-zero = failure
echo "Last bg job PID:   $!"   # PID of last background process

# $@ vs $* difference (crucial!)
function show_args {
    echo "With \$@: loops each arg separately"
    for arg in "$@"; do echo "  → $arg"; done
}
show_args "hello world" "foo bar"
# → hello world
# → foo bar   (preserves spaces — use "$@" not "$*")

Environment Variables

env_vars.sh 
#!/bin/bash
# Environment variables are available to all child processes

# Export makes a variable available to child processes
export DATABASE_URL="postgres://localhost:5432/cloudnova"
export API_KEY="sk-abc123xyz"

# Commonly used built-in env vars
echo "Home dir:    $HOME"

echo "Path:        $PATH"
echo "PWD:         $PWD"
echo "Hostname:    $HOSTNAME"

SyntaxMeaningExample
${VAR:-default}Use default if VAR is unset or empty${ENV:-prod}
${VAR:=default}Set and use default if unset${LOG:=/var/log}
${VAR:?message}Error and exit if unset${API_KEY:?API_KEY required}
${VAR:+alternate}Use alternate if VAR IS set${DEBUG:+--verbose}
${#VAR}Length of variable${#NAME} → 5
🎯 Interview Questions (4 YOE)

Q: What's the difference between $@ and $*?
A: Both expand to all positional parameters. When quoted: "$@" preserves each argument as a separate word (e.g., "arg 1" "arg 2"). "$*" concatenates all into one word separated by the first char of IFS.

Q: How do you make a variable available to child processes?
A: Use export VAR=value. Without export, the variable is local to the current shell and child processes won't inherit it.

Chapter 3 — Input / Output & Redirection

Reading data in, writing data out, piping between commands

● Beginner
🎬 Scenario

Your CloudNova script needs to: read a config file, ask the admin for a password, write logs to a file, and discard error noise from some commands. All of this is I/O redirection.

Standard Streams

stdin (0)

Standard Input — keyboard or piped data. File descriptor 0.

stdout (1)

Standard Output — normal command output. File descriptor 1.

stderr (2)

Standard Error — error messages. File descriptor 2.

io_redirection.sh 
#!/bin/bash

# ── OUTPUT REDIRECTION ────────────────────────
echo "Deploy started" > deploy.log        # overwrite
echo "Step 2 done"   >> deploy.log       # append

# ── REDIRECT STDERR ───────────────────────────
ls /nonexistent 2> error.log             # save errors to file
ls /nonexistent 2>/dev/null              # discard errors (very common!)
ls /nonexistent 2>&1                     # redirect stderr to stdout

# ── REDIRECT BOTH stdout AND stderr ──────────
./deploy.sh > all.log 2>&1               # everything to one file
./deploy.sh &> all.log                   # shorthand (bash only)

# ── INPUT REDIRECTION ─────────────────────────
wc -l < deploy.log                       # feed file as stdin

# ── HERE DOCUMENT (heredoc) ───────────────────
cat << EOF > config.conf
APP_NAME=cloudnova
VERSION=2.4.1
DB_HOST=localhost
EOF

# ── HERE STRING ───────────────────────────────
grep "error" <<< "This is an error message"

# ── PIPES ─────────────────────────────────────
# Connect stdout of cmd1 to stdin of cmd2
ps aux | grep nginx | grep -v grep
cat /var/log/syslog | grep ERROR | tail -n 20
df -h | awk 'NR>1 {print $1, $5}' | sort -k2 -rn

# ── READING USER INPUT ────────────────────────
read -p "Enter environment (dev/staging/prod): " ENV
read -sp "Enter password: " PASSWORD          # -s = silent (no echo)
read -t 30 -p "Continue? (y/n): " CONFIRM    # -t = timeout in seconds
read -a SERVERS <<< "server1 server2 server3"  # read into array

echo  # newline after silent input
echo "Deploying to: $ENV"

tee — Write to File AND Screen

logging_example.sh 
#!/bin/bash
# tee: write to stdout AND a file simultaneously
echo "Deployment starting..." | tee -a deploy.log
./run_tests.sh 2>&1 | tee test_results.log   # see output + save it

# Process substitution (advanced, but 4YOE must know)
diff <(sort file1.txt) <(sort file2.txt)   # compare sorted outputs
🎯 Interview Question (4 YOE)

Q: What does 2>&1 mean and why does order matter?
A: It redirects stderr (fd 2) to wherever stdout (fd 1) currently points. Order matters: cmd > file 2>&1 sends both to file. But cmd 2>&1 > file sends stderr to terminal (original stdout) and stdout to file — because 2>&1 evaluates at that point before stdout is redirected.

Chapter 4 — Conditionals & Logic

Making decisions in your scripts with if, case, and test expressions

● Beginner
📖 Story

CloudNova's deployment script needs intelligence: if the environment is production, require manual approval. If disk usage is above 90%, abort. If tests pass, deploy; else notify and exit. Conditionals are the brain of your script.

if / elif / else

conditionals.sh 
#!/bin/bash

# ── BASIC IF ──────────────────────────────────
ENV="production"

if [[ "$ENV" == "production" ]]; then
    echo "⚠️  PRODUCTION deployment — requires approval"
elif [[ "$ENV" == "staging" ]]; then
    echo "Staging deploy — running smoke tests first"
else
    echo "Dev deploy — going fast!"
fi

# ── STRING COMPARISONS ────────────────────────
NAME="Alice"
[[ "$NAME" == "Alice" ]]    # exact match
[[ "$NAME" != "Bob" ]]      # not equal
[[ "$NAME" == "Al*" ]]      # glob pattern match (use [[ ]])
[[ "$NAME" =~ ^[A-Z][a-z]+$ ]] # regex match (=~)
[[ -z "$NAME" ]]            # empty string?
[[ -n "$NAME" ]]            # non-empty string?

# ── NUMERIC COMPARISONS ───────────────────────
DISK=87
if [[ $DISK -gt 90 ]]; then
    echo "CRITICAL: Disk usage at $DISK%"
elif [[ $DISK -gt 80 ]]; then
    echo "WARNING: Disk usage at $DISK%"
fi
# -eq  equal        -ne  not equal
# -lt  less than    -le  less or equal
# -gt  greater      -ge  greater or equal

# ── FILE/DIR TESTS ────────────────────────────
if [[ -f "/etc/nginx/nginx.conf" ]]; then
    echo "Nginx config exists"
fi
# -f  regular file        -d  directory
# -e  exists              -r  readable
# -w  writable            -x  executable
# -s  non-empty file      -L  symbolic link
# -nt newer than          -ot older than

# ── LOGICAL OPERATORS ─────────────────────────
if [[ "$ENV" == "prod" ]] && [[ $DISK -lt 90 ]]; then
    echo "OK to deploy to prod"
fi
if [[ "$ENV" == "dev" ]] || [[ "$ENV" == "staging" ]]; then
    echo "Non-prod environment"
fi

case Statement

case_example.sh 
#!/bin/bash

ACTION="$1"

case "$ACTION" in
    start)
        echo "Starting services..."
        systemctl start nginx
        ;;
    stop)
        echo "Stopping services..."
        systemctl stop nginx
        ;;
    restart|reload)               # match either word
        echo "Restarting nginx..."
        systemctl restart nginx
        ;;
    status)
        systemctl status nginx
        ;;
    *)
        echo "Usage: $0 {start|stop|restart|status}"
        exit 1
        ;;
esac

Short-Circuit Operators

short_circuit.sh 
#!/bin/bash
# && = run second only if first succeeds (exit 0)
# || = run second only if first fails (non-zero exit)

mkdir -p /var/app/logs && echo "Directory created"
ping -c1 db.server.com &>/dev/null || echo "DB unreachable!"

# Chain commands idiomatically
cd /app && git pull && npm install && pm2 restart all

# Ternary-like pattern in Bash
[[ $DEBUG -eq 1 ]] && LOG_LEVEL="verbose" || LOG_LEVEL="info"
🎯 Interview Question (4 YOE)

Q: What's the difference between [ ], [[ ]], and (( ))?
A: [ ] is POSIX sh test command — portable but limited. [[ ]] is bash keyword — supports regex (=~), glob patterns, no word-splitting, no need to quote variables. (( )) is arithmetic evaluation — for integer math and numeric comparisons (e.g., (( disk > 90 ))). Use [[ ]] for most conditions and (( )) for arithmetic.

Chapter 5 — Loops & Iteration

for, while, until — automating repetitive tasks at scale

● Beginner / Intermediate
📖 Story

CloudNova adds 20 new servers. You need to install nginx on each, check health, and add them to a load balancer config. Doing it manually for each server is out of the question. Loops are how you automate at scale.

for Loop — All Flavors

loops.sh 
#!/bin/bash

# ── FOR OVER A LIST ──────────────────────────
SERVERS=("web-01" "web-02" "web-03" "db-01")
for server in "${SERVERS[@]}"; do
    echo "Installing nginx on: $server"
    ssh "$server" "apt-get install -y nginx"
done

# ── FOR OVER FILES ───────────────────────────
for logfile in /var/log/*.log; do
    echo "Processing: $logfile"
    gzip "$logfile"
done

# ── C-STYLE FOR LOOP ─────────────────────────
for (( i=1; i<=10; i++ )); do
    echo "Attempt $i: checking health..."
done

# ── BRACE EXPANSION RANGE ────────────────────
for num in {1..5}; do
    echo "Server $num"
done

# ── FOR WITH STEP ────────────────────────────
for port in {8080..8090..2}; do   # 8080, 8082, 8084...
    echo "Checking port $port"
done

# ── FOR OVER COMMAND OUTPUT ──────────────────
for pid in $(pgrep nginx); do
    echo "nginx PID: $pid"
done

while and until Loops

while_loops.sh 
#!/bin/bash

# ── WHILE LOOP ───────────────────────────────
RETRIES=0
MAX=5

while [[ $RETRIES -lt $MAX ]]; do
    if curl -sf http://localhost:8080/health; then
        echo "Service is UP!"
        break
    fi
    (( RETRIES++ ))
    echo "Retry $RETRIES/$MAX... waiting 5s"
    sleep 5
done
[[ $RETRIES -eq $MAX ]] && { echo "Service failed to start!"; exit 1; }

# ── READ FILE LINE BY LINE ───────────────────
while IFS= read -r line; do
    echo "Processing: $line"
done < servers.txt

# ── UNTIL LOOP (opposite of while) ───────────
COUNTER=0
until [[ $COUNTER -ge 3 ]]; do
    echo "Count: $COUNTER"
    (( COUNTER++ ))
done

# ── INFINITE LOOP (common in monitoring scripts)
while true; do
    check_disk_usage    # a function call
    sleep 60            # check every minute
done
⚡ loop control keywords

break — exit the loop immediately. continue — skip to next iteration. break 2 — break out of 2 nested loops. Always use IFS= read -r line when reading files line-by-line to preserve spaces and backslashes.

🎯 Interview Question (4 YOE)

Q: Why use while IFS= read -r line instead of just for line in $(cat file)?
A: $(cat file) in a for loop word-splits on spaces/tabs/newlines, breaking lines with spaces. It also loads the whole file into memory. while read reads one line at a time, preserves spaces within lines, and handles large files efficiently. IFS= prevents leading/trailing whitespace from being stripped; -r prevents backslash interpretation.

Chapter 6 — Functions

Modular, reusable code blocks — the backbone of serious scripts

● Intermediate
📖 Story

Your CloudNova deploy script grew to 300 lines. The disk check appears in 5 different places. Every time you fix a bug, you fix it in 5 places. Your tech lead says: "Stop copy-pasting — write a function." Functions are the building blocks of maintainable shell scripts.

functions.sh 
#!/bin/bash

# ── DEFINING FUNCTIONS ────────────────────────
function greet {
    echo "Hello, $1!"
}

greet_v2() {                         # alternative syntax (more portable)
    echo "Hello, $1!"
}

# ── RETURN VALUES ────────────────────────────
# Bash functions can only return exit codes (0-255)
# To return strings, use echo + command substitution

get_disk_pct() {
    local path="${1:-/}"
    df -h "$path" | awk 'NR==2 {gsub(/%/,""); print $5}'
}

DISK=$(get_disk_pct /)
echo "Disk: $DISK%"

# ── LOCAL VARIABLES ──────────────────────────
# Always use 'local' inside functions to avoid polluting global scope
deploy_app() {
    local app_name="$1"
    local version="$2"
    local env="${3:-development}"

    echo "Deploying $app_name v$version to $env"
    return 0   # explicit success
}

# ── RETURN CODE CHECKING ─────────────────────
deploy_app "cloudnova-api" "2.4.1" "staging"
if [[ $? -eq 0 ]]; then
    echo "Deploy successful!"
fi

# ── FUNCTIONS WITH COMPLEX LOGIC ─────────────
check_prerequisites() {
    local missing=0

    for cmd in git docker kubectl curl jq; do
        if ! command -v "$cmd" &>/dev/null; then
            echo "❌ Missing: $cmd"
            (( missing++ ))
        else
            echo "✅ Found: $cmd"
        fi
    done

    [[ $missing -gt 0 ]] && return 1 || return 0
}

check_prerequisites || { echo "Install missing tools first!"; exit 1; }

# ── LOGGING UTILITY FUNCTION (reusable pattern)
LOG_FILE="/var/log/deploy.log"

log() {
    local level="$1"; shift
    local msg="$*"
    local timestamp=$(date "+%Y-%m-%d %H:%M:%S")
    echo "[$timestamp] [$level] $msg" | tee -a "$LOG_FILE"
}

log INFO  "Deployment started"
log WARN  "Disk usage at 85%"
log ERROR "Health check failed"
🎯 Interview Question (4 YOE)

Q: How do you pass and return values from a Bash function?
A: Pass values as positional arguments (func arg1 arg2), accessed as $1 $2. Return status codes 0–255 with return N. To "return" a string, use echo "value" in the function and capture it: result=$(func). Use local inside functions to prevent variable scope leakage.

Chapter 7 — Arrays & String Manipulation

Work with collections and transform text data

● Intermediate
arrays.sh 
#!/bin/bash

# ── INDEXED ARRAYS ────────────────────────────
SERVERS=("web-01" "web-02" "db-01")
PORTS=(80 443 8080 3306)

echo "First server:   ${SERVERS[0]}"
echo "Last server:    ${SERVERS[-1]}"      # negative index
echo "All servers:    ${SERVERS[@]}"
echo "Count:          ${#SERVERS[@]}"
echo "Slice [1..2]:   ${SERVERS[@]:1:2}"  # web-02 db-01

# Add / remove elements
SERVERS+=("cache-01")                  # append
unset SERVERS[1]                       # remove index 1
SERVERS=( "${SERVERS[@]/web-01/}" )  # remove by value (creates sparse)

# ── ASSOCIATIVE ARRAYS (like a hash map) ────
declare -A CONFIG
CONFIG[app_name]="cloudnova"
CONFIG[version]="2.4.1"
CONFIG[env]="production"
CONFIG[port]=8080

echo "App: ${CONFIG[app_name]}"
echo "All keys: ${!CONFIG[@]}"          # ! gives keys
echo "All values: ${CONFIG[@]}"

for key in "${!CONFIG[@]}"; do
    echo "  $key = ${CONFIG[$key]}"
done

String Manipulation (Parameter Expansion)

strings.sh 
#!/bin/bash
FILENAME="cloudnova-api-v2.4.1.tar.gz"
PATH_STR="/opt/apps/cloudnova/config.yml"

# ── LENGTH ───────────────────────────────────
echo "Length: ${#FILENAME}"             # 25

# ── SUBSTRING ────────────────────────────────
echo "${FILENAME:0:10}"                 # cloudnova-
echo "${FILENAME: -6}"                  # .tar.gz (last 6)

# ── REMOVE PREFIX/SUFFIX ─────────────────────
echo "${FILENAME%.tar.gz}"               # cloudnova-api-v2.4.1 (remove .tar.gz)
echo "${FILENAME%.*}"                    # cloudnova-api-v2.4.1.tar (remove last .ext)
echo "${FILENAME%%.*}"                   # cloudnova-api-v2 (remove from first .)
echo "${PATH_STR#/opt/}"                 # apps/cloudnova/config.yml (remove prefix)
echo "${PATH_STR##*/}"                   # config.yml (basename)
echo "${PATH_STR%/*}"                    # /opt/apps/cloudnova (dirname)

# ── SUBSTITUTION ─────────────────────────────
echo "${FILENAME/api/backend}"            # replace first 'api'
echo "${FILENAME//a/A}"                  # replace all 'a' with 'A'

# ── CASE CONVERSION ──────────────────────────
APP="CloudNova"
echo "${APP,,}"                         # cloudnova (lowercase all)
echo "${APP^^}"                         # CLOUDNOVA (uppercase all)
echo "${APP,}"                          # cLoudNova (lowercase first char)

# ── SPLITTING STRINGS ────────────────────────
CSV="web-01,web-02,db-01"
IFS=',' read -ra NODES <<< "$CSV"
for node in "${NODES[@]}"; do echo "Node: $node"; done

Chapter 8 — File & Text Processing

grep, sed, awk, find — the power tools of shell scripting

● Intermediate
📖 Story

CloudNova's logs directory holds 10,000 log files. You need to find all ERROR lines from today, extract the request IDs, count occurrences per service, and write a summary. This is where grep, sed, awk become indispensable.

grep — Search Text

grep_examples.sh 
#!/bin/bash

grep "ERROR" app.log                   # lines containing ERROR
grep -i "error" app.log                # case-insensitive
grep -v "DEBUG" app.log                 # lines NOT containing DEBUG
grep -c "ERROR" app.log                 # count matching lines
grep -n "ERROR" app.log                 # show line numbers
grep -r "DB_HOST" /etc/app/             # recursive search
grep -l "ERROR" /var/log/*.log          # only filenames (not lines)
grep -A 3 -B 2 "ERROR" app.log          # 3 lines after, 2 before
grep -E "ERROR|WARN|CRITICAL" app.log   # extended regex
grep -P "\d{3}-\d{4}" contacts.txt      # Perl regex
grep -o "[0-9]\+\.[0-9]\+\.[0-9]\+\.[0-9]\+" app.log # print only match

sed — Stream Editor

sed_examples.sh 
#!/bin/bash

# Basic substitution: s/pattern/replacement/flags
sed 's/localhost/db.prod.com/' config.conf      # first occurrence per line
sed 's/localhost/db.prod.com/g' config.conf     # all occurrences (g = global)
sed -i 's/v2\.4\.0/v2.4.1/g' version.txt       # in-place edit (-i)
sed -i.bak 's/DEBUG/INFO/g' app.conf          # in-place with backup

# Delete lines
sed '/^#/d' config.conf                          # delete comment lines
sed '/^$/d' config.conf                          # delete empty lines
sed '5d' file.txt                               # delete line 5
sed '1,3d' file.txt                             # delete lines 1-3

# Print specific lines
sed -n '10,20p' app.log                         # print lines 10-20
sed -n '/ERROR/p' app.log                        # print only error lines

# Multi-command
sed -e 's/foo/bar/g' -e 's/baz/qux/g' file.txt

awk — Data Extraction Powerhouse

awk_examples.sh 
#!/bin/bash
# awk 'pattern { action }' file
# $1,$2... are fields, $0 is the whole line, NR=line#, NF=num fields

awk '{print $1}' access.log               # print 1st column
awk '{print $NF}' access.log              # print last column
awk 'NR==2{print $5}' df_output.txt       # line 2, col 5
awk -F: '{print $1}' /etc/passwd          # -F: field separator is ':'
awk -F, '{print $2, $4}' data.csv         # CSV: print cols 2 and 4

# Conditional in awk
awk '$5 > 90 {print $1, "HIGH USAGE:", $5"%"}' disk_report.txt

# Sum a column
awk '{sum += $3} END {print "Total:", sum}' sales.txt

# Count occurrences
awk '{count[$1]++} END {for (ip in count) print ip, count[ip]}' access.log

# BEGIN and END blocks
awk 'BEGIN {print "=== Report ==="} 
     /ERROR/ {errors++; print NR": "$0} 
     END {print "Total errors:", errors}' app.log

find — Locate Files

find_examples.sh 
#!/bin/bash

find /var/log -name "*.log"                # find by name
find /var/log -name "*.log" -mtime -7      # modified in last 7 days
find /tmp -type f -size +100M               # files larger than 100MB
find . -type f -name "*.sh" -executable    # executable shell scripts
find /app -user www-data                    # files owned by www-data
find . -maxdepth 2 -name "*.conf"          # limit search depth

# Execute action on found files
find /var/log -name "*.log" -mtime +30 -delete  # delete old logs
find . -name "*.py" -exec grep -l "import os" {} \;
find . -name "*.txt" | xargs grep -l "ERROR"  # with xargs (faster)

Chapter 9 — Process Management & Signals

Background jobs, signals, traps, and parallel execution

● Intermediate / Advanced
🎬 Scenario

CloudNova's health check script needs to: run multiple checks in parallel (not wait one by one), handle Ctrl+C gracefully without leaving temp files behind, and kill zombie processes on timeout.

process_mgmt.sh 
#!/bin/bash

# ── BACKGROUND JOBS ───────────────────────────
./health_check.sh &            # run in background; returns PID in $!
HC_PID=$!
echo "Health check PID: $HC_PID"

wait $HC_PID                   # wait for specific background job
wait                           # wait for ALL background jobs
jobs                           # list background jobs
fg %1                          # bring job 1 to foreground
bg %2                          # send job 2 to background

# ── PARALLEL EXECUTION PATTERN ───────────────
SERVERS=("web-01" "web-02" "web-03")
PIDS=()

for server in "${SERVERS[@]}"; do
    ssh "$server" "uptime" &         # run SSH in background
    PIDS+=($!)                       # collect PIDs
done

# Wait and check each
for pid in "${PIDS[@]}"; do
    if ! wait "$pid"; then
        echo "Job $pid failed!"
    fi
done

# ── SIGNALS ──────────────────────────────────
# Common signals:
#   SIGTERM (15) - graceful termination
#   SIGKILL (9)  - force kill (cannot be caught)
#   SIGHUP  (1)  - hangup / reload config
#   SIGINT  (2)  - Ctrl+C
#   SIGUSR1 (10) - user-defined

kill -SIGTERM $PID              # graceful stop
kill -9 $PID                   # force kill
kill -0 $PID                   # check if process exists (no signal sent)
pkill -f "node app.js"          # kill by name/pattern

# ── TRAP — Handle Signals Gracefully ─────────
TMPFILE=$(mktemp)               # create temp file safely

cleanup() {
    echo "Cleaning up..."
    rm -f "$TMPFILE"
    kill $HC_PID 2>/dev/null      # kill background job
    exit 1
}

trap cleanup SIGINT SIGTERM EXIT  # run cleanup() on these signals

# ── PROCESS SUBSTITUTION ─────────────────────
diff <(ssh server1 "cat /etc/hosts") <(ssh server2 "cat /etc/hosts")

# ── TIMEOUT ──────────────────────────────────
timeout 30 ./heavy_operation.sh    # kill if runs > 30 seconds
if [[ $? -eq 124 ]]; then
    echo "Operation timed out!"
fi

Q: How do you run tasks in parallel in Bash and wait for all to finish?
A: Use & to background each task, collect PIDs in an array with PIDS+=($!), then loop over wait $pid to check each exit code.

Q: What is trap and when do you use it?
A: trap registers signal handlers. Use it to clean up temp files, kill child processes, or release locks when a script is interrupted. trap cleanup EXIT fires the cleanup function whenever the script exits — normally or via Ctrl+C.

error_handling.sh 
#!/bin/bash
# ══════════════════════════════════════
#  THE PRODUCTION-GRADE SCRIPT HEADER
# ══════════════════════════════════════
set -euo pipefail
# -e  exit immediately on error
# -u  treat unset variables as errors
# -o pipefail  catch errors in pipes (not just last command)
# This trio is the single most important habit for safe scripting

set -x  # debug mode: print each command before running
set +x  # disable debug mode

# ── EXPLICIT ERROR HANDLING ───────────────────
deploy() {
    local dir="$1"

    if [[ ! -d "$dir" ]]; then
        echo "ERROR: Directory '$dir' not found" >&2
        return 1
    fi

    cd "$dir" || { echo "Cannot cd to $dir" >&2; return 1; }
    git pull || { echo "git pull failed" >&2; return 1; }
}

# ── ERR TRAP ─────────────────────────────────
error_handler() {
    local exit_code=$?
    local line_num=$1
    echo "ERROR: Script failed at line $line_num with exit code $exit_code" >&2
    echo "Stack: ${FUNCNAME[*]}" >&2
}
trap 'error_handler $LINENO' ERR

# ── SAFE DELETION PATTERN ─────────────────────
# Never: rm -rf $DIR/*   ← catastrophic if $DIR is empty!
# Always validate first:
if [[ -n "$DIR" ]] && [[ -d "$DIR" ]]; then
    rm -rf "$DIR"
fi

# ── DEFENSIVE ARGUMENT CHECKING ───────────────
if [[ $# -lt 2 ]]; then
    echo "Usage: $0 <app_name> <version> [env]" >&2
    exit 1
fi

# ── RETRY LOGIC ───────────────────────────────
retry() {
    local retries=3
    local delay=5
    local cmd="$*"

    for (( i=1; i<=retries; i++ )); do
        if eval "$cmd"; then
            return 0
        fi
        echo "Attempt $i/$retries failed. Retrying in $delays..." >&2
        sleep $delay
    done
    echo "All $retries attempts failed." >&2
    return 1
}

retry curl -sf https://api.cloudnova.io/health

System Health Monitor

Monitor CPU, memory, disk, and processes — send alerts when thresholds are breached

health_monitor.sh 
#!/usr/bin/env bash
# ══════════════════════════════════════════════
#  CloudNova System Health Monitor
#  Usage: ./health_monitor.sh [--email admin@co.io]
# ══════════════════════════════════════════════
set -euo pipefail

# ── Configuration ──────────────────────────────
readonly DISK_WARN=80
readonly DISK_CRIT=90
readonly CPU_WARN=80
readonly MEM_WARN=85
readonly LOG="/var/log/health_monitor.log"
ALERT_EMAIL=""
ALERTS=()

# ── Parse args ─────────────────────────────────
while [[ $# -gt 0 ]]; do
    case "$1" in
        --email) ALERT_EMAIL="$2"; shift 2 ;;
        *) echo "Unknown: $1"; exit 1 ;;
    esac
done

# ── Logging ────────────────────────────────────
log() {
    local lvl="$1"; shift
    printf "[%s] [%-5s] %s\n" "$(date '+%Y-%m-%d %H:%M:%S')" "$lvl" "$*" \
        | tee -a "$LOG"
}

# ── Check Disk ─────────────────────────────────
check_disk() {
    while IFS= read -r line; do
        usage=$(echo "$line" | awk '{gsub(/%/,""); print $5}')
        mount=$(echo "$line" | awk '{print $6}')
        if [[ $usage -ge $DISK_CRIT ]]; then
            log ERROR "CRITICAL disk on $mount: $usage%"
            ALERTS+=("CRITICAL: Disk $mount at $usage%")
        elif [[ $usage -ge $DISK_WARN ]]; then
            log WARN  "WARNING disk on $mount: $usage%"
        else
            log INFO  "Disk OK: $mount at $usage%"
        fi
    done < <(df -h | awk 'NR>1 && $6!="/boot"')
}

# ── Check Memory ───────────────────────────────
check_memory() {
    local mem_total mem_avail mem_pct
    mem_total=$(awk '/MemTotal/ {print $2}' /proc/meminfo)
    mem_avail=$(awk '/MemAvailable/ {print $2}' /proc/meminfo)
    mem_pct=$(( (mem_total - mem_avail) * 100 / mem_total ))

    if [[ $mem_pct -ge $MEM_WARN ]]; then
        log WARN "Memory high: $mem_pct% used"
        ALERTS+=("WARNING: Memory at $mem_pct%")
    else
        log INFO "Memory OK: $mem_pct% used"
    fi
}

# ── Check Services ─────────────────────────────
check_services() {
    local services=("nginx" "postgresql" "redis")
    for svc in "${services[@]}"; do
        if systemctl is-active --quiet "$svc"; then
            log INFO "Service UP: $svc"
        else
            log ERROR "Service DOWN: $svc"
            ALERTS+=("CRITICAL: Service $svc is DOWN")
        fi
    done
}

# ── Send alert ─────────────────────────────────
send_alert() {
    [[ ${#ALERTS[@]} -eq 0 ]] && return
    [[ -z "$ALERT_EMAIL" ]] && return

    local body
    body=$(printf '%s\n' "${ALERTS[@]}")
    echo "$body" | mail -s "[ALERT] $(hostname) Health Check" "$ALERT_EMAIL"
    log INFO "Alert email sent to $ALERT_EMAIL"
}

# ── Main ───────────────────────────────────────
log INFO "=== Health check started on $(hostname) ==="
check_disk
check_memory
check_services
send_alert
log INFO "=== Health check complete. Alerts: ${#ALERTS[@]} ==="

Automated Backup Script

Backup databases + files, rotate old backups, and verify integrity

backup.sh 
#!/usr/bin/env bash
set -euo pipefail

BACKUP_DIR="/backup/cloudnova"
DB_NAME="cloudnova_prod"
APP_DIR="/opt/cloudnova"
RETAIN_DAYS=30
DATE=$(date +%Y%m%d_%H%M%S)
LOG="/var/log/backup.log"

log()   { echo "[$(date '+%T')] $*" | tee -a $LOG; }
error() { log "ERROR: $*"; exit 1; }

# Ensure backup dir exists
mkdir -p "$BACKUP_DIR"

# ── Database backup ────────────────────────────
backup_db() {
    local dest="$BACKUP_DIR/db_$DATE.sql.gz"
    log "Starting DB backup → $dest"
    pg_dump "$DB_NAME" | gzip > "$dest" \
        || error "DB backup failed"
    log "DB backup done: $(du -sh "$dest" | cut -f1)"
}

# ── File backup ────────────────────────────────
backup_files() {
    local dest="$BACKUP_DIR/files_$DATE.tar.gz"
    log "Starting file backup → $dest"
    tar -czf "$dest" \
        --exclude='*.log' \
        --exclude='node_modules' \
        --exclude='__pycache__' \
        "$APP_DIR" || error "File backup failed"
    log "File backup done: $(du -sh "$dest" | cut -f1)"
}

# ── Verify integrity ───────────────────────────
verify_backup() {
    local file="$1"
    if gzip -t "$file" 2>/dev/null; then
        log "✅ Verified: $file"
    else
        error "Backup corrupted: $file"
    fi
}

# ── Rotate old backups ─────────────────────────
rotate_backups() {
    log "Rotating backups older than $RETAIN_DAYS days..."
    local deleted=$(find "$BACKUP_DIR" -type f -mtime +$RETAIN_DAYS -print)
    if [[ -n "$deleted" ]]; then
        find "$BACKUP_DIR" -type f -mtime +$RETAIN_DAYS -delete
        log "Deleted: $(echo "$deleted" | wc -l) old backups"
    fi
}

# ── Main ───────────────────────────────────────
backup_db
backup_files
verify_backup "$BACKUP_DIR/db_$DATE.sql.gz"
rotate_backups
log "✅ Backup complete!"

#!/usr/bin/env bash
# Usage: sudo ./provision_user.sh username "pubkey" [sudo]
set -euo pipefail

[[ $EUID -ne 0 ]] && { echo "Run as root"; exit 1; }
[[ $# -lt 2 ]] && { echo "Usage: $0 username pubkey [sudo]"; exit 1; }

    echo "Invalid username"; exit 1
}

if ! id "$USERNAME" &>/dev/null; then
    useradd -m -s /bin/bash "$USERNAME"
    echo "Created user: $USERNAME"
else
    echo "User exists: $USERNAME"
fi

# Set up SSH key
SSH_DIR="/home/$USERNAME/.ssh"
mkdir -p "$SSH_DIR"
chmod 700 "$SSH_DIR"
echo "$PUBKEY" >> "$SSH_DIR/authorized_keys"
chmod 600 "$SSH_DIR/authorized_keys"

echo "SSH key installed"

    echo "$USERNAME ALL=(ALL) NOPASSWD:ALL" > "$SUDOERS"
    chmod 440 "$SUDOERS"

Deployment Pipeline Script

deploy_pipeline.sh 
#!/usr/bin/env bash
# ══════════════════════════════════════════════
#  CloudNova Deployment Pipeline
#  Usage: ./deploy_pipeline.sh [--env prod] [--version v2.4.1]
# ══════════════════════════════════════════════
set -euo pipefail

# ── Config ─────────────────────────────────────
APP_DIR="/opt/cloudnova"
RELEASES_DIR="$APP_DIR/releases"
CURRENT_LINK="$APP_DIR/current"
SHARED_DIR="$APP_DIR/shared"
KEEP_RELEASES=5
ENV="staging"
TIMESTAMP=$(date +%Y%m%d%H%M%S)
RELEASE_DIR="$RELEASES_DIR/$TIMESTAMP"

# ── Logging ────────────────────────────────────
log()    { echo "▶ $*"; }
success(){ echo "✅ $*"; }
fail()   { echo "❌ $*" >&2; rollback; exit 1; }

# ── Rollback ───────────────────────────────────
rollback() {
    echo "⚠️  ROLLING BACK..."
    local prev=$(ls -1t "$RELEASES_DIR" | sed -n '2p')
    if [[ -n "$prev" ]]; then
        ln -sfn "$RELEASES_DIR/$prev" "$CURRENT_LINK"
        systemctl restart cloudnova
        echo "✅ Rolled back to: $prev"
    else
        echo "No previous release to roll back to"
    fi
}

# ── Pipeline Steps ─────────────────────────────
step_checkout() {
    log "Checking out code..."
    mkdir -p "$RELEASE_DIR"
    git clone --depth 1 --branch main \
        git@github.com:cloudnova/app.git "$RELEASE_DIR"
    success "Checkout complete"
}

step_dependencies() {
    log "Installing dependencies..."
    cd "$RELEASE_DIR"
    npm ci --only=production
    success "Dependencies installed"
}

step_test() {
    if [[ "$ENV" == "production" ]]; then
        log "Running tests (prod gate)..."
        cd "$RELEASE_DIR"
        npm test || fail "Tests FAILED — aborting deploy"
        success "All tests passed"
    fi
}

step_symlinks() {
    log "Setting up shared directories..."
    ln -sfn "$SHARED_DIR/.env" "$RELEASE_DIR/.env"
    ln -sfn "$SHARED_DIR/uploads" "$RELEASE_DIR/uploads"
}

step_activate() {
    log "Activating new release..."
    ln -sfn "$RELEASE_DIR" "$CURRENT_LINK"
    systemctl reload cloudnova
    success "Release $TIMESTAMP is LIVE"
}

step_cleanup() {
    log "Cleaning old releases (keeping $KEEP_RELEASES)..."
    ls -1t "$RELEASES_DIR" | tail -n +$(( KEEP_RELEASES + 1 )) | \
        while IFS= read -r old; do
            rm -rf "$RELEASES_DIR/$old"
            echo "  Removed: $old"
        done
}

# ── Main Pipeline ──────────────────────────────
echo "═════════════════════════════════════"
echo "  CloudNova Deploy — $ENV — $TIMESTAMP"
echo "═════════════════════════════════════"

step_checkout
step_dependencies
step_test
step_symlinks
step_activate
step_cleanup

echo "═════════════════════════════════════"
echo "  ✅ DEPLOYMENT SUCCESSFUL"
echo "═════════════════════════════════════"
