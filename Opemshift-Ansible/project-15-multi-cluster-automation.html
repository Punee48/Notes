01 The Manager's Ticket — INFRA-3001

🏢 ABC Bank OpenShift Platform Team — Advanced Stage

The automation is working well for a single cluster. Now the infrastructure has grown. Rajesh drops a new architecture diagram in the meeting:

"We now have four OpenShift clusters: primary-prod in Mumbai, dr-prod in Pune, non-prod in Hyderabad, and an edge cluster in Singapore. We have 18 application namespaces spread across them. Today, deploying a new ConfigMap change means an engineer SSHes into each cluster one by one, runs oc commands, and manually records what they did. We had an incident last week where the DR cluster was 3 config versions behind prod. I need: one Ansible command to update all clusters, all namespaces, simultaneously. If Singapore fails, Mumbai must not roll back. Each cluster runs independently but I want one report telling me the state of everything."

This is the central challenge of enterprise Kubernetes operations: managing a fleet, not a machine.

Acceptance Criteria

  • 1
    Inventory models all four clustersEach cluster is a group. Each has its own API URL, ServiceAccount token, and kubeconfig. No cluster shares credentials with another.
  • 2
    Multi-namespace loop per clusterOne play iterates over all 18 namespaces. Tasks run against each namespace in each cluster without duplicating playbook code.
  • 3
    Error isolation per clusterIf Singapore cluster fails (network timeout, API unreachable), the playbook continues against Mumbai, Pune, and Hyderabad. Failure is recorded and reported at the end.
  • 4
    Per-cluster connection variablesEach cluster has its own ocp_api_url, ocp_token, ocp_ca_cert. These live in host_vars/cluster-name/ and are Vault-encrypted.
  • 5
    Fleet health reportAfter all clusters processed, generate one HTML report: cluster name, namespaces updated, failures, config version applied, timestamp.
  • 6
    Dry-run modeWith -e dry_run=true, show what would change without making changes. Use check_mode delegation.

02 Why Multi-Cluster — The Enterprise Reality

🌏
Geographic Distribution
Latency, data sovereignty (GDPR, RBI regulations), regional failover. Banks must run compute close to customers and regulators.
🔒
Blast Radius Isolation
A cluster upgrade gone wrong on DR should not affect PROD. Separate clusters separate failure domains. Not just namespaces.
⚙️
Lifecycle Independence
PROD may run OCP 4.14, DR runs 4.15 being tested, DEV runs 4.16. Each cluster on its own upgrade cadence.
📋
Compliance Boundaries
PCI-DSS scope: only the prod cluster is in scope. Non-prod is outside. Different auditors, different security controls.

03 Inventory Architecture — Modelling a Cluster Fleet

🏗️
The Key Mental Shift

In single-cluster Ansible, your inventory is hosts (servers). In multi-cluster Kubernetes Ansible, your inventory is clusters — each cluster is a "host" in the Ansible sense, but we're not SSHing into it. We're calling its API. The ansible_connection: local means Ansible runs on the control node and makes API calls to each cluster's URL. ansible_host is the cluster API endpoint, not an SSH host.

04 Connection Patterns — API Not SSH

Multi-Cluster Connection Variables
ansible_connection: local Ansible runs tasks on the control node (no SSH). All kubernetes.core.k8s* tasks make HTTPS API calls to the cluster URL. This is the correct pattern for cloud API automation.
host: "{{ ocp_api_url }}" Every kubernetes.core.k8s and k8s_info task explicitly passes the cluster URL. Because we're using connection: local, there's no implicit "current cluster" — you must always state which cluster you're targeting.
api_key: "{{ ocp_token }}" ServiceAccount bearer token from host_vars vault. Each cluster has its own SA token. The token is namespace-cluster scoped — it only works on the cluster it was issued by.
kubeconfig: "{{ kubeconfig_path }}" Alternative: use a kubeconfig file with multiple contexts. The k8s tasks support kubeconfig + context. Useful when managing clusters interactively or using OIDC auth rather than SA tokens.
validate_certs: "{{ ocp_validate_certs }}" Always true in production. False only in internal dev clusters with self-signed certs. Use ca_cert to provide custom CA bundle rather than disabling validation.

05 Multi-Namespace Loops — One Task, All Namespaces

yamlroles/openshift_fleet/tasks/update_namespace_config.yml
---
# Called per cluster. Loops over all managed_namespaces for that cluster.
# inventory_hostname = current cluster name (e.g. primary-prod)


- name: "[{{ inventory_hostname }}] Update ConfigMap in all namespaces"
  kubernetes.core.k8s:
    state: present
    definition:
      apiVersion: v1
      kind: ConfigMap
      metadata:
        name:      platform-config
        namespace: "{{ item }}"
        annotations:
          config-version: "{{ config_version_target }}"
          applied-by:     ansible
          applied-at:     "{{ ansible_date_time.iso8601 }}"
      data:
        environment:     "{{ cluster_tier }}"
        cluster:         "{{ inventory_hostname }}"
        region:          "{{ cluster_region }}"
        config_version:  "{{ config_version_target }}"
        log_level:       "{{ 'INFO' if cluster_tier == 'production' else 'DEBUG' }}"
    host:           "{{ ocp_api_url }}"
    api_key:        "{{ ocp_token }}"
    validate_certs: "{{ ocp_validate_certs }}"
  loop:         "{{ managed_namespaces }}"
  loop_control:
    label: "{{ inventory_hostname }}/{{ item }}"
  register: namespace_update_results
  check_mode: "{{ dry_run | default(false) | bool }}"

- name: "[{{ inventory_hostname }}] Build update summary"
  ansible.builtin.set_fact:
    cluster_update_summary:
      cluster:           "{{ inventory_hostname }}"
      namespaces_updated: "{{ namespace_update_results.results | selectattr('changed') | list | length }}"
      namespaces_ok:      "{{ namespace_update_results.results | rejectattr('changed') | list | length }}"
      config_version:    "{{ config_version_target }}"
      timestamp:         "{{ ansible_date_time.iso8601 }}"
      status:            success

06 Multi-Cluster Playbook — The Fleet Play

yamlplaybooks/fleet_config_sync.yml — Main Fleet Playbook
---
# Fleet-wide config sync playbook.
# Runs against all clusters in parallel (or serial for prod).
# Error isolation: any_errors_fatal: false means one cluster failing
# does not stop others.
#
# Usage:
#   ansible-playbook playbooks/fleet_config_sync.yml -i inventories/fleet/
#   ansible-playbook ... --limit prod_clusters         # prod only
#   ansible-playbook ... -e dry_run=true               # what-if mode
#   ansible-playbook ... -e config_version_target=2.8.0


###############################################################
# PLAY 1: Pre-flight checks on ALL clusters (parallel)
###############################################################
- name: "FLEET: Pre-flight — verify all clusters reachable"
  hosts: all_clusters
  connection: local
  gather_facts: false
  any_errors_fatal: false   # ONE failing cluster won't stop others

  tasks:
    - name: "[{{ inventory_hostname }}] Verify cluster API is reachable"
      kubernetes.core.k8s_info:
        kind:           ClusterVersion
        api_version:    config.openshift.io/v1
        name:           version
        host:           "{{ ocp_api_url }}"
        api_key:        "{{ ocp_token }}"
        validate_certs: "{{ ocp_validate_certs }}"
      register: cluster_version_check

    - name: "[{{ inventory_hostname }}] Extract OCP version"
      ansible.builtin.set_fact:
        ocp_version: "{{ cluster_version_check.resources[0].status.desired.version | default('unknown') }}"

    - name: "[{{ inventory_hostname }}] Preflight passed"
      ansible.builtin.debug:
        msg: "✅ {{ inventory_hostname }} reachable — OCP {{ ocp_version }} — {{ managed_namespaces | length }} namespaces"

###############################################################
# PLAY 2: Apply config to NON-PROD (parallel — fast feedback)
###############################################################
- name: "FLEET: Apply config — Non-Prod clusters"
  hosts: nonprod_clusters
  connection: local
  gather_facts: false
  any_errors_fatal: false

  roles:
    - role: openshift_fleet

###############################################################
# PLAY 3: Apply config to PROD clusters (serial=1 for safety)
###############################################################
- name: "FLEET: Apply config — Production clusters (serial)"
  hosts: prod_clusters
  connection: local
  gather_facts: false
  serial: 1             # One prod cluster at a time — safer rollout
  any_errors_fatal: false

  roles:
    - role: openshift_fleet

###############################################################
# PLAY 4: Generate fleet report (runs once on control node)
###############################################################
- name: "FLEET: Generate report on control node"
  hosts: localhost
  connection: local
  gather_facts: true

  tasks:
    - name: "Generate fleet config sync HTML report"
      ansible.builtin.template:
        src:  templates/fleet_report.html.j2
        dest: "/tmp/fleet-report-{{ ansible_date_time.date }}.html"
      vars:
        report_title:  "Fleet Config Sync Report"
        report_date:   "{{ ansible_date_time.iso8601 }}"

    - name: "Send report summary to Slack"
      community.general.slack:
        token:   "{{ vault_slack_token }}"
        channel: "#platform-ops"
        msg:     "✅ Fleet sync complete. Clusters: {{ groups['all_clusters'] | length }}. Version: {{ config_version_target }}. See report for details."

07 Federation Pattern — Primary Drives DR

A common BFSI requirement: primary-prod is the source of truth. DR cluster must always mirror it. Ansible can enforce this by reading from primary and writing to DR:

yamlplaybooks/sync_prod_to_dr.yml — Config Federation
---
# Read ConfigMaps from primary-prod, write identical values to dr-prod.
# Ensures DR is always in sync with PROD configuration.


- name: "FEDERATION: Read source config from primary-prod"
  hosts: primary-prod
  connection: local
  gather_facts: false

  tasks:
    - name: "Read all ConfigMaps from primary-prod namespaces"
      kubernetes.core.k8s_info:
        kind:      ConfigMap
        namespace: "{{ item }}"
        host:      "{{ ocp_api_url }}"
        api_key:   "{{ ocp_token }}"
        label_selectors:
          - "managed-by=ansible"           # Only sync Ansible-managed CMs
      register: "source_cm_{{ item | replace('-','_') }}"
      loop: "{{ managed_namespaces }}"
      loop_control:
        label: "primary-prod/{{ item }}"

    # Collect all ConfigMaps and store as hostvars accessible by dr-prod play
    - name: "Store source ConfigMaps for DR sync"
      ansible.builtin.set_fact:
        primary_configmaps: "{{ source_cm_payment_prod.resources
          + source_cm_fraud_prod.resources
          + source_cm_auth_prod.resources }}"

- name: "FEDERATION: Write configs to dr-prod"
  hosts: dr-prod
  connection: local
  gather_facts: false

  tasks:
    - name: "Apply primary ConfigMaps to DR (strip cluster-specific fields)"
      kubernetes.core.k8s:
        state: present
        definition:
          apiVersion: v1
          kind: ConfigMap
          metadata:
            name:      "{{ item.metadata.name }}"
            namespace: "{{ item.metadata.namespace }}"
            labels:    "{{ item.metadata.labels | default({}) }}"
            annotations:
              source-cluster: primary-prod
              synced-at:      "{{ ansible_date_time.iso8601 }}"
          data: "{{ item.data | default({}) }}"
        host:    "{{ ocp_api_url }}"          # dr-prod's URL from its host_vars
        api_key: "{{ ocp_token }}"          # dr-prod's token
      loop: "{{ hostvars['primary-prod']['primary_configmaps'] }}"
      loop_control:
        label: "{{ item.metadata.namespace }}/{{ item.metadata.name }}"

08 Error Isolation — One Cluster Fails, Others Continue

yamlroles/openshift_fleet/tasks/main.yml — Error-Isolated Fleet Tasks
---
# block/rescue/always at the cluster level.
# If this cluster fails, we capture the error and set a failure fact.
# The playbook-level any_errors_fatal: false then lets other clusters run.


- name: "[{{ inventory_hostname }}] Fleet task block"
  block:

    - name: "[{{ inventory_hostname }}] Update all namespace ConfigMaps"
      ansible.builtin.include_tasks:
        file: update_namespace_config.yml

    - name: "[{{ inventory_hostname }}] Verify all namespaces updated"
      ansible.builtin.include_tasks:
        file: verify_namespace_config.yml

    - name: "[{{ inventory_hostname }}] Mark cluster success"
      ansible.builtin.set_fact:
        cluster_result:
          cluster: "{{ inventory_hostname }}"
          status:  success
          error:   null

  rescue:
    - name: "[{{ inventory_hostname }}] Capture failure — cluster continues independently"
      ansible.builtin.set_fact:
        cluster_result:
          cluster: "{{ inventory_hostname }}"
          status:  failed
          error:   "{{ ansible_failed_result.msg | default('Unknown failure') }}"

    - name: "[{{ inventory_hostname }}] Alert on cluster failure"
      community.general.slack:
        token:   "{{ vault_slack_token }}"
        channel: "#platform-alerts"
        color:   danger
        msg:     "🔴 Fleet sync FAILED on cluster *{{ inventory_hostname }}*: {{ cluster_result.error }}"

  always:
    - name: "[{{ inventory_hostname }}] Write result to fleet audit log"
      ansible.builtin.lineinfile:
        path:   "/var/log/ansible/fleet-audit-{{ ansible_date_time.date }}.csv"
        line:   "{{ ansible_date_time.iso8601 }},{{ inventory_hostname }},{{ cluster_result.status }},{{ config_version_target }}"
        create: true
      delegate_to: localhost    # Write to control node's filesystem

09 Cross-Cluster State — hostvars and delegate_to

🔗
hostvars — The Cross-Play Communication Bridge

hostvars['cluster-name']['variable'] lets one play access facts set by another play on a different inventory host. In multi-cluster playbooks, this is how you pass data between clusters: primary-prod sets a fact → dr-prod reads it via hostvars. The variable must have been set in a previous play that ran against that host, or via set_fact with cacheable: true.

yamlCross-cluster data access patterns
# Pattern 1: Read from primary, write to DR using hostvars

- name: "Get primary-prod config version"
  ansible.builtin.debug:
    msg: "Primary config version: {{ hostvars['primary-prod']['deployed_config_version'] }}"
# hostvars['primary-prod'] = all vars from the primary-prod play


# Pattern 2: delegate_to — run a task on a different host

- name: "Trigger a notification on control node"
  ansible.builtin.debug:
    msg: "Running on {{ inventory_hostname }}, delegating to localhost"
  delegate_to: localhost
# delegate_to: localhost = run on control node, but vars stay from current host


# Pattern 3: run_once — run once regardless of how many hosts in play

- name: "Create shared report directory (once per playbook run)"
  ansible.builtin.file:
    path:  "/tmp/fleet-reports/"
    state: directory
  delegate_to: localhost
  run_once: true
# run_once: true + delegate_to: localhost = runs one time total, on control node


# Pattern 4: add_host — dynamically add hosts to run against

- name: "Add discovered cluster to runtime inventory"
  ansible.builtin.add_host:
    name:                "discovered-cluster"
    groups:              dynamic_clusters
    ansible_connection:  local
    ocp_api_url:         "https://api.new-cluster.example.com:6443"
    ocp_token:           "{{ discovered_token }}"
    managed_namespaces:  [app-prod]
  delegate_to: localhost
  no_log: true

10 Fleet Health Report — Aggregating Cluster State

yamltasks/fleet_health_check.yml — Aggregate Health Across All Clusters
---
# Health check per cluster: node status, pod health, quota usage

- name: "[{{ inventory_hostname }}] Get cluster node status"
  kubernetes.core.k8s_info:
    kind:           Node
    host:           "{{ ocp_api_url }}"
    api_key:        "{{ ocp_token }}"
    validate_certs: "{{ ocp_validate_certs }}"
  register: node_status

- name: "[{{ inventory_hostname }}] Count healthy nodes"
  ansible.builtin.set_fact:
    healthy_nodes:   "{{ node_status.resources | selectattr('status.conditions',
      'defined') | list | length }}"
    total_nodes:     "{{ node_status.resources | length }}"

- name: "[{{ inventory_hostname }}] Get all pods in all managed namespaces"
  kubernetes.core.k8s_info:
    kind:      Pod
    namespace: "{{ item }}"
    host:      "{{ ocp_api_url }}"
    api_key:   "{{ ocp_token }}"
  register: ns_pods
  loop: "{{ managed_namespaces }}"
  loop_control:
    label: "{{ item }}"

- name: "[{{ inventory_hostname }}] Compute failed pod count"
  ansible.builtin.set_fact:
    all_pods:    "{{ ns_pods.results | map(attribute='resources') | flatten }}"
    failed_pods: "{{ ns_pods.results | map(attribute='resources') | flatten
      | rejectattr('status.phase','in',['Running','Succeeded'])
      | list }}"

- name: "[{{ inventory_hostname }}] Build cluster health record"
  ansible.builtin.set_fact:
    cluster_health:
      cluster:      "{{ inventory_hostname }}"
      region:       "{{ cluster_region }}"
      ocp_version:  "{{ ocp_version | default('unknown') }}"
      total_nodes:  "{{ total_nodes }}"
      healthy_nodes:"{{ healthy_nodes }}"
      total_pods:   "{{ all_pods | length }}"
      failed_pods:  "{{ failed_pods | length }}"
      namespaces:   "{{ managed_namespaces | length }}"
      checked_at:   "{{ ansible_date_time.iso8601 }}"

11 Troubleshooting Guide

SymptomRoot CauseFix / Diagnosis Command
All tasks fail on one cluster: "401 Unauthorized" SA token expired or rotated. Token in vault.yml is stale. Extract fresh token: oc get secret -n ansible-platform ansible-automation-sa-token -o jsonpath='{.data.token}' | base64 -d. Re-encrypt in vault.yml.
"SSL: CERTIFICATE_VERIFY_FAILED" Cluster uses internally-signed cert; validate_certs: true fails. Provide ca_cert: /path/to/cluster-ca.crt in k8s tasks. Never use validate_certs: false in prod. Get CA: oc get secret router-certs-default -o yaml.
hostvars['primary-prod'] empty in dr-prod play primary-prod play ran but set_fact wasn't cacheable, or play failed silently. Add cacheable: true to set_fact in the source play. Verify with -v output. Check any_errors_fatal didn't suppress the primary play.
Singapore cluster failures blocking Mumbai any_errors_fatal: true (default) causes abort on first cluster failure. Set any_errors_fatal: false in the play. Use block/rescue to capture errors per cluster. Failures become facts, not fatal stops.
Loop over managed_namespaces empty for a cluster host_vars/cluster-name/vars.yml missing or managed_namespaces not defined. Check: ansible-inventory -i inventories/fleet/ --host singapore-edge — shows all vars for that host. Verify host_vars file path matches inventory hostname exactly.
Tasks applying to wrong cluster Missing host: "{{ ocp_api_url }}" in k8s tasks — defaults to whatever kubeconfig/env says. Always explicitly pass host: "{{ ocp_api_url }}" and api_key: "{{ ocp_token }}". Never rely on implicit cluster context in fleet playbooks.

12 Interview Questions

How do you model a multi-cluster inventory in Ansible when you're not SSHing into nodes?
Each cluster is an inventory host with ansible_connection: local. Ansible runs on the control node and makes API calls. Per-cluster connection vars — ocp_api_url, ocp_token, validate_certs — live in host_vars/cluster-name/vars.yml with secrets in a separately vault-encrypted host_vars/cluster-name/vault.yml. Clusters are grouped by tier (prod_clusters, nonprod_clusters, edge_clusters) so you can target them with --limit prod_clusters. managed_namespaces is a list variable in host_vars telling each cluster's play which namespaces to iterate over. Every k8s task explicitly passes host and api_key — there is no implicit "current cluster".
If a fleet playbook runs against 4 clusters and cluster 3 fails, how do you ensure clusters 1, 2, and 4 still complete?
Two things together: (1) any_errors_fatal: false at the play level — by default it's false, but worth being explicit. This means Ansible marks the failing host as failed but continues processing other hosts in the same play. (2) block/rescue at the cluster level — wrap cluster tasks in block/rescue so failures are caught, turned into set_facts (cluster_result.status = failed), and the play doesn't propagate the error outward. The rescue block also sends a Slack alert immediately. The always block writes to the audit log. End result: cluster 3 is flagged as failed, the other 3 complete, and the final report shows 3 success + 1 failed.
Explain hostvars and how you use it to sync data between cluster plays.
hostvars is a special Ansible variable dictionary containing every variable set for every host in the inventory. In multi-cluster playbooks: Play 1 runs on primary-prod and sets a fact (e.g. deployed_config_version). Play 2 runs on dr-prod and can read that fact via hostvars['primary-prod']['deployed_config_version']. The variable must already have been set — either from inventory vars, or from a set_fact in a prior play. For cacheable cross-play data, use set_fact with cacheable: true. This pattern replaces the need for a shared database or message queue between cluster plays — Ansible's in-memory hostvars is the shared state bus.
What is the difference between serial, any_errors_fatal, and max_fail_percentage?
serial: controls how many hosts run simultaneously. serial: 1 = one at a time (safest for prod). serial: 3 = three at a time. Can be a percentage: serial: 30% = 30% of hosts at once. any_errors_fatal: if true, when any host fails, all remaining hosts abort after their current task finishes. Useful when you want all-or-nothing across a cluster group. any_errors_fatal: false (default) = each host runs to completion independently. max_fail_percentage: allows a certain percentage of failures before aborting. max_fail_percentage: 20 = up to 20% of hosts can fail; if more fail, abort the remaining. Use together: serial: 1 + max_fail_percentage: 0 = stop as soon as any cluster fails.
How would you implement a dry-run mode for fleet operations?
Two approaches: (1) Ansible's built-in check mode: pass --check flag or set check_mode: true dynamically. For kubernetes.core.k8s tasks, check_mode shows what would change without applying. Pass as check_mode: "{{ dry_run | default(false) | bool }}" in each task — when dry_run=true is passed as extra_var, tasks run in check mode. (2) Custom dry_run logic: set dry_run as a variable, wrap state-changing tasks in when: not dry_run | bool, add debug tasks showing what would happen. Combine both: check_mode handles the k8s diff output cleanly, the when condition handles tasks that don't support check_mode (shell commands, file writes).

Challenge 1 of 3

Write a playbook play that queries the OCP cluster version from all clusters and generates a report listing each cluster's name, API URL, OCP version, and whether it is running the target version. Flag clusters that are behind the target version.

▶ Show Answer
yamlFleet version audit play
- name: "FLEET: OCP Version Audit"
  hosts: all_clusters
  connection: local
  gather_facts: false
  any_errors_fatal: false
  vars:
    target_ocp_version: "4.14.32"

  tasks:
    - name: "Get ClusterVersion"
      kubernetes.core.k8s_info:
        kind: ClusterVersion
        api_version: config.openshift.io/v1
        name: version
        host: "{{ ocp_api_url }}"
        api_key: "{{ ocp_token }}"
        validate_certs: "{{ ocp_validate_certs }}"
      register: cv

    - name: "Set cluster version fact"
      ansible.builtin.set_fact:
        cluster_ocp_version: "{{ cv.resources[0].status.desired.version | default('unknown') }}"

  hosts: all_clusters
  connection: local
  gather_facts: false
  serial: 1

  tasks:
    - name: "Get nodes"
      kubernetes.core.k8s_info:
        kind: Node
        host: "{{ ocp_api_url }}"
        api_key: "{{ ocp_token }}"
      register: nodes

    - name: "Count ready nodes"
      ansible.builtin.set_fact:
        ready_nodes: >-
          {{ nodes.resources
             | selectattr('status.conditions','defined')
             | map(attribute='status.conditions')
             | map('selectattr','type','eq','Ready')
             | map('selectattr','status','eq','True')
             | list | length }}

    - name: "Skip cluster if not enough ready nodes"
      ansible.builtin.meta: end_host
      when: ready_nodes | int < 2

    - name: "Log skip reason"
      ansible.builtin.debug:
        msg: "⚠️ {{ inventory_hostname }} skipped — only {{ ready_nodes }} ready nodes"
      when: ready_nodes | int < 2

    - name: "Apply config (cluster passed readiness gate)"
      ansible.builtin.include_tasks: update_namespace_config.yml
      when: ready_nodes | int >= 2
