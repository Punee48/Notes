03 Advanced k8s_info — Field Selectors, Label Selectors, Bulk Queries

In Project 01, we used basic k8s_info: query by kind and name. Now we unlock its full power with filters.

Query Types

🔍
Field Selector
Filter by metadata fields: status.phase, status.conditions. Example: "Give me pods in Failed phase."
🏷️
Label Selector
Filter by labels: app=payment, tier=backend. Example: "Give me all pods with app=payment label."
📋
Namespace Filter
Query specific namespace or all namespaces. Scope down results: "Give me pods only in namespace prod."
🎯
Bulk Query
Query ALL resources of a type (no filtering). Example: "Give me every single Pod in the cluster."
yaml k8s_info Query Examples — CHEAT SHEET 
# Example 1: Query all Pods cluster-wide (BULK)
- name: "Get all pods"
  kubernetes.core.k8s_info:
    api_version: v1
    kind: Pod
    host: "{{ ocp_api_url }}"
    api_key: "{{ ocp_token }}"
  register: all_pods

# Example 2: Query pods in specific namespace
- name: "Get pods in namespace 'production'"
  kubernetes.core.k8s_info:
    kind: Pod
    namespace: production  # Scope to one namespace
    host: "{{ ocp_api_url }}"
    api_key: "{{ ocp_token }}"
  register: prod_pods

# Example 3: Query pods with label selector (app=payment)
- name: "Get pods with app=payment label"
  kubernetes.core.k8s_info:
    kind: Pod
    label_selectors:
      - "app=payment"  # Only pods with this label
    host: "{{ ocp_api_url }}"
    api_key: "{{ ocp_token }}"
  register: payment_pods

# Example 4: Query pods in Failed phase (field selector)
- name: "Get failed pods"
  kubernetes.core.k8s_info:
    kind: Pod
    field_selectors:
      - "status.phase=Failed"  # Only Failed pods
    host: "{{ ocp_api_url }}"
    api_key: "{{ ocp_token }}"
  register: failed_pods

# Example 5: Complex query — namespace + labels + field selector
- name: "Get running payment pods in prod"
  kubernetes.core.k8s_info:
    kind: Pod
    namespace: production
    label_selectors:
      - "app=payment"
      - "tier=backend"           # Multiple labels (AND logic)
    field_selectors:
      - "status.phase=Running"
    host: "{{ ocp_api_url }}"
    api_key: "{{ ocp_token }}"
  register: running_payment_pods
⚠️
Label Selector Syntax — Multiple Values

Label selectors have a syntax all their own. app=payment,tier=backend means "label app is payment AND tier is backend". To match multiple values for one label: app in (payment,fraud,compliance). To exclude: tier!=frontend. Ansible's label_selectors: parameter takes a list, so multiple selectors are AND'd together.

04 Filtering in Jinja2 — The Power of Data Transformation

Once we have raw API responses, Jinja2 filters transform them into useful information. This is where the magic happens.

Essential Jinja2 Filters for Reporting

Jinja2 Filters Used in Inventory Reporting
selectattr()Filter a list of dicts by an attribute value. Example: pods | selectattr('status.phase', 'equalto', 'Running') — keeps only Running pods.
rejectattr()Opposite of selectattr. Example: pods | rejectattr('status.phase', 'equalto', 'Failed') — removes Failed pods.
map()Transform each item in a list. Example: pods | map(attribute='metadata.name') — extract just the pod names from full pod objects.
sum()Add up numeric values. Example: pods | map(attribute='spec.containers') | sum — total container count.
lengthCount items in a list. Example: pods | length — how many pods total.
groupby()Group list items by attribute. Example: pods | groupby('metadata.namespace') — organize pods by their namespace.
sort()Sort by attribute. Example: pods | sort(attribute='metadata.creationTimestamp') — oldest pods first.

Real-World Filter Examples

# Extract pod names from a list of pod objects
{% set pod_names = all_pods.resources | map(attribute='metadata.name') | list %}
# Count Running pods vs Failed pods
{% set running_count = all_pods.resources | selectattr('status.phase', 'equalto', 'Running') | length %}
{% set failed_count = all_pods.resources | selectattr('status.phase', 'equalto', 'Failed') | length %}
# Find pods older than 30 days (high restart risk)
{% set old_pods = all_pods.resources | selectattr('metadata.creationTimestamp', 'lessthan', cutoff_date) | list %}
# Sum total CPU requests across all pods in a namespace

---
# Task orchestration for inventory reporting


# ──────────────────────────────────────────────
# STAGE 1: QUERY CLUSTER RESOURCES
# ──────────────────────────────────────────────

- name: "[01] Query all pods cluster-wide"
  kubernetes.core.k8s_info:
    kind: Pod
    host: "{{ ocp_api_url }}"
    api_key: "{{ ocp_token }}"
    validate_certs: "{{ ocp_validate_certs }}"
  register: all_pods
  tags: [query]

- name: "[02] Query all nodes"
  kubernetes.core.k8s_info:
    kind: Node
    host: "{{ ocp_api_url }}"
    api_key: "{{ ocp_token }}"
    validate_certs: "{{ ocp_validate_certs }}"
  register: all_nodes
  tags: [query]

- name: "[03] Query all namespaces"
  kubernetes.core.k8s_info:
    kind: Namespace
    host: "{{ ocp_api_url }}"
    api_key: "{{ ocp_token }}"
    validate_certs: "{{ ocp_validate_certs }}"
  register: all_namespaces
  tags: [query]

# ──────────────────────────────────────────────
# STAGE 2: CALCULATE SUMMARY METRICS
# ──────────────────────────────────────────────

- name: "[04] Calculate summary metrics using filters"
  ansible.builtin.set_fact:
    cluster_summary:
      total_pods: "{{ all_pods.resources | length }}"
      running_pods: "{{ all_pods.resources | selectattr('status.phase', 'equalto', 'Running') | length }}"
      failed_pods: "{{ all_pods.resources | selectattr('status.phase', 'equalto', 'Failed') | length }}"
      pending_pods: "{{ all_pods.resources | selectattr('status.phase', 'equalto', 'Pending') | length }}"
      total_nodes: "{{ all_nodes.resources | length }}"
      nodes_ready: "{{ all_nodes.resources | selectattr('status.conditions', 'search', 'type=Ready') | length }}"
  tags: [aggregate]

# ──────────────────────────────────────────────
# STAGE 3: BUILD NAMESPACE-BY-NAMESPACE INVENTORY
# ──────────────────────────────────────────────

- name: "[05] Build per-namespace inventory"
  ansible.builtin.set_fact:
    namespace_inventory: "{}"
  tags: [aggregate]

- name: "[06] Loop namespaces and aggregate pod data"
  ansible.builtin.set_fact:
    namespace_inventory: "{{ namespace_inventory | combine({item.metadata.name: {
      'name': item.metadata.name,
      'pod_count': (all_pods.resources | selectattr('metadata.namespace', 'equalto', item.metadata.name) | length),
      'running': (all_pods.resources | selectattr('metadata.namespace', 'equalto', item.metadata.name) | selectattr('status.phase', 'equalto', 'Running') | length),
      'failed': (all_pods.resources | selectattr('metadata.namespace', 'equalto', item.metadata.name) | selectattr('status.phase', 'equalto', 'Failed') | length),
      }}) }}"
  loop: "{{ all_namespaces.resources }}"
  tags: [aggregate]

# ──────────────────────────────────────────────
# STAGE 4: GENERATE REPORTS
# ──────────────────────────────────────────────

- name: "[07] Generate HTML inventory report"
  ansible.builtin.template:
    src: inventory_report.html.j2
    dest: "{{ report_output_path }}/cluster_inventory_report.html"
    mode: '0644'
  tags: [report]

- name: "[08] Generate JSON inventory export"
  ansible.builtin.template:
    src: inventory_data.json.j2
    dest: "{{ report_output_path }}/cluster_inventory.json"
    mode: '0644'
  tags: [report]

- name: "[09] Generate CSV pod list export"
  ansible.builtin.template:
    src: inventory_data.csv.j2
    dest: "{{ report_output_path }}/cluster_pods.csv"
    mode: '0644'
  tags: [report]

- name: "[SUMMARY] Inventory reporting complete"
  ansible.builtin.debug:
    msg:
      - "Inventory Report Generation Complete"
      - "  Total Pods: {{ cluster_summary.total_pods }}"
      - "  Running: {{ cluster_summary.running_pods }}, Failed: {{ cluster_summary.failed_pods }}"
      - "  Total Nodes: {{ cluster_summary.total_nodes }} ({{ cluster_summary.nodes_ready }} ready)"
      - "  Reports: HTML, JSON, CSV"
      - "  Location: {{ report_output_path }}/"
  tags: [always]

08 Code Walkthrough — The Magic Moments

Understanding set_fact with Filters

Key Concepts in Data Aggregation
all_pods.resourcesThe raw list returned from k8s_info. Each item is a complete Pod object with metadata, status, spec.
selectattr()Jinja2 filter that keeps only items matching a condition. Example: selectattr('status.phase', 'equalto', 'Running') keeps only Running pods.
| lengthAfter filtering, | length counts remaining items. Example: Running pods | length = count of Running pods.
set_factAnsible task that creates/updates a variable. Used to store intermediate results for later use in templates.

Real Example — Filter Chain

| selectattr('status.phase', 'equalto', 'Failed')        # Filter: keep only Failed → 2 pods

09 Resource Relationships — Understanding the Hierarchy

OpenShift resources have relationships. To build accurate reports, understand the hierarchy.

OpenShift Resource Hierarchy

Cluster (OpenShift)
↓
Nodes (worker-01, worker-02, ...)
↓
Namespaces (production, staging, kube-system, ...)
↓
Pods (pod-xyz, pod-abc, ...)
↓
Containers (container-1, container-2 in each pod)

Query Strategy:
1. Query Pods cluster-wide (no scope limit)
2. Filter by metadata.namespace to organize by namespace
3. Pods know their node: metadata.spec.nodeName
4. Each pod has spec.containers → access container details

10 Troubleshooting Guide

SymptomErrorRoot CauseFix
k8s_info returns empty resources: [] Query is too restrictive or resource doesn't exist. Label selector/field selector filtering out everything. Remove filters one at a time. Verify namespace exists. Use debug task to inspect actual resource structure.
Filter not working UndefinedError: 'list' has no attribute 'xxx' Attribute name is wrong or doesn't exist on this resource type. Attribute path wrong (should be dot-notation). Use debug to print one resource and check exact structure. Example: debug: var=all_pods.resources[0]
Jinja2 filter syntax error TemplateAssertionError: no filter named 'xxx' Filter name misspelled or doesn't exist. Common: 'match' vs 'equalto', 'sum' needs no params. Verify filter name in Jinja2 docs. Common filters: selectattr, rejectattr, map, sum, length, sort, groupby.
Template renders but output wrong HTML/JSON/CSV file exists but content is empty/incorrect Variable not set correctly before template. Data structure doesn't match template expectations. Add debug task before template to verify data. Example: debug: var=cluster_summary
Performance issue — k8s_info slow Query takes 30+ seconds for large clusters Querying all resources in cluster. API rate limiting or cluster size. Use namespace filter when possible: namespace: production. Avoid querying all Pods if you only need one namespace.

11 Interview Questions

What is the difference between field_selectors and label_selectors in k8s_info?
Field selectors filter by metadata fields like status.phase, status.nodeName. Label selectors filter by labels attached to resources. Field selectors use field names and operators (=, ==, !=, etc). Label selectors use Kubernetes label syntax (key=value, key!=value, key in (v1,v2)). Field selectors are evaluated by the API server; label selectors are too. Use labels for organizational metadata (app=payment, tier=backend); use fields for status queries (status.phase=Running).
Explain the filter chain in Jinja2. What does | selectattr | map | sum do?
Pipes (|) chain Jinja2 filters left-to-right. Each filter transforms its input and passes output to next filter. Example: pods | selectattr('status.phase', 'equalto', 'Running') filters to Running pods. Then | map(attribute='spec.containers') extracts containers from each. Then | sum adds up container counts. Result: total Running containers across cluster. This is more efficient than looping manually.
How do you handle resource aggregation when building inventory reports?
Query each resource type once (Pods, Nodes, Namespaces) and register to variables. Then use set_fact with Jinja2 filters to aggregate. Loop over namespaces, calculating stats for each (pod count, running count, failed count, resource requests). Store in a dict indexed by namespace name. Use combine() to merge dicts as you loop. Finally, pass the aggregated structure to Jinja2 templates for rendering. This approach: (1) minimizes API calls, (2) separates query from rendering, (3) makes templates simple and reusable.
Why would you generate reports in multiple formats (HTML, JSON, CSV)?
Different stakeholders need different formats. HTML is for humans — visual, readable, dashboards. JSON is for APIs and monitoring systems — machine-readable, integrations. CSV is for spreadsheet tools — analysts use Excel/Sheets to dig into data, do custom analysis. Each format is generated from the same aggregated data (cluster_summary, namespace_inventory), so they are always in sync. One playbook run generates all three.
How would you optimize k8s_info queries for large clusters (10,000+ pods)?
Query by namespace when possible: "get pods in namespace X" is faster than "get all pods". Use field selectors/label selectors in the k8s_info module itself — let the API server do filtering, not Ansible. Avoid querying same resource type twice — register once, filter in Jinja2. Cache results if running playbook multiple times per hour. Schedule reports during off-peak hours. If still slow, split into parallel tasks (different namespaces queried concurrently) using async.

▶ Show Answer
yamltasks/main.yml addition
- name: "Calculate pod age and identify old pods"
  ansible.builtin.set_fact:
    old_pods: []

- name: "Loop pods and calculate age"
  ansible.builtin.set_fact:
    old_pods: "{{ old_pods + [item] }}"
  vars:
    creation_ts: "{{ item.metadata.creationTimestamp | to_datetime }}"
    age_seconds: "{{ (now(utc=True) - creation_ts).total_seconds() }}"

  loop: "{{ all_pods.resources }}"
