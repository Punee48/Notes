01

Business Scenario

NovaStack Bank's Identity & Access team handles roughly 40 joiner/mover/leaver (JML) events per week affecting Linux server access — new engineers needing sudo groups, transfers needing old access revoked, leavers needing immediate lockout. Today this is a manual checklist an Infra Ops engineer works through by hand across dozens of servers per event, and a post-incident review found a departed contractor's SSH key was still active 11 days after their last day — a serious access-control failure that Internal Audit flagged.

Automation Engineering has been asked to build an AD-integrated access automation pipeline: when HR/IAM triggers a JML event, the correct sudo group membership and SSH key state changes should apply across the entire relevant server fleet within minutes, not days — with leaver deprovisioning treated as the highest-priority, fastest path in the whole system.

Why this can't stay manualAn 11-day gap on a leaver's access is a real security incident waiting to happen. Manual checklists don't scale to 40 events/week without delay, and delay on a leaver event is the one thing this process cannot tolerate.

This is the first project introducing Active Directory / LDAP integration as a trigger source, and a priority-lane design: leaver events bypass the normal queue entirely.

Authentication

The automation authenticates to AD/LDAP using a read-only service bind account for lookups, and to target hosts via the standard SSH service-account pattern with sudo scoped narrowly to user/group management commands (usermod, passwd -l, authorized_keys management) — never full root.

Ansible Design

Architect's note

Leaver logic is deliberately a separate, simpler, faster-path role from joiner/mover — it does one thing (lock everything, immediately) with no dependency on the access matrix lookup, so it can never be slowed down by a mapping-table issue.

# ansible-jml-access/
├── roles/
│   ├── access_leaver/tasks/main.yml      # simple, fast, high priority
│   └── access_joiner_mover/tasks/main.yml # matrix-driven, normal priority
├── catalog/role_to_group_matrix.yml
├── playbooks/jml_event.yml

Code & Roles

roles/access_leaver/tasks/main.yml 
---
# Deliberately minimal and dependency-free. This path must never be
# blocked by a lookup failure elsewhere in the system -- a leaver event
# is the one case where "fail safe by locking harder" is correct.
- name: Lock the user's local password immediately
  ansible.builtin.user:
    name: "{{ leaver_username }}"
    password_lock: true

- name: Remove all SSH authorized keys for the user
  ansible.posix.authorized_key:
    user: "{{ leaver_username }}"
    state: absent
    key: "{{ lookup('file', 'dummy') }}"
    exclusive: true    # exclusive:true wipes the file rather than needing the exact key text

- name: Remove user from all sudo-granting groups
  ansible.builtin.user:
    name: "{{ leaver_username }}"
    groups: ""
    append: false

- name: Kill any active SSH sessions for the user
  ansible.builtin.shell: "pkill -KILL -u {{ leaver_username }} || true"
  changed_when: false
  # Revoking access is meaningless if an already-open session survives it --
  # this is the step most manual checklists forget.

- name: Report completion timestamp back to IAM system
  ansible.builtin.uri:
    url: "{{ iam_callback_url }}"
    method: POST
    body_format: json
    body:
      event_id: "{{ jml_event_id }}"
      host: "{{ inventory_hostname }}"
      completed_at: "{{ ansible_date_time.iso8601 }}"
  delegate_to: localhost

Execution flow, in plain terms

The leaver role locks the password, strips every SSH key, clears sudo group membership, and kills any live session — in that order, so even a session opened seconds before the event fires gets terminated, not just prevented from reopening. It reports back to IAM with a timestamp per host, which is exactly the evidence that closes the audit gap.

Rollback Procedure

Disable the webhook trigger in AAP to revert to the manual process instantly; no host-level state needs to be undone since access removal is the safe direction to fail toward.

15

Troubleshooting

Leaver job fails on an unreachable host Symptom: Job reports SSH timeout on one host in the user's access list.
Fix: Immediate automatic retry, then page on-call if still unreachable after 3 attempts — an unreachable host during a leaver event is treated as a security-priority incident, not a routine automation failure.

Interview Preparation

Why is the leaver role separate from joiner/mover instead of one unified role?
Leaver is the highest-risk, most time-sensitive path — it can't depend on the same access-matrix lookup that joiner/mover needs, because any failure or delay in that lookup would directly recreate the exact audit gap we're fixing.
How do you make sure this fails safely?
Every failure mode in the leaver path is designed to leave the user with less access, never more — locking the password and clearing groups happen before anything that could fail on network issues, and any host that can't be reached pages a human immediately rather than silently skipping.
