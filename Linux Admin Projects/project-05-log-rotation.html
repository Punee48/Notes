Log Rotation Automation

The irony that stung: a disk-full incident caused by our own monitoring logs. Today we build the safety net every script from Projects 1–4 has been missing.

🎯 Level: Intermediate 🧠 New Concepts: 9 🏗️ Environment: Linux / WSL ⏱️ Duration: 2–3 hrs

📖 The Story — Monitoring the Monitors

Six weeks into running our health, disk, memory, and CPU checks, an alert fires: the jump box's own /logs partition is at 94%. Nobody touched it — the four scripts we've built have quietly been appending to log files every single day, forever, with no cleanup. The monitoring system built to prevent disk-full incidents nearly caused one itself.

Priya isn't upset — she expected this. "Every log-writing script we build from now on needs a rotation policy. I want logs compressed after 7 days, and deleted entirely after 90 — and this needs to work generically across all the log directories we've already created, not be copy-pasted four separate times."

Today's project isn't tied to a banking service — it's tied to the health of our own tooling, which is just as production-critical.
🔁 Reinforced from Projects 1–4
log_message(), flock, config-driven behavior, and find-based file selection (first seen pruning state files in Project 3) all return here, generalized.

Prevent monitoring and application logs from ever consuming enough disk space to cause an outage, while preserving enough history for audits and incident review.

Customer Requirement

Audit needs at least 90 days of log history available (compressed is fine); Ops needs disk space to never be put at risk by log growth.

Every project so far (Projects 1–4) writes a new daily log file into its own logs/ directory, on the jump box and potentially per-server, with zero cleanup built in until now.

None — this is a genuinely new capability, not a replacement for an existing manual one.

🧠 New Bash Concepts for This Project

1. gzip for Compression

What: gzip file.log compresses a file in place, replacing it with file.log.gz (roughly 80-90% smaller for text logs).
Why: Old logs are read rarely but must be kept for audit — compression keeps them available while using a fraction of the space.
Best practice: Never compress today's active log file — only files that are already closed/finished being written to.

2. find ... -mtime +N -exec (Reinforced & Extended)

What: Beyond -delete (seen in Project 3), -exec runs an arbitrary command against every matched file: find logs/ -name "*.log" -mtime +7 -exec gzip {} \;
{}: a placeholder find replaces with each matched filename.
\;: marks the end of the -exec command (escaped so the shell doesn't interpret the semicolon itself).

3. du -sh for Human-Readable Size Reporting

What: du -sh directory/ reports total size of a directory in human-readable units (K/M/G).
Why: We measure size before and after rotation to report exactly how much space was reclaimed.

4. Byte-Accurate Size Math with du -sb

What: du -sb reports the exact byte count instead of a rounded human-readable value.
Why: We need raw, comparable numbers to calculate a "before minus after" delta correctly — human-readable units like "3.2M vs 1.1M" aren't safely subtractable as plain arithmetic.
Best practice: Do the math in bytes internally, then convert only the final result to human-readable form for the report.

5. The Dry-Run Pattern

What: A flag (-n) that makes a script print exactly what it would do, without actually doing it — every destructive action is wrapped in a check of this flag.
Why: Deleting the wrong files at 200-server scale is exactly the kind of mistake that should be rehearsable safely first.
Production example: if [[ "$DRY_RUN" == true ]]; then echo "[DRY-RUN] Would delete: $file"; else rm -f "$file"; fi
Best practice (house rule after this incident): Any script capable of deleting files must support dry-run, permanently, with no exceptions.

6. Iterating find Results Safely with while read -d

What: find ... -print0 | while IFS= read -r -d '' file; do ... done — the null-byte-safe way to loop over filenames that might contain spaces or special characters.
Why: A naive for file in $(find ...) breaks on filenames with spaces; -print0/-d '' use a null byte as the separator instead of newlines, which filenames can never contain.
Common mistake: Using for f in $(find ...) — this is one of the most common real-world Bash bugs, and exactly why we teach the safe pattern here.

7. Arrays of Directories from Config (Reinforced)

What: LOG_DIRECTORIES=("../../novatrust-health-check/logs" "../../novatrust-disk-monitor/logs" ...) — same array pattern as CRITICAL_SERVICES in Project 1, now holding paths instead of service names.
Why: Adding a new project's log directory to rotation should mean editing one config line, never touching the rotation script's logic.

8. Arithmetic Growth Across a Loop (Running Totals)

What: Accumulating a byte count across multiple directories: TOTAL_RECLAIMED=$(( TOTAL_RECLAIMED + RECLAIMED_THIS_DIR ))
Why: The final summary needs one grand total across every log directory processed, not just per-directory numbers.

9. Converting Bytes to Human-Readable Form (numfmt)

What: numfmt --to=iec 4832156 turns a raw byte count into something like 4.6M.
Why: Our internal math is done in exact bytes for accuracy, but the final report should be easy for a human to read at a glance.

🧩 Utility Functions (Extended)

scripts/utils.sh (additions)
# ---------- get_dir_size_bytes ----------
# Purpose: Return exact byte size of a directory (0 if it doesn't exist)
get_dir_size_bytes() {
    local dir="$1"
    [[ -d "$dir" ]] || { echo 0; return; }
    du -sb "$dir" 2>/dev/null | awk '{print $1}'    # First column of du -sb output is the byte count
}

# ---------- compress_old_logs ----------
# Purpose: Gzip-compress .log files older than COMPRESS_AFTER_DAYS in a directory
# Arguments: $1 = directory, $2 = "true"/"false" for dry-run
compress_old_logs() {
    local dir="$1"
    local dry_run="$2"

    # -print0 / -d '' is the null-byte-safe way to handle filenames with spaces or odd characters
    find "$dir" -name "*.log" -mtime +"$COMPRESS_AFTER_DAYS" -print0 |
    while IFS= read -r -d '' file; do
        if [[ "$dry_run" == "true" ]]; then
            log_message "INFO" "[DRY-RUN] Would compress: $file"
        else
            gzip "$file" && log_message "INFO" "Compressed: $file"
        fi
    done
}

# ---------- delete_old_archives ----------
# Purpose: Permanently delete .gz archives older than DELETE_AFTER_DAYS in a directory
# Arguments: $1 = directory, $2 = "true"/"false" for dry-run
delete_old_archives() {
    local dir="$1"
    local dry_run="$2"

    find "$dir" -name "*.log.gz" -mtime +"$DELETE_AFTER_DAYS" -print0 |
    while IFS= read -r -d '' file; do
        if [[ "$dry_run" == "true" ]]; then
            log_message "INFO" "[DRY-RUN] Would delete: $file"
        else
            rm -f "$file" && log_message "INFO" "Deleted: $file"
        fi
    done
}

# ---------- bytes_to_human ----------
# Purpose: Convert a raw byte count into a human-readable string like "4.6M"
bytes_to_human() {
    local bytes="$1"
    numfmt --to=iec --suffix=B "$bytes" 2>/dev/null || echo "${bytes}B"   # Fallback if numfmt is unavailable
}

Line-by-Line Highlights

  • du -sb "$dir" | awk '{print $1}' — du -sb prints size followed by the path, separated by a tab; awk '{print $1}' grabs just the numeric byte count.
  • find ... -print0 | while IFS= read -r -d '' file — the null-byte-safe pattern; even a file named weird log.log (with a space) is handled correctly, unlike a plain for f in $(find ...).
  • gzip "$file" && log_message ... — logging only happens if gzip actually succeeded (&&), so a failed compression is never silently reported as done.
  • numfmt --to=iec --suffix=B — iec means binary units (1024-based: K, M, G), matching how du and most Linux tools already report size.

🩺 Main Script

scripts/log_rotate.sh
#!/bin/bash
# =====================================================================
# log_rotate.sh
# NovaTrust Bank - Generic Log Rotation for All Monitoring Projects
# =====================================================================

set -uo pipefail

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
source "$SCRIPT_DIR/utils.sh"
source "$SCRIPT_DIR/../config/log_rotate.conf"

DRY_RUN="false"
while getopts "nh" opt; do                          # 'n' takes no value, so no colon after it
    case $opt in
        n) DRY_RUN="true" ;;
        h) echo "Usage: $0 [-n]   (-n = dry-run, show actions without executing them)"; exit 0 ;;
        *) echo "Invalid option. Usage: $0 [-n]"; exit 1 ;;
    esac
done

TODAY=$(date '+%Y%m%d')
LOG_FILE="$SCRIPT_DIR/$LOG_DIR/log_rotate_${TODAY}.log"
mkdir -p "$(dirname "$LOG_FILE")"

exec 200>"$LOCK_FILE"
flock -n 200 || { log_message "WARN" "Another instance is already running. Exiting."; exit 0; }
trap 'log_message "INFO" "Log rotation run finished. Dry-run: $DRY_RUN"' EXIT

if [[ "$DRY_RUN" == "true" ]]; then
    log_message "INFO" "=== Starting log rotation in DRY-RUN mode (no files will be changed) ==="
else
    log_message "INFO" "=== Starting log rotation (LIVE mode) ==="
fi

TOTAL_RECLAIMED=0

for dir in "${LOG_DIRECTORIES[@]}"; do
    RESOLVED_DIR="$SCRIPT_DIR/$dir"

    if [[ ! -d "$RESOLVED_DIR" ]]; then
        log_message "WARN" "Directory not found, skipping: $RESOLVED_DIR"
        continue
    fi

    log_message "INFO" "Processing: $RESOLVED_DIR"
    SIZE_BEFORE=$(get_dir_size_bytes "$RESOLVED_DIR")

    compress_old_logs "$RESOLVED_DIR" "$DRY_RUN"
    delete_old_archives "$RESOLVED_DIR" "$DRY_RUN"

    SIZE_AFTER=$(get_dir_size_bytes "$RESOLVED_DIR")
    RECLAIMED=$(( SIZE_BEFORE - SIZE_AFTER ))        # Bash integer arithmetic - both values are always whole bytes

    if [[ "$DRY_RUN" != "true" ]]; then
        TOTAL_RECLAIMED=$(( TOTAL_RECLAIMED + RECLAIMED ))
        log_message "INFO" "Space reclaimed in $RESOLVED_DIR: $(bytes_to_human "$RECLAIMED")"
    fi
done

if [[ "$DRY_RUN" == "true" ]]; then
    log_message "INFO" "=== DRY-RUN complete. No files were changed. Re-run without -n to apply. ==="
else
    log_message "INFO" "=== SUMMARY: Total space reclaimed across all directories: $(bytes_to_human "$TOTAL_RECLAIMED") ==="
fi

exit 0

Every Line, Explained

LineExplanation
while getopts "nh" optNo colon after n means it's a boolean flag (present or absent), unlike e: in earlier projects which required a value.
RESOLVED_DIR="$SCRIPT_DIR/$dir"Config paths are relative to the rotation project's own location; resolving against SCRIPT_DIR makes the script location-independent, same pattern as every prior project.
[[ ! -d "$RESOLVED_DIR" ]]Gracefully skips a configured directory that doesn't exist (e.g., a project not yet deployed to this server) rather than erroring out the whole run.
RECLAIMED=$(( SIZE_BEFORE - SIZE_AFTER ))Plain Bash integer arithmetic is safe here because du -sb always returns whole byte counts, unlike the percentage/decimal math that needed bc in Project 3.
if [[ "$DRY_RUN" != "true" ]]; then ... fiSpace-reclaimed accounting only makes sense for a live run — in dry-run mode nothing actually changed, so reporting a "reclaimed" number would be misleading.

# NovaTrust Bank - Generic Log Rotation

## Usage
    ./scripts/log_rotate.sh -n     # DRY RUN - always do this first in a new environment
    ./scripts/log_rotate.sh        # LIVE - actually compresses/deletes

## Policy
- Files older than 7 days:  compressed with gzip

## Adding a New Project's Logs to Rotation
Add its log directory path to LOG_DIRECTORIES in config/log_rotate.conf.

🔄 What Happens Internally

  1. Two full passes per directory: compress, then delete — always in that order, since a file must be compressed to .gz before it could ever match the delete pattern.
  2. find ... -print0 piped into while read -d '' creates a subshell for the loop (because of the pipe) — this is fine here since we only log inside it and don't need its loop-local variables afterward, unlike Project 2's host loop which needed the redirection form instead.
  3. Size measurement brackets the entire compress+delete sequence for each directory — this is what makes the "reclaimed" number represent the true combined effect of both operations together.
  4. Dry-run and live mode share 100% of the same code path up until the innermost if inside each utility function — this guarantees the dry-run output is a truthful preview, not a separate, potentially-diverging implementation.

🛡️ Production Best Practices

Dry-Run Is Not Optional

Any script capable of deleting files must support a dry-run mode, and that mode must share the same code path as the real one — never a separate, divergent implementation.

Null-Byte-Safe File Iteration

find -print0 / read -d '' should be the default for any loop over filenames, not an afterthought.

Measure, Don't Assume

Report actual space reclaimed via du before/after, rather than assuming compression ratios or estimating.

Configuration Over Hardcoding

Every log directory, and every age threshold, lives in config — this script should never need a code change to support a new project's logs.

Order Matters

Always compress before checking for deletable archives in the same run — reversing the order could delete a file that should have been compressed and kept instead.

Never Touch Today's Active Log

Age-based filtering (-mtime +7) naturally protects actively-written files — never explicitly exclude "today's file" by name, since that's fragile compared to age-based logic.

🎤 Interview Preparation

Scenario: After running log rotation, an auditor asks for a log file from 45 days ago and it's missing. What went wrong?
The retention math is likely misconfigured — either DELETE_AFTER_DAYS was set too aggressively, or a file's modification time was reset by an unrelated process (like a backup tool touching it), making it appear older than it actually is to find -mtime.
Production Support: The rotation script reports a negative "space reclaimed" number every night. Is this a bug?
Not necessarily — if new log entries are being actively written to that directory between the "before" and "after" measurement, growth can outpace what was reclaimed in that single run; it becomes concerning only if it's large and consistent, suggesting rotation isn't actually triggering.
Shell Scripting: Why is for f in $(find ...) considered dangerous, and what's the safe alternative?
Word-splitting on the command substitution breaks apart any filename containing a space or newline into multiple "files"; the safe alternative is find -print0 piped into while IFS= read -r -d '' file, which uses null bytes as a separator that can never appear in a filename.
Troubleshooting: Dry-run shows files that should be compressed, but the live run compresses nothing. What's different?
Check for a permissions issue — dry-run only prints intentions and never touches the filesystem, so a read-only directory or file ownership mismatch would only surface as a failure during the actual gzip call in live mode.
Manager Round: Why 7 days for compression and 90 for deletion specifically — how would you justify these numbers to Audit?
7 days keeps a full week of uncompressed, quickly-readable logs for near-term incident review; 90 days aligns with common regulatory minimum retention expectations for operational logs in BFSI environments, while still bounding disk growth — both values are configurable precisely so Audit's actual requirement can be matched exactly.
Architecture: Why measure directory size with du -sb instead of summing individual file sizes some other way?
du is the standard, well-tested tool for this exact purpose and correctly accounts for filesystem block sizes and nested content; reinventing size calculation manually risks subtly wrong numbers that don't match what df/other tools would report for the same directory.
Best Practice: Why bracket the size measurement around BOTH compression and deletion, rather than measuring reclaimed space separately for each?
A single before/after measurement around the whole sequence gives one trustworthy number reflecting the directory's true net change; measuring separately around each step risks double-counting or math errors if the two operations interact (e.g., a file compressed in this same run immediately becoming eligible for the delete check too).
Real Incident Discussion: The jump box hit 94% disk from its own logs. What's the single most important design decision in this project that prevents a repeat?
Making log rotation itself a first-class, generically-configurable monitoring project rather than a one-off cleanup script — any future project's log directory is one config-file line away from being protected, rather than something easily forgotten again.
