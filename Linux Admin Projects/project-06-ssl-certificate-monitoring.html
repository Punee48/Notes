SSL Certificate Expiry Monitoring

A TLS certificate doesn't "fail" — it just quietly stops being valid at midnight. Today we make sure NovaTrust never finds out about that from angry customers.

🎯 Level: Intermediate 🧠 New Concepts: 8 🏗️ Environment: Linux / WSL + OpenSSL ⏱️ Duration: 2–3 hrs

📖 The Story — Midnight, No Warning

At 12:00 AM last Tuesday, the certificate for payments.novatrust.com expired. No server crashed, no process died, no CPU spiked — every check we've built so far (Projects 1–5) would have reported perfectly healthy servers. Yet every customer trying to make an online payment saw a browser security warning, and the NEFT gateway's own internal service calls started failing TLS handshakes.

Priya opens the retro with: "This is the sneakiest kind of outage — everything about the server was fine. It was a piece of paper, so to speak, that expired. I want a script that checks every certificate we depend on — external customer-facing ones and internal service-to-service ones — and screams well before midnight, not after."

Today we monitor something that isn't CPU, memory, or disk at all — a date, buried inside a cryptographic certificate.
🔁 Reinforced from Projects 1–5
Config-driven thresholds (now in days, not percentages), timeout-wrapped external calls, tiered WARNING/CRITICAL classification, and the consolidated report pattern all continue.

🏛️ Business Requirement & Banking Scenario

Business Requirement

Detect TLS certificates approaching expiry — both customer-facing and internal service-to-service — well before they actually expire.

Customer Requirement

Ops wants at least 30 days' notice on any expiring certificate, escalating urgency as the date approaches.

Banking Scenario

NovaTrust exposes customer-facing HTTPS endpoints (online banking, payment gateway) and also uses TLS between internal services (Core Banking ↔ Fraud Detection, for example).

Existing Manual Process

None, effectively — certificate renewal has historically been tracked in a shared calendar reminder that's easy to miss or mis-set.

Problems with a Calendar Reminder

Calendar entries get deleted, missed, or set for the wrong certificate; there's no automatic verification against the certificate's actual expiry date as installed on the server.

Business Impact & Risk

An expired customer-facing certificate directly blocks transactions and damages trust; an expired internal certificate can silently break service-to-service calls in ways that look like a mysterious application bug.

Why Automation Is Required

Only a script can reliably read a certificate's actual embedded expiry date and compare it against today, every single day, without relying on a human remembering to check a calendar.

Solution Design

For each configured endpoint (host:port) or local certificate file, extract the expiry date using openssl, convert it to a comparable form, calculate days remaining, and classify into HEALTHY/WARNING/CRITICAL/EXPIRED tiers.

Project Scope

In scope: remote endpoint certs (via network) and local certificate files, day-based tiered thresholds, timeout-protected network calls. Out of scope: automatic certificate renewal (a separate, higher-risk automation).

Expected Outcome

A daily report showing every monitored certificate's exact days-until-expiry, with a 30-day WARNING and a 7-day CRITICAL tier, so renewal always happens with time to spare.

🧠 New Bash Concepts for This Project

1. Fetching a Remote Certificate with openssl s_client

What: echo | openssl s_client -connect host:443 -servername host 2>/dev/null performs a TLS handshake and prints the server's certificate details.
Why: This is how we check a certificate as actually served by the endpoint right now — not a local copy that might be outdated.
-servername: required for SNI (Server Name Indication) — many servers host multiple certificates on one IP, and without this flag you may get the wrong one.
Why pipe echo into it: s_client normally waits interactively for input; piping an empty echo gives it just enough input to complete the handshake and exit instead of hanging.

2. Extracting the Expiry Date with openssl x509 -enddate

What: openssl x509 -noout -enddate reads a certificate (from a file or piped from s_client) and prints just its expiry date, e.g. notAfter=Aug 14 23:59:59 2026 GMT.
-noout: suppresses printing the certificate itself, since we only want the one date field.

3. Converting a Certificate Date to Epoch Seconds

What: date -d "Aug 14 23:59:59 2026 GMT" '+%s' converts that human-readable date into a single comparable number (seconds since 1970).
Why: Two arbitrary date strings can't be subtracted directly — converting both "today" and "expiry" to epoch seconds turns date comparison into simple arithmetic.

4. Days-Remaining Arithmetic

What: DAYS_LEFT=$(( (EXPIRY_EPOCH - NOW_EPOCH) / 86400 )) — the difference in seconds, divided by seconds-per-day.
Why: This single number drives our entire classification (HEALTHY/WARNING/CRITICAL/EXPIRED).
Common mistake: Forgetting that Bash integer division truncates (rounds toward zero) — 1.9 days remaining will show as 1, which is actually the safer direction to round for an expiry warning.

5. Parsing "host:port" Pairs from Config

What: IFS=':' read -r host port <<< "$entry" splits a single config line like payments.novatrust.com:443 into two variables.
Why: Different endpoints may use different ports; storing them together as one config line keeps the inventory file simple and self-contained.

6. Timeout-Wrapping a Network Handshake (Reinforced)

What: timeout 10 openssl s_client ... — same pattern as Project 2's SSH calls, now protecting a TLS handshake instead.
Why: An unresponsive or firewalled endpoint can otherwise hang s_client indefinitely, exactly the kind of risk we've guarded against with every other network call so far.

7. Defensive Parsing of External Command Output

What: Checking that openssl's output actually contains notAfter= before trying to parse a date out of it.
Why: A failed handshake, an invalid certificate, or an unreachable host can all produce empty or error output — parsing that blindly could silently produce a wrong "days remaining" number instead of a clear error.

8. Checking Both Files and Network Endpoints with One Shared Function

What: Designing get_cert_enddate() to accept either a file path or host:port, and branch internally, so the classification logic downstream doesn't need to know or care which kind of source it came from.
Why: Both local and remote certificates ultimately reduce to the same one piece of information we care about — reusing one classification path for both keeps the script simpler and more maintainable.

🧩 Utility Functions (Extended)

scripts/utils.sh (additions)
# ---------- get_cert_enddate ----------
# Purpose: Return the raw "notAfter=..." expiry line for either a remote endpoint or a local file
# Arguments: $1 = "host:port" or a local file path, $2 = "remote" or "local"
get_cert_enddate() {
    local target="$1"
    local kind="$2"

    if [[ "$kind" == "remote" ]]; then
        local host="${target%%:*}"                       # Everything before the first colon
        local port="${target##*:}"                       # Everything after the last colon
        # echo | feeds just enough input for s_client to complete the handshake and exit cleanly
        # 2>/dev/null discards handshake noise; timeout guards against an unresponsive endpoint
        timeout "$CONNECT_TIMEOUT" bash -c \
            "echo | openssl s_client -connect '$host:$port' -servername '$host' 2>/dev/null" |
            openssl x509 -noout -enddate 2>/dev/null
    else
        [[ -f "$target" ]] || return 1                    # Local file must actually exist
        openssl x509 -noout -enddate -in "$target" 2>/dev/null
    fi
}

# ---------- calculate_days_remaining ----------
# Purpose: Convert a raw "notAfter=..." line into an integer number of days remaining (can be negative)
calculate_days_remaining() {
    local raw_enddate="$1"

    # Defensive check: only proceed if the expected "notAfter=" marker is actually present
    [[ "$raw_enddate" == notAfter=* ]] || { echo ""; return; }

    local date_part="${raw_enddate#notAfter=}"            # Strip the "notAfter=" prefix, keep the date text
    local expiry_epoch now_epoch
    expiry_epoch=$(date -d "$date_part" '+%s' 2>/dev/null) || { echo ""; return; }
    now_epoch=$(date '+%s')

    echo $(( (expiry_epoch - now_epoch) / 86400 ))         # Integer division: seconds -> whole days
}

# ---------- classify_cert_status ----------
# Purpose: Turn a days-remaining integer into a status label
classify_cert_status() {
    local days="$1"
    if   [[ "$days" -lt 0 ]]; then echo "EXPIRED"
    elif [[ "$days" -le "$CERT_CRITICAL_DAYS" ]]; then echo "CRITICAL"
    elif [[ "$days" -le "$CERT_WARN_DAYS" ]]; then echo "WARNING"
    else echo "HEALTHY"
    fi
}

Line-by-Line Highlights

  • host="${target%%:*}" — parameter expansion removing the longest match of :* from the end, leaving everything before the first colon.
  • port="${target##*:}" — the mirror operation, removing the longest match of *: from the start, leaving everything after the last colon.
  • timeout "$CONNECT_TIMEOUT" bash -c "echo | openssl s_client ..." — wrapping the whole pipeline in bash -c lets timeout govern the entire handshake-and-parse sequence as one unit.
  • [[ "$raw_enddate" == notAfter=* ]] — a simple glob-style pattern match (not regex) confirming the expected marker is present before we trust the rest of the string.
  • expiry_epoch=$(date -d "$date_part" '+%s' 2>/dev/null) || { echo ""; return; } — if date can't parse the string at all (corrupted output), we bail out gracefully with an empty result rather than doing arithmetic on garbage.

🩺 Main Script

scripts/cert_monitor.sh
#!/bin/bash
# =====================================================================
# cert_monitor.sh
# NovaTrust Bank - SSL/TLS Certificate Expiry Monitor
# =====================================================================

set -uo pipefail

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
source "$SCRIPT_DIR/utils.sh"
source "$SCRIPT_DIR/../config/cert_monitor.conf"

ENDPOINT_FILE="$SCRIPT_DIR/../config/cert_endpoints.txt"
[[ -f "$ENDPOINT_FILE" ]] || { echo "ERROR: Endpoint file not found: $ENDPOINT_FILE" >&2; exit 1; }

TODAY=$(date '+%Y%m%d')
LOG_FILE="$SCRIPT_DIR/$LOG_DIR/cert_monitor_${TODAY}.log"
mkdir -p "$(dirname "$LOG_FILE")"

exec 200>"$LOCK_FILE"
flock -n 200 || { log_message "WARN" "Another instance is already running. Exiting."; exit 0; }
trap 'log_message "INFO" "Certificate monitor run finished."' EXIT

log_message "INFO" "=== Starting certificate expiry check ==="

OVERALL_EXIT=0
HEALTHY=0; WARNING=0; CRITICAL=0; EXPIRED=0; CHECK_FAILED=0

while IFS= read -r line; do
    [[ -z "$line" || "$line" == \#* ]] && continue

    KIND="${line%%:*}"                                    # "remote" or "local"
    TARGET="${line#*:}"                                   # Everything after the first colon

    RAW_ENDDATE=$(get_cert_enddate "$TARGET" "$KIND")
    if [[ -z "$RAW_ENDDATE" ]]; then
        log_message "FAIL" "$TARGET: could not retrieve or parse certificate"
        ((CHECK_FAILED++))
        OVERALL_EXIT=2
        continue
    fi

    DAYS_LEFT=$(calculate_days_remaining "$RAW_ENDDATE")
    if [[ -z "$DAYS_LEFT" ]]; then
        log_message "FAIL" "$TARGET: retrieved certificate but could not parse its expiry date"
        ((CHECK_FAILED++))
        OVERALL_EXIT=2
        continue
    fi

    STATUS=$(classify_cert_status "$DAYS_LEFT")
    case "$STATUS" in
        HEALTHY)  ((HEALTHY++)) ;;
        WARNING)  ((WARNING++)); [[ $OVERALL_EXIT -lt 1 ]] && OVERALL_EXIT=1 ;;
        CRITICAL) ((CRITICAL++)); OVERALL_EXIT=2 ;;
        EXPIRED)  ((EXPIRED++));  OVERALL_EXIT=2 ;;
    esac

    log_message "$STATUS" "$TARGET: expires in ${DAYS_LEFT} day(s)"

done < "$ENDPOINT_FILE"

log_message "INFO" "=== SUMMARY ==="
log_message "INFO" "Healthy: $HEALTHY | Warning: $WARNING | Critical: $CRITICAL | Expired: $EXPIRED | Check Failed: $CHECK_FAILED"

exit $OVERALL_EXIT

Every Line, Explained

LineExplanation
KIND="${line%%:*}"Splits the config line's prefix (remote or local) from the rest, reusing the same parameter-expansion technique as parsing host:port earlier.
TARGET="${line#*:}"#*: removes the shortest match of "anything followed by a colon" from the start — leaving the full remainder (which itself may contain more colons, e.g. host:443).
if [[ -z "$RAW_ENDDATE" ]]; then ... continue; fiThe first of two distinct failure points — this one means we couldn't even retrieve a certificate at all (network issue, missing file).
if [[ -z "$DAYS_LEFT" ]]; then ... continue; fiThe second distinct failure point — we got something back, but couldn't make sense of its date; deliberately kept separate from the first failure for clearer troubleshooting.
case "$STATUS" in ... esacSame pattern as Project 1's summary — a fixed, known set of values is exactly what case is designed for.

🔄 What Happens Internally

  1. Two-stage failure detection: "couldn't retrieve" and "couldn't parse" are deliberately checked and logged separately, giving Ops a much faster diagnosis than one generic "cert check failed" message would.
  2. timeout wraps the entire bash -c subshell running the piped echo | openssl s_client | openssl x509 sequence — if any part of that chain hangs, the whole thing is killed together.
  3. Two completely different retrieval mechanisms (network vs. file) converge on one shared date string format (notAfter=...), which is exactly why calculate_days_remaining and classify_cert_status never need to know which source the data came from.
  4. Integer division truncation in calculate_days_remaining means a certificate expiring in 6 hours shows as "0 days remaining," correctly still triggering CRITICAL rather than being hidden by rounding.

🛡️ Production Best Practices

Separate "Can't Retrieve" from "Can't Parse"

These are different failure modes with different fixes (network/firewall vs. certificate corruption) — never merge them into one vague error.

Always Timeout Network Handshakes

A TLS handshake to an unresponsive host is just as capable of hanging a script as an SSH connection — treat it with the same discipline.

Use SNI Correctly

Always pass -servername to openssl s_client — omitting it can silently return the wrong certificate on multi-tenant servers.

Give Enough Lead Time

A 30-day WARNING window accounts for real-world renewal lead times (procurement, approval, deployment) — don't set thresholds shorter than your actual renewal process takes.

Round Toward Danger

Truncating days-remaining downward (rather than rounding to nearest) means a cert expiring in 23.9 hours is correctly still flagged as urgent, not rounded away.

Monitor Internal Certs, Not Just Public Ones

Internal service-to-service certificates cause just as real an outage as public-facing ones, and are far easier to forget about.

🎤 Interview Preparation

Scenario: A certificate shows HEALTHY in our report, but customers are already seeing a browser warning. What could explain the mismatch?
The load balancer or CDN in front of the actual endpoint may be serving a different (expired) certificate than the one our check reached — worth confirming the check is actually hitting the same endpoint path real customer traffic uses, including SNI and any routing layer.
Production Support: The script reports CHECK_FAILED for an endpoint that works fine in a browser. Why?
Likely a firewall rule allowing browser traffic (perhaps from a different network path) but blocking the jump box's outbound connection specifically, or a timeout that's too short for a slow handshake — worth testing the exact same command manually from the jump box itself.
Shell Scripting: Why pipe an empty echo into openssl s_client instead of just running it directly?
s_client normally stays open waiting for interactive input (as if you were about to type an HTTP request); feeding it an empty line via echo gives it just enough to complete its job and exit on its own, which is essential for non-interactive scripting.
Troubleshooting: date -d fails to parse a valid-looking date string from OpenSSL. What's the most likely cause?
A locale mismatch — OpenSSL emits month names in English (e.g. "Aug"), and if the system's locale doesn't map that correctly, date -d may fail; forcing LC_ALL=C for the parsing step resolves this reliably.
Manager Round: Why do we need both a WARNING and a CRITICAL tier instead of just one expiry alert?
A single alert type doesn't convey urgency — 30 days out is "plan the renewal," 7 days out is "this needs attention today"; separate tiers let Ops triage and prioritize correctly across many certificates at once.
Architecture: Why design one shared classification function for both remote and local certificate sources instead of two separate ones?
Both sources ultimately reduce to the same notAfter= date string — keeping classification logic single and shared avoids duplicating (and potentially drifting) the same threshold logic in two places.
Best Practice: Why is -servername so important when checking a certificate over the network?
Modern servers commonly host multiple TLS certificates behind one IP address using SNI; without specifying which hostname you're asking for, the server may return its default certificate, which could be entirely unrelated to the one actually serving real traffic for that hostname.
Real Incident Discussion: The payments.novatrust.com outage happened at midnight with zero server-level symptoms. What's the core lesson this project encodes?
Infrastructure health (CPU, memory, disk, services running) is necessary but not sufficient — some of the most damaging outages come from time-based conditions like certificate expiry that have nothing to do with server resource health, which is why this had to become its own dedicated monitoring category.
