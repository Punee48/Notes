1. Why Firewalls Matter Here

Puneeth, here is a very common real-world story. A team builds a beautiful playbook, tests it on their laptop where it works perfectly, and then runs it from AAP in the actual data center — and it just hangs, then times out. Nine times out of ten, the reason is not the Ansible code at all. It is that AAP's network was never given permission to reach the AWS API, or the Azure API, or the target server's SSH port. Firewalls in a large enterprise are locked down by default — nothing is open unless someone specifically requested it, in writing, and got it approved.

This module is about being the engineer who raises the right firewall requests before Day 1 of testing, instead of discovering each missing rule one frustrating timeout at a time.

3. Five Types of Connectivity — Don't Confuse Them

When you talk to network and firewall teams, they will ask "what kind of connectivity do you need," and mixing these up is a classic beginner mistake. Let's separate them clearly.

1. Control-Plane Connectivity

This is traffic inside AAP itself — between the Controller node (where jobs are launched and tracked) and the Execution nodes (where the actual playbook runs), and any Hop nodes in between, across the Automation Mesh. This connectivity has nothing to do with AWS, Azure, or OpenShift — it is purely "how does AAP talk to itself."

2. API Connectivity

This is AAP (specifically, the Execution node where the playbook actually runs) reaching out to a cloud provider's HTTPS API — the AWS API, the Azure Resource Manager API, the OpenShift API. This is almost always outbound HTTPS on port 443 (OpenShift's API commonly uses 6443 instead). This is the connectivity that lets the ec2_instance or azure_rm_virtualmachine module actually create something.

3. SSH Connectivity

This is different from API connectivity — it happens after the server already exists. Once the EC2 instance, Azure VM, or KubeVirt VM is up and running, AAP needs to log directly into that Linux server on port 22 to run post-provisioning configuration (set hostname, create users, install agents). This traffic goes from AAP straight to the new server's IP, not to any cloud API.

4. WinRM Connectivity

The Windows equivalent of SSH connectivity. Instead of port 22, AAP talks to Windows servers on port 5985 (HTTP, avoid in production) or 5986 (HTTPS, recommended) using the WinRM protocol, to run PowerShell-based configuration tasks.

5. Application Connectivity

This is connectivity that has nothing to do with AAP at all — it's the traffic real end-users or other applications will use once the server is live, for example, users hitting the Payment application on port 8080. This is usually a separate firewall request raised by the Application team, not something the automation engineer requests, but you should be able to explain the difference in an interview.

4. Proxy Requirements in the Enterprise

Many large companies do not allow servers to reach the public internet directly — every outbound HTTPS request must go through a corporate proxy server, which logs and filters the traffic. This affects our project in a very concrete way:

AAP Execution Node | v Is the destination public internet (AWS/Azure APIs)? | Yes -+---------------------- No (internal system e.g. OpenShift, Git, Vault) | | v v Route via Corporate Proxy Direct internal network path | | v v AWS / Azure API Internal API / Server

In practice, this means the Execution Environment (the container image AAP uses to run the job) must have its proxy environment variables (HTTPS_PROXY, NO_PROXY) configured correctly. The NO_PROXY list is especially important — it must include internal destinations like the OpenShift API and Git server, so that traffic meant to stay inside the company network is not accidentally routed out through the proxy, which would fail.

Recommended for production: Set proxy variables at the Execution Environment or Job Template level (not hardcoded inside playbooks), and always populate NO_PROXY carefully with every internal domain/IP range AAP needs to reach directly. A missing entry here is one of the most common "it works from my laptop but not from AAP" bugs.
