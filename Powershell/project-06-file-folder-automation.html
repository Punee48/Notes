Quick Recap of Projects 1–5

We've collected system data, classified it, sampled it over time, checked named lists with error handling, and ranked/grouped running processes. This project moves to the file system — and for the first time, we'll write a script that can actually delete things, which means safety mechanisms matter more than ever.

The Story — Why We're Building This

Remember WINAPP07 running out of disk space (Project 2)? Our manager just got the root-cause report: 60GB of application log files, some over two years old, had never been cleaned up. Nobody wanted to manually delete files on a Production banking server without being absolutely sure what they were removing.

Our task: build a script that finds log files older than a configurable number of days, shows exactly what would be deleted before deleting anything, archives them to a separate folder first, and only then removes the originals. Nothing gets deleted blind.

Concepts First — Before We Touch Code

1. Get-ChildItem — Listing Files and Folders

ParameterPurpose
-PathWhere to start looking
-RecurseAlso search every subfolder, not just the top level
-FileReturn only files, skip folders
-FilterA fast, simple wildcard filter applied while enumerating (e.g. *.log)

2. LastWriteTime and Date Arithmetic

Every file object has a LastWriteTime property (a DateTime). To find "files older than 30 days," we compare it against a cutoff date we calculate ourselves.

$CutoffDate = (Get-Date).AddDays(-30)   # Today's date, minus 30 days
  • .AddDays(-30) — a method on the DateTime object returned by Get-Date. Passing a negative number subtracts days instead of adding them.

3. Basic Regular Expressions with -match

A regular expression (regex) is a pattern language for matching text. -match tests whether a string matches a regex pattern and returns $true/$false.

PatternMeaning
\.log$Ends with literally ".log"
^app_Starts with "app_"
\d{4}Exactly 4 digits somewhere in the string (e.g. a year)
-like vs -match-like (Project 4) uses simple wildcards (*, ?) — good enough for most filename matching. -match uses full regular expressions — far more powerful, but also easier to get subtly wrong. We introduce it here on filenames specifically because it's a safe, low-stakes place to practice before we need it for harder parsing later in the course.

4. Why -WhatIf Matters Before Any Destructive Command

This is the most important concept in this projectMany built-in cmdlets that change or remove something support a -WhatIf switch: instead of actually performing the action, they print what would happen. Running a cleanup script with -WhatIf first — every single time, as a habit — is one of the most important safety practices in enterprise automation, especially before anything that deletes files, stops services, or modifies production systems.
Remove-Item -Path "C:\Logs\old.log" -WhatIf   # Shows what WOULD be deleted, without deleting it

We'll go much deeper into building our own functions that support -WhatIf in the Advanced stage (SupportsShouldProcess). For now, we lean on the built-in support that Remove-Item and Move-Item already provide.

5. Archive-Then-Delete, Not Just Delete

Instead of removing old logs outright, we'll Move-Item them into a dated archive folder first. This gives Operations a safety net — if something turns out to matter, it's still recoverable for a while rather than gone the instant the script runs.

6. Measuring Folder Size

(Get-ChildItem -Path $Folder -Recurse -File | Measure-Object -Property Length -Sum).Sum

Same Measure-Object -Sum pattern from Project 5, this time summing the Length property (file size in bytes) across every file found.

Full Script — Invoke-LogCleanup.ps1

# =====================================================================
# Invoke-LogCleanup.ps1
# ABC Bank - Windows Infrastructure Automation Team
# Purpose: Safely find, archive, and clean up old log files
# =====================================================================

param(
    [switch]$WhatIf = $true,      # Defaults to PREVIEW MODE - must be explicitly turned off to actually delete/move
    [switch]$Confirm              # Optional extra confirmation prompt per file
)

$LogFolder     = ".\logs"          # Where log files live
$ArchiveFolder = ".\archive"        # Where old logs get moved to before cleanup
$ReportFolder  = ".\reports"         # Where our CSV summary is saved
$RetentionDays = 30                   # Files older than this many days are considered "old"
$FilePattern   = "\.log$"              # Regex: filename must end with ".log"

Write-Host "`n=== LOG CLEANUP: $LogFolder ===" -ForegroundColor Magenta
if ($WhatIf) {
    Write-Host "Running in PREVIEW MODE - nothing will actually be moved or deleted.`n" -ForegroundColor Yellow
}

# ---------------------------------------------------------------
# STEP 1: Calculate the cutoff date - anything older gets archived
# ---------------------------------------------------------------
$CutoffDate = (Get-Date).AddDays(-$RetentionDays)   # e.g. today minus 30 days

# ---------------------------------------------------------------
# STEP 2: Find candidate files - matching pattern AND older than cutoff
# ---------------------------------------------------------------
$OldLogFiles = Get-ChildItem -Path $LogFolder -File -Recurse |   # Lists every file, including subfolders
    Where-Object {
        $_.Name -match $FilePattern -and                            # Filename must match our regex pattern
        $_.LastWriteTime -lt $CutoffDate                             # AND must be older than the cutoff date
    }

Write-Host "Found $($OldLogFiles.Count) log file(s) older than $RetentionDays days.`n" -ForegroundColor Cyan

# ---------------------------------------------------------------
# STEP 3: Report what was found, with age in days for context
# ---------------------------------------------------------------
$Results = @()   # Will hold one record per file processed

foreach ($File in $OldLogFiles) {                                # Loops through each old file found

    $AgeDays = [math]::Round(((Get-Date) - $File.LastWriteTime).TotalDays, 0)   # How many days old this file is
    $SizeKB  = [math]::Round($File.Length / 1KB, 1)                              # File size in KB

    Write-Host "  $($File.Name)  -  $AgeDays days old, $SizeKB KB" -ForegroundColor Gray

    # ---------------------------------------------------------------
    # STEP 4: Move to archive (respects -WhatIf automatically)
    # ---------------------------------------------------------------
    $Destination = Join-Path $ArchiveFolder $File.Name    # Builds the full destination path safely

    Move-Item -Path $File.FullName -Destination $Destination -WhatIf:$WhatIf -Confirm:$Confirm   # Built-in safety switches

    $Results += [PSCustomObject]@{                         # Records what happened for this file
        FileName    = $File.Name
        AgeDays     = $AgeDays
        SizeKB      = $SizeKB
        Action      = if ($WhatIf) { "PREVIEWED (not moved)" } else { "MOVED TO ARCHIVE" }
        ArchivePath = $Destination
    }
}

# ---------------------------------------------------------------
# STEP 5: Export results and summarize space that would be reclaimed
# ---------------------------------------------------------------
if (-not (Test-Path $ReportFolder)) {
    New-Item -ItemType Directory -Path $ReportFolder | Out-Null
}
$Timestamp = Get-Date -Format "yyyyMMdd_HHmmss"
$Results | Export-Csv -Path "$ReportFolder\LogCleanup_$Timestamp.csv" -NoTypeInformation

$TotalKB = [math]::Round((($Results.SizeKB | Measure-Object -Sum).Sum), 1)   # Total size of all processed files
Write-Host "`nTotal space involved: $TotalKB KB across $($Results.Count) file(s)." -ForegroundColor Cyan
Write-Host "Report saved to $ReportFolder\" -ForegroundColor Green

if ($WhatIf) {
    Write-Host "`nThis was a PREVIEW. Re-run with -WhatIf:`$false to actually move these files." -ForegroundColor Yellow
}

Line-by-Line Explanation

param( [switch]$WhatIf = $true, [switch]$Confirm )

  • [switch] — a parameter type that's either present or not, true or false — like a checkbox, not a value you type text into.
  • Defaulting $WhatIf to $true is a deliberate safety choice: running this script with no arguments at all is safe by default. You have to consciously override it to make real changes — this is often called a "safe by default" design and is standard practice for anything destructive.

Where-Object { $_.Name -match $FilePattern -and $_.LastWriteTime -lt $CutoffDate }

  • -match $FilePattern — tests the filename against our regex string "\.log$". Inside that pattern, the backslash before the dot means "a literal dot character" (an unescaped dot in regex normally means "any character"), and $ at the end anchors the match to the very end of the string, so "app.log" matches but "app.log.bak" does not.

$AgeDays = [math]::Round(((Get-Date) - $File.LastWriteTime).TotalDays, 0)

  • Same DateTime-subtraction-produces-a-TimeSpan idea from Project 3's uptime calculation, here applied to file age instead of system uptime — .TotalDays gives us that duration expressed as a decimal number of days.

$Destination = Join-Path $ArchiveFolder $File.Name

  • Join-Path — safely combines a folder path and a filename into one valid path, correctly handling whether or not the folder path already ends with a backslash. Always prefer this over manually concatenating strings with + or interpolation, which can produce malformed paths like double backslashes or missing separators.

Move-Item -Path $File.FullName -Destination $Destination -WhatIf:$WhatIf -Confirm:$Confirm

  • -WhatIf:$WhatIf — this syntax passes the value of our own $WhatIf variable into the cmdlet's built-in -WhatIf switch parameter. Without the colon and variable, just writing -WhatIf would always turn it on; this form lets us control it dynamically based on what the caller specified.
  • $File.FullName — the complete path to the source file, as opposed to $File.Name which is just the filename by itself.

Action = if ($WhatIf) { "PREVIEWED (not moved)" } else { "MOVED TO ARCHIVE" }

  • Another example (like Challenge 3 in Project 3) of an if/else producing a value directly, assigned straight into a property — no separate variable or extra lines needed.

Architecture & Safety Flow

Get-ChildItem -Recurse
→
Where-Object (pattern + age)
→
Candidate Files
Candidate Files
→
Move-Item -WhatIf
→
Preview Output (default)
Explicit -WhatIf:$false
→
Move-Item (real)
→
Archive Folder + CSV Report

The key architectural decision here is that the same code path handles both preview and real execution — we're not maintaining two separate scripts. This guarantees the preview accurately reflects what the real run would do, because it's literally the same Move-Item call, just toggled.

Production Incident Walkthrough

Imagine an earlier, less careful version of this script ran directly with Remove-Item and no -WhatIf default, against a folder path that had a typo pointing one level too high. It would have deleted far more than intended, with no preview step to catch the mistake beforehand.
  • Why default to WhatIf = $true instead of $false? If a script is ever run accidentally — a misclick, a copy-paste into the wrong terminal, a scheduled task triggered against the wrong config — a safe default means the worst case is "nothing happened, review the output," not "production logs are gone."
  • Why archive instead of deleting outright? Archiving buys a recovery window. A later project (log rotation / retention policy) will handle actually purging the archive folder itself, on a separate, even more deliberate schedule.

Interview Preparation

Q1. Why default a cleanup script's -WhatIf parameter to $true instead of $false?

Answer: It makes the safe outcome the accidental outcome — if the script runs unintentionally, nothing destructive happens; the person running it must consciously opt into real changes.

Follow-up: "Isn't that inconvenient for someone who runs this script daily on purpose?" — Answer: yes, which is why in later projects we'll show scheduled/automated runs explicitly passing -WhatIf:$false in their configuration, rather than relying on an interactive user to remember each time — the safe default protects against mistakes, not against deliberate, documented automation.

Q2. What's the difference between -like and -match?

Answer: -like uses simple wildcard matching (*, ?) and is easier to read for basic filename patterns. -match uses full .NET regular expressions, which can express far more complex patterns (anchors, character classes, repetition) but require more care to get exactly right.

Follow-up: "When would -like not be powerful enough?" — Answer: matching something like "exactly 4 digits followed by a dash," which wildcards can't express precisely but a regex like \d{4}- can.

Q3. Why move files to an archive folder instead of deleting them directly?

Answer: It creates a recovery window — if a file turns out to still be needed, it's still available in archive rather than permanently gone the moment the cleanup script ran.

Follow-up: "How would you eventually clean up the archive folder itself?" — Answer: with a separate, longer-retention cleanup policy (e.g. purge archive files older than 180 days), run on its own deliberate schedule — separating "move out of the way" from "actually delete" into two distinct, independently controlled steps.
