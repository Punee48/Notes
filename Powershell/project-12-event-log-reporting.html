Concepts First — Before We Touch Code

1. ConvertTo-Html — Objects to HTML Tables

$Results | ConvertTo-Html -Fragment
  • ConvertTo-Html — takes pipeline objects and converts them into an HTML <table>, the same way Export-Csv converts them to CSV rows or ConvertTo-Json converts them to JSON — one consistent object, many possible output formats.
  • -Fragment — outputs just the <table> HTML, without a full <html><head><body> document wrapper — useful because we want to combine multiple tables (restarts, app errors) into one custom-styled page ourselves, rather than getting a separate complete HTML document for each.

2. Here-Strings — Multi-Line Text Blocks

$Css = @"
body { font-family: Segoe UI, sans-serif; background: #F5F3FF; color: #1F2937; }
h1 { color: #6D28D9; }
table { border-collapse: collapse; width: 100%; }
th { background: #EDE9FE; color: #6D28D9; padding: 8px; }
td { padding: 8px; border: 1px solid #E5E1F5; }
"@
  • @" ... "@ — a here-string: everything between the opening @" and closing "@ (which must start at the beginning of its own line) is treated as one literal multi-line string, including quotes and special characters that would otherwise need escaping. This is the natural way to embed a whole block of CSS or HTML without fighting string escaping line by line.
Double vs single-quoted here-strings@" "@ still allows variable interpolation inside it (like a normal double-quoted string); @' '@ treats everything completely literally, with no interpolation at all — useful when your block of text happens to contain dollar signs you don't want PowerShell to try to expand.

3. Assembling a Full Report from Fragments

We build the final HTML by combining a header, our embedded CSS, and each table fragment into one string, then write that combined result to a file — the same "collect pieces, then combine" shape we've used since Project 7's two-log correlation.

4. Report Retention — Reusing Project 6's Cleanup Pattern

A daily report generator run forever will eventually leave hundreds of old report files behind. We reuse the exact age-based cleanup logic from Project 6 (LastWriteTime, a retention threshold, Remove-Item) — this time applied to our own generated reports instead of application logs, proving that pattern generalizes.

Full Script — New-EventLogHtmlReport.ps1

# =====================================================================
# New-EventLogHtmlReport.ps1
# ABC Bank - Windows Infrastructure Automation Team
# Purpose: Generate a styled HTML event log report with automatic retention cleanup
# =====================================================================

$ComputerName  = $env:COMPUTERNAME
$DaysBack      = 7                        # How many days of event history to include
$RetentionDays = 30                        # How long to keep generated report files
$ReportFolder  = ".\reports"

$StartTime = (Get-Date).AddDays(-$DaysBack)

# ---------------------------------------------------------------
# STEP 1: Gather event data (same queries as Project 7)
# ---------------------------------------------------------------
$RestartEvents = @()
try {
    $RestartEvents = Get-WinEvent -FilterHashtable @{ LogName = "System"; Id = 6008,41,1074; StartTime = $StartTime } -ErrorAction Stop |
        Select-Object TimeCreated, Id, ProviderName, @{ Name="Message"; Expression={ ($_.Message -split "`n")[0] } }   # Calculated property (Project 5 pattern)
}
catch { }   # No restart events found is a normal, expected outcome (Project 7 pattern) - nothing to do here

$AppErrors = @()
try {
    $AppErrors = Get-WinEvent -FilterHashtable @{ LogName = "Application"; Level = 1,2; StartTime = $StartTime } -ErrorAction Stop |
        Select-Object TimeCreated, Id, ProviderName, @{ Name="Message"; Expression={ ($_.Message -split "`n")[0] } }
}
catch { }

# ---------------------------------------------------------------
# STEP 2: Define the report's visual style as a here-string
# ---------------------------------------------------------------
$Css = @"                                                          # Opens the here-string - must be at end of this line

"@                                                                   # Closes the here-string - must start this line

# ---------------------------------------------------------------
# STEP 3: Convert each result set into an HTML table fragment
# ---------------------------------------------------------------
$RestartHtml = if ($RestartEvents.Count -gt 0) {                    # Only builds a table if there's data to show
    $RestartEvents | ConvertTo-Html -Fragment -PreContent "
Restart / Shutdown Events
"
} else {
    "
Restart / Shutdown Events
None found in the last $DaysBack days.
"
}

$AppErrorHtml = if ($AppErrors.Count -gt 0) {
    $AppErrors | ConvertTo-Html -Fragment -PreContent "
Application Errors
"
} else {
    "
Application Errors
None found in the last $DaysBack days.
"
}

# ---------------------------------------------------------------
# STEP 4: Assemble the full HTML document
# ---------------------------------------------------------------
$ReportDate = Get-Date -Format "yyyy-MM-dd HH:mm"

$FullReport = @"

$Css

    
Event Log Report - $ComputerName

    
Generated $ReportDate | Covering the last $DaysBack days

    $RestartHtml
    $AppErrorHtml


"@

# ---------------------------------------------------------------
# STEP 5: Save the report
# ---------------------------------------------------------------
if (-not (Test-Path $ReportFolder)) { New-Item -ItemType Directory -Path $ReportFolder | Out-Null }

$Timestamp   = Get-Date -Format "yyyyMMdd_HHmmss"
$ReportPath  = Join-Path $ReportFolder "EventReport_$Timestamp.html"   # Join-Path from Project 6
$FullReport | Out-File -FilePath $ReportPath -Encoding UTF8              # Writes the assembled HTML to disk

Write-Host "`nReport generated: $ReportPath" -ForegroundColor Green

# ---------------------------------------------------------------
# STEP 6: Clean up old reports (Project 6's retention pattern, reapplied)
# ---------------------------------------------------------------
$CutoffDate = (Get-Date).AddDays(-$RetentionDays)

$OldReports = Get-ChildItem -Path $ReportFolder -Filter "EventReport_*.html" |
    Where-Object { $_.LastWriteTime -lt $CutoffDate }

if ($OldReports.Count -gt 0) {
    Write-Host "Removing $($OldReports.Count) report(s) older than $RetentionDays days..." -ForegroundColor Yellow
    $OldReports | Remove-Item -Force
}
else {
    Write-Host "No old reports to clean up." -ForegroundColor Cyan
}

Line-by-Line Explanation

$Css = @" ... "@

  • Notice @" must be the last thing on its opening line, and "@ must be the very first thing on its closing line — this strict formatting is what lets PowerShell reliably tell where the block of literal text begins and ends.

$RestartEvents | ConvertTo-Html -Fragment -PreContent "<h2>Restart / Shutdown Events</h2>"

  • -PreContent — extra HTML inserted immediately before the generated table — a convenient way to add a heading to each fragment without manually concatenating strings afterward.

$RestartHtml = if ($RestartEvents.Count -gt 0) { ... } else { ... }

  • Same "if/else producing a value directly" pattern from Projects 3, 6, and 8 — here choosing between a real data table and a friendly "none found" message, so the report never shows a confusing empty table with just column headers and no rows.

$FullReport = @" <html><head>$Css</head>... "@

  • Because this here-string uses @" (double-quoted style), $Css, $ComputerName, $ReportDate, $RestartHtml, and $AppErrorHtml all get interpolated directly into the final string — the entire report is assembled from previously-built pieces in one readable block, rather than one giant concatenated line.

$FullReport | Out-File -FilePath $ReportPath -Encoding UTF8

  • -Encoding UTF8 — explicitly sets the file's text encoding; being explicit here avoids potential character-display issues in browsers, especially important once report content might include non-ASCII characters from application error messages.

Get-ChildItem -Path $ReportFolder -Filter "EventReport_*.html" | Where-Object { $_.LastWriteTime -lt $CutoffDate }

  • The -Filter "EventReport_*.html" narrows results to only files this script itself created (by naming convention), so cleanup can never accidentally target unrelated files that happen to live in the same reports folder.

Every report run does two independent jobs: produce a new report, and retire old ones. Keeping these as separate steps (rather than one tangled block) means either could be changed or disabled independently — for instance, if a compliance requirement later demanded reports be kept for a full year, only $RetentionDays would need to change.

Production Incident Walkthrough

Three months after this script starts running daily via a Project-11-style scheduled task, someone notices the reports folder has grown to over 90 files and asks whether that's expected. Because retention was built in from day one with a sensible default, the answer is simple: reports older than 30 days are automatically removed, and 90 files roughly matches 30 days times a few report types — nothing is silently accumulating forever.
  • Why build retention in from the very first version instead of adding it later "if it becomes a problem"? Unbounded growth is a predictable, guaranteed outcome of any recurring file-generating script — the same reasoning that made -WhatIf's safe-by-default in Project 6 worth building in immediately rather than retrofitting after an incident.

Common Mistakes to Avoid

  • Misplacing here-string delimiters (they must be alone on their line).
  • Using a single-quoted here-string when you actually need variable interpolation.
  • Deleting every file in a shared reports folder instead of only the ones your script created.
  • Showing an empty table with no explanatory message when a check finds nothing.

Interview Preparation

Q1. What's the difference between ConvertTo-Html with and without -Fragment?

Answer: Without -Fragment, you get a complete, standalone HTML document (<html><head><body> and all); with -Fragment, you get just the <table> element itself, intended to be combined with other content into a larger custom document — exactly what we needed here since we wanted two tables in one styled page.

Follow-up: "How would you add custom CSS if you weren't using -Fragment?" — Answer: ConvertTo-Html has a -Head parameter for injecting a custom <head> block (including a <style> tag) into the full document it generates.

Q2. Why use a here-string for the CSS instead of a regular quoted string?

Answer: CSS naturally spans many lines and contains characters (curly braces, colons, semicolons) that would be tedious and error-prone to escape in a single-line string — a here-string lets us paste it in almost exactly as we'd write a real .css file.

Follow-up: "When would you choose a single-quoted here-string (@' '@) instead?" — Answer: when the block of text itself contains dollar signs or other characters you don't want PowerShell trying to interpret as variables — for example, embedding literal PowerShell code samples or regex patterns inside documentation.

Q3. Why filter cleanup by filename pattern instead of just deleting every old file in the reports folder?

Answer: A shared folder might eventually contain files this script didn't create — filtering by the specific naming convention this script uses ensures cleanup only ever touches its own output, never something unrelated that happens to be old.

Follow-up: "What would you do if two different scripts needed to share the same reports folder?" — Answer: give each script its own clearly distinct filename prefix (as we did with "EventReport_") so each can safely clean up only its own files without needing a separate folder per script.
