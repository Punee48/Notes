1.1 Filesystem & Navigation — Your Map of Linux
▶
Priya messages you: "SSH in and explore the server. Tell me what's in /etc and /var/log. Oh, and set up our project folder structure." Simple enough. But wait — where even IS /etc?
THE LINUX FILESYSTEM TREE
In Linux, everything is a file — regular files, directories, devices, network sockets, even running processes. They all live in one single tree that starts at / (called "root"). Think of it like a house: / is the front door, and every room inside is a directory.
nebula@prod-01
# The entire Linux filesystem — annotated / ← ROOT: The top. Everything is inside here ├── /bin ← BINaries: ls, cp, mv, cat — core commands ├── /sbin ← System BINaries: fsck, reboot — root-only tools ├── /etc ← ETCetera: ALL config files (nginx, ssh, cron...) ├── /home ← HOME: /home/nebula, /home/priya — user dirs ├── /root ← ROOT user's home (≠ / !) — admin's private space ├── /var ← VARiable: logs(/var/log), databases, mail, spool ├── /tmp ← TEMPorary: wiped on reboot — never store things here ├── /usr ← Unix System Resources: installed apps & libraries │ ├── /usr/bin ← User commands: python3, git, vim... │ └── /usr/local ← Locally compiled software goes here ├── /proc ← PROCess info: virtual FS — shows kernel/process data ├── /dev ← DEVices: /dev/sda (disk), /dev/null (trash), /dev/tty ├── /sys ← SYStem: kernel hardware info, CPU, memory stats ├── /boot ← BOOT: kernel image (vmlinuz) — DON'T touch randomly └── /mnt ← MouNT: where you attach USB drives, NFS shares

chmod = CHange file MODe (permissions). 755 = three digits, one for each group. Owner gets 7 (rwx=read+write+execute), Group gets 5 (r-x=read+execute), Others get 5. This means: "I can do anything, everyone else can read and run but not modify." Perfect for scripts.

THE FILE
chown = CHange OWNership. The format is owner:group. You can change just the owner: chown nebula file, just the group: chown :developers file, or both at once. Requires sudo to change to a different owner.
ScenarioCorrect chmodWhy
Script that only you should runchmod 700Only owner: rwx, group & others: nothing
Web server public filechmod 644Owner: rw-, group & others: r-- (read-only)

Private SSH key (!)chmod 600Owner: rw-, nobody else anything — SSH will refuse to use the key otherwise!

Symbolic chmod: You don't need to memorize numbers! chmod +x file adds execute for all. chmod u+x file adds execute for user only. chmod go-w file removes write from group and others. Both styles work.

1.5Bash Scripting Intro — Automate Your First Real Task
▶

ANATOMY OF A BASH SCRIPT
nebula/scripts/health-check.sh — Word by Word
#!/bin/bash # ↑ SHEBANG: Tells the OS which interpreter to use (bash, not sh/python/etc) # Without this, the OS doesn't know it's a bash script! # ── VARIABLES ────────────────────────────────────────────── REPORT_DIR="$HOME/nebula/logs" # Variable assignment: no spaces around = ! # $HOME = built-in variable that = your home directory DATE=$(date +%Y-%m-%d) # $() = command substitution: runs 'date +%Y-%m-%d', stores result # date +%Y-%m-%d = format: 2026-05-18 REPORT="$REPORT_DIR/health-$DATE.txt" # Build filename using variables — quotes needed for spaces safety # ── FUNCTIONS ────────────────────────────────────────────── print_section() { echo "═══ $1 ═══" # $1 = first argument passed to function } # ── MAIN LOGIC ────────────────────────────────────────────── mkdir -p "$REPORT_DIR" # Ensure report dir exists { # { ... } groups commands, redirect all output at once echo "NEBULA HEALTH REPORT - $DATE" echo "Generated: $(date)" echo "" print_section "DISK USAGE" df -h # Disk Free: -h = human readable (GB/MB) print_section "MEMORY" free -h # Memory free: -h = human readable print_section "LOGGED IN USERS" who # Show who is logged in right now print_section "TOP 5 CPU PROCESSES" ps aux --sort=-%cpu | head -6 # ps aux = all processes with details # --sort=-%cpu = sort by CPU% descending (- = descending) # head -6 = show 6 lines (1 header + 5 processes) } > "$REPORT" # Redirect ALL output into the report file # ── CONDITIONAL ────────────────────────────────────────────── if [ $? -eq 0 ]; then # $? = exit code of last command (0=success) echo "✓ Report saved: $REPORT" else echo "✗ ERROR: Report generation failed" >&2 # >&2 = send to stderr exit 1 # exit 1 = signal failure to caller fi
Script Golden Rules: (1) Always start with #!/bin/bash. (2) Always quote variables: "$VAR" not $VAR — spaces in values break unquoted variables. (3) Use set -e at the top to exit immediately on any error. (4) Test with bash -n script.sh (syntax check) before running.

2.2Groups & sudo — The Art of Least Privilege
▶
Priya: "Carol needs to restart nginx and manage services but she shouldn't have full root access — too risky. Set up sudo with specific permissions."
HOW sudo WORKS
sudo = Super User DO. It lets specific users run specific commands as root WITHOUT knowing the root password. The rules live in /etc/sudoers (always edit it with visudo — it validates syntax before saving, preventing lockouts).
/etc/sudoers configuration
# NEVER edit /etc/sudoers directly! Always use: nebula@prod-01:~$ sudo visudo # Inside visudo, the format is: # WHO WHERE=(AS_WHO) WHAT # Give carol FULL sudo (like root) carol ALL=(ALL:ALL) ALL # carol = the user # ALL = on all hosts # (ALL:ALL) = run as any user:any group # ALL = run any command # Give carol ONLY nginx restart (least privilege) carol ALL=(root) /bin/systemctl restart nginx, /bin/systemctl reload nginx # Give %developers group ability to restart services, no password needed %developers ALL=(root) NOPASSWD: /bin/systemctl # % = group. NOPASSWD: = no password prompt # Safer: use /etc/sudoers.d/ directory for per-user files nebula@prod-01:~$ echo "carol ALL=(root) /bin/systemctl" | sudo tee /etc/sudoers.d/carol nebula@prod-01:~$ sudo chmod 440 /etc/sudoers.d/carol
CommandWhat It Does
sudo commandRun command as root (your password)
sudo -u alice cmdRun command AS alice
sudo -iOpen root shell (full root environment)
su - aliceSwitch to alice's account (needs alice's password)
sudo !! Re-run LAST command with sudo (!! = last command)
sudo -lList what you're allowed to do with sudo
2.3Process Management — What's Running on Your Server?
▶
Priya: "The server is slow. CPU is maxed out. Find what's eating resources and kill it. Also, nginx crashed — restart it in the background."
WHAT IS A PROCESS?
Every running program is a process with a unique PID (Process ID). Every process has a parent (PPID). The very first process (PID 1) is systemd — it starts everything else. Processes can spawn children, creating a tree.
Process Investigation
# See ALL processes with full details nebula@prod-01:~$ ps aux # ps = Process Status # a = show processes of ALL users (not just yours) # u = user-oriented format (shows username, CPU%, MEM%) # x = include processes not attached to a terminal USER PID %CPU %MEM VSZ RSS TTY STAT START COMMAND root 1 0.0 0.1 169604 12480 ? Ss May17 /sbin/init nebula 1234 99.9 2.0 82404 8192 pts/0 R+ 10:23 python3 bad_script.py # Top CPU consumers right now nebula@prod-01:~$ ps aux --sort=-%cpu | head -6 # Find process by name nebula@prod-01:~$ pgrep -la nginx # pgrep = process grep: find process by name # -l = list name, -a = full command line 1337 nginx: master process /usr/sbin/nginx # Process tree (who started what) nebula@prod-01:~$ pstree -p # KILL a runaway process nebula@prod-01:~$ kill 1234 # kill = send a signal to a process. Default signal = SIGTERM (15) # SIGTERM = "please shut down gracefully" — process can ignore it nebula@prod-01:~$ kill -9 1234 # Signal 9 = SIGKILL = "DIE NOW" — cannot be ignored or caught nebula@prod-01:~$ pkill -9 bad_script # pkill = kill by name (not PID)
Use kill -15 (SIGTERM) first, give the process 5 seconds, THEN use kill -9 if it doesn't respond. Abrupt SIGKILL can corrupt databases or leave locks behind. Always try graceful shutdown first.

UNDERSTANDING THE CRON SYNTAX

LVM: 3 LAYERS THAT GIVE YOU FLEXIBILITY
LVM adds an abstraction layer between physical disks and mount points. You can resize on the fly, span volumes across multiple disks, and take snapshots — things impossible with regular partitions.

IP ADDRESSES & SUBNETTING IN PLAIN ENGLISH
An IP address like 192.168.1.10 is 32 bits written as 4 numbers (octets). The /24 (subnet mask) tells you how many bits define the network (24 bits) vs the host (8 bits). So 192.168.1.0/24 means: network=192.168.1, hosts=.1 to .254.

nebula@prod-01:~$ sudo apt install -y auditd # Watch for any writes to passwd or shadow (user tampering) nebula@prod-01:~$ sudo auditctl -w /etc/passwd -p wa -k user-changes # -w /etc/passwd = watch this file # -p wa = watch for Writes and Attribute changes # -k user-changes = tag events with this keyword (for searching) nebula@prod-01:~$ sudo auditctl -w /etc/sudoers -p wa -k sudo-changes # Search audit log for events tagged user-changes nebula@prod-01:~$ sudo ausearch -k user-changes --interpret # Generate a compliance report nebula@prod-01:~$ sudo aureport --summary
