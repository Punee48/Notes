Project 09: NFS Share Validation & Mount Point Health Monitoring

Network File System (NFS) mounts are the invisible backbone of banking infrastructure. Oracle databases store archived redo logs on NFS, application servers mount shared configuration directories via NFS, backup agents write to NFS targets, and compliance report repositories live on NFS shares. When an NFS mount becomes stale — the mount point exists in the OS but the NFS server is unreachable — any process that touches that path hangs indefinitely, causing application timeouts, database archiver failures, and backup job freezes. This project automates complete NFS health validation: mount existence, mount options compliance, stale mount detection, I/O reachability testing, NFS server export validation, and automatic stale mount recovery.

🏦 1. The Banking Story

Setting: ABC Global Bank mounts NFS shares across 340 Linux servers. The primary NAS (NetApp FAS 8200) provides NFS shares for: Oracle archived redo logs (/arch), application shared configurations (/app/shared), compliance report storage (/mnt/compliance), and backup agent staging (/mnt/backups).

Incident 1 — The Archiver Hang: At 02:14 AM, the NetApp NAS experienced a brief network blip — 45 seconds of packet loss. All NFS mounts on the Oracle database servers became stale. The Oracle ARCH process (archiver) tried to write archived redo logs to /arch — and hung. In Oracle, when ARCH hangs, the database suspends all user sessions after the online redo logs fill up. CBS was completely unavailable for 23 minutes. Root cause: stale NFS mount. Fix: remount /arch on all DB servers. Total impact: ₹4.2 crore in suspended transactions during the morning rush.

Incident 2 — The Security Finding: During a PCI-DSS audit, the QSA found that /mnt/backups was mounted with rw,exec options on 47 servers. PCI-DSS requires NFS mounts to be mounted noexec,nosuid,nodev (to prevent execution of code from the NFS share). This was an audit finding: "Unauthorized code execution path from network storage."

Incident 3 — The Silent Ghost: 23 servers had NFS mount entries in /etc/fstab pointing to a decommissioned NFS server. The NFS client retried indefinitely on boot — extending boot time from 45 seconds to 8 minutes. No application ran on those 23 servers — it was only discovered when they needed emergency rebooting after a kernel update.

The Ask: "Monitor all NFS mounts every 15 minutes. Detect stale mounts before they cause application hangs. Auto-remount stale mounts. Validate mount options against security policy. And give us a weekly report of all NFS mounts across the estate."

📚 2. NFS Concepts You Must Know

What is a Stale NFS Mount?
A stale NFS mount occurs when:
1. An NFS share was mounted successfully
2. The NFS server becomes unreachable (network issue, server reboot, NIC failure)
3. The mount point still exists in the OS (df shows it, /proc/mounts lists it)
4. BUT any I/O to that path hangs indefinitely — the kernel waits for the NFS server to respond

Why hangs occur: By default, NFS uses the hard mount option — the OS retries I/O forever until the server responds. A process touching the stale mount enters an uninterruptible sleep (D state in ps). It cannot be killed with kill -9. The only fix is to remount or reboot.

Detection challenge: df -h will hang if a stale mount is listed. mount | grep nfs shows it as mounted. The standard OS tools don't distinguish stale from healthy NFS mounts.

Testing NFS Reachability Without Hanging
The key challenge: we cannot use standard I/O on a potentially stale mount (it will hang). We need timeout-protected methods:

Method 1: timeout command
timeout 5 ls /mnt/nfs_share 2>/dev/null — returns exit code 124 if it hangs for 5 seconds

Method 2: stat with timeout
timeout 3 stat /mnt/nfs_share — stat is quicker than ls for detecting stale mounts

Method 3: Check /proc/mounts + TCP to NFS server
First verify the mount exists in /proc/mounts, then check if the NFS server port is reachable (TCP 2049 or 111 for portmapper). If port is unreachable, mount is likely stale.

Our automation uses Method 1 (timeout + stat) as the primary detection method.

Critical Design Decision — Timeout-Protected I/O: Every task that touches an NFS mount path uses the Linux timeout command with a short deadline (3-10 seconds). Without this, a stale mount would cause the Ansible task itself to hang — and the AAP job would never complete. The timeout command ensures Ansible always gets a result (either success or timeout exit code 124) within a predictable time.

💻 9. Roles & Tasks — Complete Code

Role 1: nfs_mount_check

roles/nfs_mount_check/tasks/check_proc_mounts.yml
---
# =====================================================================
# Check if NFS mounts are present in /proc/mounts
# /proc/mounts is the kernel's authoritative list of active mounts
# It's always readable (unlike df which can hang on stale mounts)
# =====================================================================

- name: Read /proc/mounts to get all current mount information
  ansible.builtin.slurp:                               # slurp: reads file without I/O hang risk
    src: /proc/mounts                                   # Kernel mount table — always readable
  register: proc_mounts_raw
  become: true

- name: Parse /proc/mounts into structured mount list
  ansible.builtin.set_fact:
    current_mounts: >-
      {{ proc_mounts_raw.content | b64decode
         | split('\n')
         | reject('equalto', '')
         | map('split', ' ')
         | list }}
    # Each line in /proc/mounts: "device mountpoint fstype options dump pass"
    # Example: "nas01:/vol/oracle_arch /arch nfs4 rw,hard,nointr,... 0 0"

- name: Extract NFS-specific mounts
  ansible.builtin.set_fact:
    current_nfs_mounts: >-
      {{ current_mounts
         | selectattr('2', 'in', ['nfs', 'nfs4'])
         | list }}
    # selectattr('2', ...): filter where element at index 2 (fstype) is nfs or nfs4

- name: Determine which expected mounts are actually present
  ansible.builtin.set_fact:
    mount_presence: >-
      {{ mount_presence | default([]) + [{
        'mount_point': item.mount_point,
        'nfs_server': item.nfs_server,
        'nfs_export': item.nfs_export,
        'is_mounted': (current_nfs_mounts
                       | selectattr('1', 'equalto', item.mount_point)
                       | list | length > 0),
        'actual_options': (current_nfs_mounts
                           | selectattr('1', 'equalto', item.mount_point)
                           | map(attribute='3')
                           | first | default('')),
        'critical': item.critical | default(false),
        'required_options': item.required_options,
        'forbidden_options': item.forbidden_options | default([])
      }] }}
  loop: "{{ nfs_mounts_expected }}"
  loop_control:
    label: "{{ item.mount_point }}"

- name: Log mount presence results
  ansible.builtin.debug:
    msg:
      - "Mount Presence Check — {{ inventory_hostname }}"
      - "Expected: {{ mount_presence | length }}"
      - "Mounted: {{ mount_presence | selectattr('is_mounted') | list | length }}"
      - "Missing: {{ mount_presence | rejectattr('is_mounted') | map(attribute='mount_point') | list | join(', ') | default('None') }}"
roles/nfs_mount_check/tasks/detect_stale_mount.yml
---
# =====================================================================
# Detect stale NFS mounts using timeout-protected stat command
# CRITICAL: We MUST use timeout here — without it, stat on a stale
# mount will hang the Ansible task indefinitely
# =====================================================================

- name: Test NFS mount I/O reachability using timeout-protected stat
  ansible.builtin.shell:
    cmd: >
      timeout {{ nfs_io_test_timeout_sec }} stat {{ item.mount_point }}
      > /dev/null 2>&1
      && echo "REACHABLE"
      || echo "STALE_OR_MISSING"
    # timeout {{ N }}: kill the command after N seconds
    # stat: touches the filesystem (faster than ls or touch)
    # > /dev/null 2>&1: suppress all output — we only care about exit code
    # && echo REACHABLE: if stat completes, mount is healthy
    # || echo STALE_OR_MISSING: if stat times out (exit 124) or fails — stale/missing
    executable: /bin/bash
  register: mount_io_tests
  loop: "{{ mount_presence | selectattr('is_mounted') | list }}"
  loop_control:
    label: "{{ item.mount_point }}"
  changed_when: false
  become: true
  # We only test mounts that ARE mounted (from check_proc_mounts)
  # Mounts that aren't in /proc/mounts are handled by the remount task

- name: Classify mounted mounts as healthy or stale
  ansible.builtin.set_fact:
    stale_mounts: >-
      {{ mount_io_tests.results
         | selectattr('stdout', 'equalto', 'STALE_OR_MISSING')
         | map(attribute='item')
         | list }}
    healthy_mounts: >-
      {{ mount_io_tests.results
         | selectattr('stdout', 'equalto', 'REACHABLE')
         | map(attribute='item')
         | list }}

- name: Identify completely missing mounts (not in /proc/mounts at all)
  ansible.builtin.set_fact:
    missing_mounts: >-
      {{ mount_presence
         | rejectattr('is_mounted')
         | list }}

- name: Log stale and missing mount detection results
  ansible.builtin.debug:
    msg:
      - "NFS Mount Health — {{ inventory_hostname }}"
      - "Healthy: {{ healthy_mounts | length }}"
      - "STALE: {{ stale_mounts | map(attribute='mount_point') | list | join(', ') | default('None') }}"
      - "MISSING: {{ missing_mounts | map(attribute='mount_point') | list | join(', ') | default('None') }}"

- name: Fire PagerDuty P1 for stale critical NFS mounts
  ansible.builtin.uri:
    url: "{{ pagerduty_integration_url }}"
    method: POST
    body_format: json
    body:
      routing_key: "{{ vault_pagerduty_routing_key }}"
      event_action: trigger
      dedup_key: "nfs-stale-{{ inventory_hostname }}-{{ item.mount_point | replace('/', '-') }}"
      payload:
        summary: >-
          🔴 STALE NFS MOUNT: {{ item.mount_point }} on {{ inventory_hostname }}
          is mounted but I/O is HANGING. {{ item.nfs_server }}:{{ item.nfs_export }}
          is unreachable. Auto-remount initiated.
        severity: "{{ 'critical' if item.critical else 'error' }}"
        source: ansible-nfs-monitor
        custom_details:
          host: "{{ inventory_hostname }}"
          mount_point: "{{ item.mount_point }}"
          nfs_server: "{{ item.nfs_server }}"
          nfs_export: "{{ item.nfs_export }}"
          action: "Ansible auto-remount triggered"
    status_code: [202]
  loop: "{{ stale_mounts }}"
  loop_control:
    label: "{{ item.mount_point }}"
  when: stale_mounts | length > 0
  delegate_to: localhost
roles/nfs_mount_check/tasks/check_mount_options.yml
---
# =====================================================================
# Validate mount options against security policy
# This catches the PCI-DSS finding (exec on backup mount)
# =====================================================================

- name: Check required and forbidden mount options for each healthy mount
  ansible.builtin.set_fact:
    options_compliance: >-
      {{ options_compliance | default([]) + [{
        'mount_point': item.mount_point,
        'actual_options': item.actual_options,
        'required_options': item.required_options,
        'forbidden_options': item.forbidden_options | default([]),
        'missing_required': (item.required_options
                             | reject('in', item.actual_options.split(','))
                             | list),
        'present_forbidden': (item.forbidden_options | default([])
                              | select('in', item.actual_options.split(','))
                              | list),
        'compliant': ((item.required_options
                       | reject('in', item.actual_options.split(','))
                       | list | length == 0)
                      and (item.forbidden_options | default([])
                           | select('in', item.actual_options.split(','))
                           | list | length == 0))
      }] }}
  loop: "{{ healthy_mounts }}"
  loop_control:
    label: "{{ item.mount_point }}"

- name: Alert on mount options violations
  ansible.builtin.uri:
    url: "{{ slack_webhook_url }}"
    method: POST
    body_format: json
    body:
      text: >-
        🔒 *NFS Mount Options Violation — {{ inventory_hostname }}*
        {% for m in options_compliance | rejectattr('compliant') | list %}
        *Mount:* {{ m.mount_point }}
        {% if m.missing_required %}
        Missing required: {{ m.missing_required | join(', ') }}
        {% endif %}
        {% if m.present_forbidden %}
        Forbidden options present: {{ m.present_forbidden | join(', ') }}
        {% endif %}
        Actual options: {{ m.actual_options }}
        {% endfor %}
        _PCI-DSS Req 7: Unauthorized options may allow code execution from NFS_
    status_code: [200]
  delegate_to: localhost
  when: options_compliance | rejectattr('compliant') | list | length > 0
roles/nfs_mount_check/tasks/check_capacity.yml
---
# =====================================================================
# Check disk usage on NFS mount points
# MUST use timeout — df on stale mount will hang!
# =====================================================================

- name: Get disk usage for each healthy NFS mount (timeout-protected)
  ansible.builtin.shell:
    cmd: >
      timeout {{ nfs_io_test_timeout_sec }} df -P {{ item.mount_point }}
      2>/dev/null | tail -1
    # df -P: POSIX output format (consistent columns across Linux versions)
    # tail -1: skip header line, get data line only
    # timeout: prevent hang on stale mount
    executable: /bin/bash
  register: df_results
  loop: "{{ healthy_mounts }}"
  loop_control:
    label: "{{ item.mount_point }}"
  changed_when: false
  become: true
  failed_when: false

- name: Parse df output and calculate usage percentages
  ansible.builtin.set_fact:
    capacity_status: >-
      {{ capacity_status | default([]) + [{
        'mount_point': item.item.mount_point,
        'capacity_warn': item.item.capacity_warn_percent | default(80),
        'capacity_critical': item.item.capacity_critical_percent | default(90),
        'df_output': item.stdout | default(''),
        'used_percent': (item.stdout | default('')
                         | regex_search('([0-9]+)%', '\\1')
                         | first | default(0) | int),
        'timed_out': item.rc == 124
      }] }}
  loop: "{{ df_results.results }}"
  loop_control:
    label: "{{ item.item.mount_point }}"

- name: Alert on high-capacity NFS mounts
  ansible.builtin.uri:
    url: "{{ pagerduty_integration_url }}"
    method: POST
    body_format: json
    body:
      routing_key: "{{ vault_pagerduty_routing_key }}"
      event_action: trigger
      dedup_key: "nfs-capacity-{{ inventory_hostname }}-{{ item.mount_point | replace('/', '-') }}"
      payload:
        summary: >-
          ⚠️ NFS Mount Capacity: {{ item.mount_point }} on {{ inventory_hostname }}
          is {{ item.used_percent }}% full (threshold: {{ item.capacity_critical }}%)
        severity: "{{ 'critical' if item.used_percent >= item.capacity_critical else 'error' }}"
        source: ansible-nfs-monitor
    status_code: [202]
  loop: "{{ capacity_status | selectattr('used_percent', '>=', 75) | list }}"
  loop_control:
    label: "{{ item.mount_point }} ({{ item.used_percent }}%)"
  when: capacity_status | selectattr('used_percent', '>=', 75) | list | length > 0
  delegate_to: localhost

  loop: "{{ stale_mounts + missing_mounts }}"

    label: "Unmounting: {{ item.mount_point }}"

  register: unmount_results
  become: true

- name: Wait for unmount to complete

# NFS fstab Audit — Weekly
# Finds unauthorized/ghost NFS entries in /etc/fstab
# =====================================================================
- name: NFS fstab Reconciliation Audit
  hosts: nfs_clients
  gather_facts: false
  become: true
  serial: 30

  vars_files:
    - "{{ inventory_dir }}/group_vars/all/vault.yml"

        src: /etc/fstab

        fstab_nfs_entries: >-
          {{ fstab_raw.content | b64decode
             | split('\n')
             | reject('match', '^#.*')
             | reject('equalto', '')
             | select('match', '.*\\s+nfs[4]?\\s+.*')
             | list }}
        # Reject comment lines (starting with #)
        # Reject empty lines
        # Select only NFS mount lines

    - name: Identify fstab NFS entries NOT in approved mount list
      ansible.builtin.set_fact:
        nfs_mounts_expected: >-
          {{ nfs_mounts_oracle_db + nfs_mounts_app_servers + nfs_mounts_backup_servers }}
        approved_mount_points: >-
          {{ (nfs_mounts_oracle_db + nfs_mounts_app_servers + nfs_mounts_backup_servers)
             | map(attribute='mount_point') | list }}

    - name: Check each fstab NFS entry against approved list
      ansible.builtin.set_fact:
        unauthorized_fstab_mounts: >-
          {{ fstab_nfs_entries
             | reject('search', approved_mount_points | join('|'))
             | list }}
        # reject('search', pattern): remove lines matching any approved mount point
        # What remains = unauthorized/ghost NFS entries

    - name: Alert on unauthorized fstab NFS entries
      ansible.builtin.uri:
        url: "{{ slack_webhook_url }}"
        method: POST
        body_format: json
        body:
          text: >-
            ⚠️ *Unauthorized NFS fstab Entries — {{ inventory_hostname }}*
            The following NFS mounts in /etc/fstab are NOT in the approved mount list:
            {% for entry in unauthorized_fstab_mounts %}
            • {{ entry }}
            {% endfor %}

🎯 16. Interview Prep

Q: Why use /proc/mounts instead of the mount command to check if an NFS share is mounted?
The mount command and df both read from the kernel, but they do so by accessing the actual filesystem — which means they will HANG if any listed path is a stale NFS mount. /proc/mounts is a kernel virtual file that is always readable from the VFS layer without triggering any filesystem I/O. Reading /proc/mounts with slurp will NEVER hang, even if every single NFS mount on the system is stale.

This is a critical distinction. If we used ansible.builtin.command: mount, our monitoring playbook would hang on stale mounts — making it completely useless exactly when we need it most.
Q: What is the difference between hard and soft NFS mounts, and when would you use each?
Hard mount: The NFS client retries I/O indefinitely if the server is unreachable. The process accessing the mount enters an uninterruptible D-state sleep. It cannot be killed. Oracle and databases require hard mounts because a soft mount that returns an I/O error mid-transaction can corrupt the database.

Soft mount: The NFS client returns an I/O error to the application after a configurable timeout. The process gets an error it can handle — no hanging. Better for application servers accessing configuration files (an error is better than a hang).

Banking rule: Oracle archivelog and RMAN backup mounts → hard. Application config and report shares → soft with timeo and retrans set.
Q: How do you detect a stale NFS mount without hanging the Ansible task?
The key technique is the Linux timeout command wrapped around any I/O operation on the mount:

timeout 5 stat /mount_point > /dev/null 2>&1 && echo REACHABLE || echo STALE

stat is used instead of ls or touch because it's the fastest filesystem metadata operation. The timeout 5 prefix guarantees the command completes in at most 5 seconds — if the mount is stale and stat hangs, timeout kills it after 5 seconds and returns exit code 124.

We check the output ("REACHABLE" vs "STALE_OR_MISSING") rather than the exit code because timeout's exit code 124 is different from stat's failure exit code — using stdout string comparison is more reliable across different shell environments.
Q: Why use umount -f -l instead of just umount for stale mounts?
Regular umount /path will ALSO hang on a stale NFS mount because it tries to communicate with the NFS server to do a clean unmount. We need:

-f (force): Forces the unmount without waiting for a server response. Immediately tells the kernel to stop trying to use the NFS server.
-l (lazy): Detaches the filesystem from the directory tree immediately, but allows processes that already have files open to continue until they close them. Without -l, force unmount on a busy mount fails with "device busy."

The combination umount -f -l is the industry standard approach for recovering stale NFS mounts. After this, processes that had open files will get SIGPIPE or EIO errors on their next I/O operation — they can then handle the error gracefully rather than hanging indefinitely.
