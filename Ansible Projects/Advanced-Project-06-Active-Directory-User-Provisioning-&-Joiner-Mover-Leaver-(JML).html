Project 06: Active Directory User Provisioning & Joiner-Mover-Leaver (JML) Automation

Every bank employs thousands of staff — analysts, tellers, managers, IT engineers, and contractors. Each person joining, moving between departments, or leaving the bank requires precise Active Directory actions: creating accounts with correct OUs and groups (Joiner), updating access when roles change (Mover), and disabling/deleting accounts immediately when staff leave (Leaver). This project automates the complete JML lifecycle — driven by ServiceNow HR tickets — using Ansible with WinRM to manage Windows Domain Controllers. It enforces PCI-DSS Req 8 (user account management) and reduces provisioning time from 2 days to under 5 minutes.

🏦 1. The Banking Story

Setting: ABC Global Bank employs 18,500 staff across 320 branches. The IT team manages Active Directory for all staff accounts — covering banking applications, email, VPN, and system access. The bank's AD has 12,000+ user accounts across 47 OUs mapped to departments.

Three Real Incidents:

Incident 1 — The Leaver Problem: Rajan Sharma resigned from the Treasury department on a Friday. HR raised a ticket. The AD admin was on leave. Nobody disabled Rajan's account over the weekend. On Monday, Rajan used his still-active VPN and AD credentials to access Treasury system reports. This was a data breach. RBI was notified. PCI-DSS audit finding: "User accounts not disabled within required timeframe."

Incident 2 — The Mover Problem: Priya Nair moved from Retail Banking to the Credit Risk team. Her old Retail Banking AD groups (access to CBS teller module, branch vault reports) were never removed. She retained access to systems she no longer needed for 8 months — violating PCI-DSS Req 7 (least privilege). Found only during a quarterly access review audit.

Incident 3 — The Joiner Delay: A new DBA joined the IT team. It took 2 days to create his AD account because the AD admin was busy. He sat idle for 2 days — unproductive. The hiring manager complained. This happened 23 times in one quarter.

The Ask: "Automate JML completely. A resignation ServiceNow ticket must disable the AD account within 15 minutes. A new hire ticket must provision the account within 5 minutes. A role-change ticket must update groups immediately."

📚 2. Active Directory & JML Concepts

Active Directory Structure — OUs, Groups, GPOs
OU (Organizational Unit): Folder-like container in AD. User accounts are placed in OUs that match their department. GPOs (Group Policy Objects) apply to OUs — placing a user in the wrong OU gives them wrong GPO settings (e.g., branch teller OU applies branch PC lockdown policy).

Security Groups: Control access to resources. Users are members of groups; groups are granted permissions. In banking, groups control: application access (CBS-Teller-Access), network share access (Finance-Reports-Read), VPN profiles (VPN-Treasury-Users).

UPN (User Principal Name): Login name format: firstname.lastname@abcbank.in. Must be unique across the domain.

sAMAccountName: The pre-Windows 2000 login name (max 20 characters). Used for legacy application authentication. Format: firstinitial+lastname (e.g., rajan.sharma → rsharma).
JML Lifecycle — What Each Stage Requires
StageTriggerAD Actions RequiredPCI-DSS Requirement
JoinerNew hire HR ticket approvedCreate user in correct OU, set groups per role, set password, enable account, set expiry (contractors), send welcome emailReq 8.2 — Unique IDs for all users
MoverTransfer/promotion HR ticket approvedMove user to new OU, remove old role groups, add new role groups, update manager attributeReq 7.2 — Access based on need to know; Req 8.6 — Remove unnecessary access
LeaverResignation/termination HR ticketDisable account IMMEDIATELY, remove from all groups, move to Disabled-Users OU, set account expiry to today, clear manager attribute, forward email (optional)Req 8.1.4 — Remove inactive accounts within 90 days (immediate for terminations)
Key Ansible Modules for Active Directory
  • microsoft.ad.user — Create, modify, disable, delete AD users (new recommended module)
  • microsoft.ad.group — Manage AD security groups
  • microsoft.ad.ou — Manage Organizational Units
  • microsoft.ad.membership — Manage group memberships
  • ansible.windows.win_shell + PowerShell — For complex AD operations not covered by modules
All these modules run via WinRM on a Domain Controller.

❗ 4. Problem Statement

Current Manual Process

  • HR raises ServiceNow ticket → AD admin reads email → manually creates/modifies/disables account in ADUC (AD Users and Computers GUI)
  • Leaver: depends on AD admin being available — SLA routinely breached on weekends/holidays
  • Mover: old groups often not removed — access accumulates over career (Priya's incident)
  • Joiner: 2-day average provisioning time — productivity loss
  • No audit trail of WHO made which AD change and WHEN
  • Password set manually → sometimes weak or reused passwords
  • Contractor expiry dates not tracked — contracts silently become permanent

After Automation

  • ServiceNow webhook → AAP → AD change within 5-15 minutes, 24x7
  • Leaver disable: 15-minute SLA met regardless of weekends or holidays
  • Mover: old groups explicitly removed first, then new groups added — no accumulation
  • Joiner: 5-minute provisioning after HR approval
  • Every AD change logged in AAP job history with ServiceNow ticket reference
  • Temporary password auto-generated, meets policy, forces change at first login
  • Contractor expiry: set from ticket field — automatic expiry enforced

💻 9. Roles & Tasks — Complete Code

Role: ad_joiner — Create New Employee Account

roles/ad_joiner/tasks/validate_inputs.yml
---
# =====================================================================
# Validate all required inputs from ServiceNow webhook payload
# Fail early with clear messages if any required field is missing
# =====================================================================

- name: Validate required fields are present in webhook payload
  ansible.builtin.assert:
    that:
      - employee_id is defined and employee_id | length > 0
      - full_name is defined and full_name | length > 0
      - department is defined and department in ou_map
      - role is defined and role in role_group_map
      - manager_username is defined and manager_username | length > 0
      - employee_type is defined and employee_type in ['permanent', 'contractor']
      - snow_ticket is defined
    fail_msg: >-
      JML Joiner validation FAILED for ticket {{ snow_ticket | default('UNKNOWN') }}.
      Missing or invalid required fields. Check ServiceNow webhook payload.
      Required: employee_id, full_name, department (must be in ou_map),
      role (must be in role_group_map), manager_username, employee_type, snow_ticket.
    success_msg: "All required joiner fields validated successfully for {{ full_name }}"

- name: Validate contractor has contract end date
  ansible.builtin.assert:
    that:
      - contract_end_date is defined
      - contract_end_date | length > 0
    fail_msg: "Contractor account requires contract_end_date field. Ticket: {{ snow_ticket }}"
  when: employee_type == 'contractor'

- name: Generate UPN and sAMAccountName from full name
  ansible.builtin.set_fact:
    # UPN format: firstname.lastname@abcbank.in
    user_upn: >-
      {{ (full_name.split()[0] | lower)
         + '.'
         + (full_name.split()[-1] | lower)
         + upn_suffix }}
    # sAMAccountName: first initial + lastname (max 20 chars)
    user_sam: >-
      {{ ((full_name.split()[0][0] | lower)
          + (full_name.split()[-1] | lower))[:20] }}
    # [:20] truncates to 20 characters — AD sAMAccountName limit

- name: Log generated account names
  ansible.builtin.debug:
    msg:
      - "Full Name: {{ full_name }}"
      - "UPN: {{ user_upn }}"
      - "sAMAccountName: {{ user_sam }}"
      - "Department: {{ department }}"
      - "Role: {{ role }}"
      - "Employee Type: {{ employee_type }}"
      - "ServiceNow Ticket: {{ snow_ticket }}"
roles/ad_joiner/tasks/create_user.yml
---
# =====================================================================
# Create Active Directory user account using microsoft.ad.user module
# =====================================================================

- name: Generate a secure random initial password
  ansible.windows.win_shell:
    cmd: |
      # PowerShell: generate cryptographically random password
      Add-Type -AssemblyName System.Web
      $pwd = [System.Web.Security.Membership]::GeneratePassword(
        {{ initial_password_length }}, 4)
      # GeneratePassword(length, numNonAlphanumeric)
      # 4 non-alphanumeric chars ensures complexity requirement
      Write-Output $pwd
  register: generated_password
  changed_when: false
  no_log: true                                             # Never log generated passwords!

- name: Store generated password as fact (no_log protected)
  ansible.builtin.set_fact:
    user_initial_password: "{{ generated_password.stdout | trim }}"
  no_log: true                                             # Protect in fact registration too

- name: Create Active Directory user account
  microsoft.ad.user:                                       # microsoft.ad collection module
    name: "{{ full_name }}"                                # Display name: "Amit Kumar"
    sam_account_name: "{{ user_sam }}"                     # sAMAccountName: "akumar"
    upn: "{{ user_upn }}"                                  # UPN: "amit.kumar@abcbank.in"
    firstname: "{{ full_name.split()[0] }}"                # Given name
    surname: "{{ full_name.split()[-1] }}"                 # Surname
    password: "{{ user_initial_password }}"                # Initial password (forced change)
    password_never_expires: false                          # false = password expires per policy
    update_password: on_create                             # Only set password when creating (not on re-runs)
    user_cannot_change_password: false                     # User can (and must) change password
    path: "{{ ou_map[department] }}"                       # OU path from our ou_map variable
    # Example: "OU=Treasury,OU=HO-Staff,DC=abcbank,DC=in"
    state: present                                         # Create if not exists
    enabled: true                                          # Account starts enabled
    attributes:                                            # Additional AD attributes
      # Department attribute in AD
      department: "{{ department }}"
      # Title/job role
      title: "{{ role | replace('_', ' ') }}"
      # Employee ID (custom attribute)
      employeeID: "{{ employee_id }}"
      # Manager attribute: must be the manager's DN (Distinguished Name)
      manager: "CN={{ manager_username }},{{ ou_map[manager_department | default(department)] }}"
      # Company name
      company: "ABC Global Bank"
      # Description: references the ServiceNow ticket for audit trail
      description: "Created by Ansible AAP — Ticket: {{ snow_ticket }} — {{ ansible_date_time.date }}"
  register: user_creation_result
  no_log: false                                            # Log the task (no passwords in params)

- name: Force password change at first login
  ansible.windows.win_shell:
    cmd: >
      Set-ADUser -Identity "{{ user_sam }}"
                 -ChangePasswordAtLogon $true
      # PowerShell: sets the "User must change password at next logon" flag
      # The microsoft.ad.user module doesn't expose this directly — use PowerShell
  when: initial_password_must_change | bool

- name: Log user creation result
  ansible.builtin.debug:
    msg: >-
      ✅ AD Account Created:
      User: {{ user_upn }}
      sAMAccountName: {{ user_sam }}
      OU: {{ ou_map[department] }}
      Ticket: {{ snow_ticket }}
      Changed: {{ user_creation_result.changed }}
roles/ad_joiner/tasks/assign_groups.yml
---
# =====================================================================
# Assign role-based AD security groups to new user
# Groups determined by role_group_map variable
# =====================================================================

- name: Get list of groups to assign for role {{ role }}
  ansible.builtin.set_fact:
    groups_to_assign: "{{ role_group_map[role] | default([]) }}"
    # role_group_map[role]: looks up the role in our group mapping dictionary
    # default([]): returns empty list if role not found (validate_inputs should catch this)

- name: Fail if no groups defined for this role
  ansible.builtin.fail:
    msg: "No group mapping found for role '{{ role }}'. Add it to role_group_map in group_vars/all.yml"
  when: groups_to_assign | length == 0

- name: Add user to all role-based security groups
  microsoft.ad.membership:                               # Module for AD group membership
    name: "{{ item }}"                                   # Group name
    members:
      add:
        - "{{ user_sam }}"                               # Add our new user's sAMAccountName
    state: present
  loop: "{{ groups_to_assign }}"                         # Loop over all groups for this role
  loop_control:
    label: "Adding {{ user_sam }} to {{ item }}"
  register: group_assignment_results

- name: Log group assignments
  ansible.builtin.debug:
    msg: >-
      Group assignments for {{ user_sam }}:
      {{ groups_to_assign | join(', ') }}
roles/ad_joiner/tasks/set_contractor_expiry.yml
---
# =====================================================================
# Set account expiry date for contractors
# Permanent employees never have account expiry set
# =====================================================================

- name: Skip expiry configuration for permanent employees
  ansible.builtin.meta: end_host
  when: employee_type != 'contractor'

- name: Set AD account expiry to contractor end date
  microsoft.ad.user:
    sam_account_name: "{{ user_sam }}"
    state: present
    account_expires: "{{ contract_end_date }}"
    # account_expires: ISO date string "2024-12-31"
    # AD will automatically lock the account at midnight on this date
    # No manual tracking needed — AD enforces it automatically

- name: Add contractor expiry note to AD description
  ansible.windows.win_shell:
    cmd: >
      Set-ADUser -Identity "{{ user_sam }}"
                 -Description "Contractor — Expires: {{ contract_end_date }}
                               — Ticket: {{ snow_ticket }}
                               — Created: {{ ansible_date_time.date }}"

- name: Log contractor expiry configuration
  ansible.builtin.debug:
    msg: >-
      Contractor account {{ user_sam }} set to expire on {{ contract_end_date }}

Role: ad_leaver — Disable Account & Remove Access (Most Critical)

roles/ad_leaver/tasks/disable_account.yml
---
# =====================================================================
# LEAVER: Disable account immediately upon termination
# This is the most time-sensitive JML operation — PCI-DSS Req 8.1.4
# SLA: Complete within 15 minutes of ServiceNow ticket approval
# =====================================================================

- name: Look up user in Active Directory by employee ID
  ansible.windows.win_shell:
    cmd: >
      Get-ADUser -Filter { EmployeeID -eq '{{ employee_id }}' }
                 -Properties SamAccountName, DistinguishedName,
                              DisplayName, Department, Enabled |
      ConvertTo-Json -Depth 2
    # Search by EmployeeID (not username) to handle name changes
    # EmployeeID never changes — username might after marriage/divorce
  register: ad_user_lookup
  changed_when: false

- name: Fail if user not found in AD (may already be disabled)
  ansible.builtin.fail:
    msg: >-
      Leaver process FAILED: Employee ID {{ employee_id }} not found in Active Directory.
      Check if account was already disabled or employee ID is correct.
      ServiceNow Ticket: {{ snow_ticket }}
  when: ad_user_lookup.stdout | trim == '' or ad_user_lookup.stdout | trim == 'null'

- name: Parse AD user data
  ansible.builtin.set_fact:

---
# =====================================================================
# MOVER: Update AD account when employee changes role or department
# Key: Remove OLD access BEFORE adding NEW access (not additive!)
# =====================================================================

- name: Look up current user AD state
  ansible.windows.win_shell:
    cmd: >
      Get-ADUser -Filter { EmployeeID -eq '{{ employee_id }}' }
                 -Properties SamAccountName, MemberOf, Department, Title |
      ConvertTo-Json -Depth 3
  register: mover_user_lookup
  changed_when: false

- name: Parse user data
  ansible.builtin.set_fact:
    mover_user: "{{ mover_user_lookup.stdout | from_json }}"
    mover_sam: "{{ (mover_user_lookup.stdout | from_json).SamAccountName }}"

- name: Get current group SamAccountNames
  ansible.windows.win_shell:
    cmd: >
      (Get-ADUser -Identity "{{ mover_sam }}" -Properties MemberOf).MemberOf |
      ForEach-Object { (Get-ADGroup $_).SamAccountName } | ConvertTo-Json
  register: current_groups_raw
  changed_when: false

- name: Parse current groups
  ansible.builtin.set_fact:
    mover_current_groups: >-
      {{ current_groups_raw.stdout | from_json
         if current_groups_raw.stdout | trim not in ['', 'null']
         else [] }}

- name: Determine groups to REMOVE (old role groups)
  ansible.builtin.set_fact:
    groups_to_remove: >-
      {{ role_group_map[old_role] | default([])
         | intersect(mover_current_groups) }}
    # intersect: only remove groups the user actually has
    # This prevents errors trying to remove groups they weren't in

- name: Determine groups to ADD (new role groups)
  ansible.builtin.set_fact:
    groups_to_add: "{{ role_group_map[new_role] | default([]) }}"

- name: Remove OLD role groups first (principle of least privilege)
  ansible.windows.win_shell:
    cmd: >
      Remove-ADGroupMember -Identity "{{ item }}"
                           -Members "{{ mover_sam }}"
                           -Confirm:$false
  loop: "{{ groups_to_remove }}"
  loop_control:
    label: "Removing from: {{ item }}"
  when: groups_to_remove | length > 0

- name: Move user to new department OU
  microsoft.ad.user:
    sam_account_name: "{{ mover_sam }}"
    state: present
    path: "{{ ou_map[new_department] }}"                  # New department OU
    attributes:
      department: "{{ new_department }}"
      title: "{{ new_role | replace('_', ' ') }}"

- name: Add NEW role groups
  microsoft.ad.membership:
    name: "{{ item }}"
    members:
      add:
        - "{{ mover_sam }}"
    state: present
  loop: "{{ groups_to_add }}"
  loop_control:
    label: "Adding to: {{ item }}"

- name: Log mover completion
  ansible.builtin.debug:
    msg:
      - "✅ MOVER COMPLETE: {{ mover_sam }}"
      - "Removed from: {{ groups_to_remove | join(', ') }}"
      - "Added to: {{ groups_to_add | join(', ') }}"
      - "Moved to OU: {{ ou_map[new_department] }}"
      - "Ticket: {{ snow_ticket }}"

ServiceNow Business Rule — Trigger AAP on Ticket Approval
// ServiceNow Business Rule (JavaScript)
// Table: sc_req_item | When: After | Condition: state changes to Approved

(function executeRule(current, previous) {
  var restMessage = new sn_ws.RESTMessageV2();

  // Determine action type from ticket category
  var action = current.getValue('cat_item');  // joiner, mover, or leaver

  var endpointMap = {
    'new_hire':     'https://aap.abcbank.in/api/v2/job_templates/45/github/',
    'transfer':     'https://aap.abcbank.in/api/v2/job_templates/46/github/',
    'termination':  'https://aap.abcbank.in/api/v2/job_templates/47/github/'
  };

  restMessage.setEndpoint(endpointMap[action]);
  restMessage.setHttpMethod('POST');
  restMessage.setRequestHeader('Content-Type', 'application/json');
  restMessage.setRequestHeader('X-GitHub-Event', 'push');  // AAP webhook type

  var payload = {
    "employee_id":       current.getValue('u_employee_id'),
    "full_name":         current.getValue('u_employee_name'),
    "department":        current.getValue('u_department'),
    "role":              current.getValue('u_job_role'),
    "manager_username":  current.getValue('u_manager_username'),
    "employee_type":     current.getValue('u_employment_type'),
    "snow_ticket":       current.getValue('number'),
    "snow_ticket_sys_id": current.getValue('sys_id'),
    "contract_end_date": current.getValue('u_contract_end_date'),
    "old_role":          current.getValue('u_previous_role'),
    "new_role":          current.getValue('u_new_role'),
    "new_department":    current.getValue('u_new_department')
  };

  restMessage.setRequestBody(JSON.stringify(payload));
  var response = restMessage.execute();
})(current, previous);

🎯 14. Interview Preparation

Q: What is the difference between a Security Group and a Distribution Group in AD?
Security Group: Used to control access to resources (file shares, applications, VPN). Members inherit the permissions granted to the group. When we add a user to CBS-Teller-Access, they get the application permissions granted to that group. This is what all JML automation manages.

Distribution Group: Used only for email distribution lists (like mailing lists). Cannot be used to control resource access. When we add a user to "Email-Treasury-Team", it only adds them to the treasury mailing list — it doesn't grant any system access.

In JML automation, we only manage Security Groups (and Mail-Enabled Security Groups that serve both purposes).
Q: Why do you search by Employee ID instead of username in the leaver process?
Employee usernames can change over the course of a career: marriage, divorce, or legal name change all cause username updates. An employee who joined as priya.sharma might now be priya.nair.

Employee IDs (like E12345) are assigned at hiring and NEVER change. ServiceNow's HR records use Employee ID as the primary key. By searching AD using the employeeID attribute (a custom AD attribute we populate during joiner), we always find the correct account regardless of name changes. Using username risks missing the account if it was renamed — a serious PCI-DSS compliance gap.
Q: How does the Mover process prevent privilege accumulation?
Privilege accumulation (also called "role creep") is when users retain access from previous roles as they move through the organization. After 5 years, someone who's been in 3 departments has the combined access of all 3.

Our Mover automation prevents this with the explicit sequence:
1. Get the user's CURRENT groups
2. Determine which groups belong to the OLD role (from role_group_map[old_role])
3. Use intersect to find old-role groups the user actually has
4. Remove those groups FIRST
5. THEN add the new role groups

The order matters. Remove-then-add ensures there's a brief moment where the user has fewer privileges (acceptable) rather than an extended period with both old AND new access (not acceptable under PCI-DSS Req 7).
Q: How would you handle an emergency off-hours leaver (e.g., immediate termination for cause)?
For immediate termination (misconduct, fraud suspicion), waiting for the ServiceNow webhook workflow may be too slow. Two approaches:

1. Emergency AAP template: Create a separate "AD-Emergency-Leaver" Job Template that ONLY requires employee_id as a survey input. Restricted to Security Team and CISO only. Can be launched manually from AAP mobile app in 30 seconds.

2. Break-glass PowerShell script: A pre-approved PowerShell one-liner stored in a secure runbook. For true emergencies where AAP access may be unavailable: Disable-ADAccount -Identity "employeeID" -Confirm:$false. All break-glass executions are logged to the SIEM.

The automation should always be faster than manual — but break-glass exists as a safety net for infrastructure failures.
