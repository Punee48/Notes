1. The Production Story

Scenario The payment-api namespace baseline (Project 1) and RBAC (Project 2) are in place. Now the application team asks platform engineering to help them stand up their actual stack: a React frontend, a backend API, a PostgreSQL database, and a Redis cache — consistently across DEV/QA/STAGE/PROD, with zero manual oc apply commands.
Business Problem Previously, each environment's stack was deployed slightly differently — one environment was missing readiness probes, another had the database Secret checked into a plaintext YAML file in Git. We need one Ansible-driven definition of "the stack" that's safe to run in every environment.
Our Mandate Automate the full multi-tier deployment: Deployments, Services, ConfigMaps, Vault-encrypted Secrets, PersistentVolumeClaims for the database, resource limits, liveness/readiness probes, and a Route exposing the frontend.

5. The Playbooks — Fully Commented

5.1 roles/postgres/tasks/main.yml

roles/postgres/tasks/main.yml
---
# PostgreSQL needs a PVC because its data must survive pod restarts
# and rescheduling -- unlike the stateless frontend/backend tiers.

- name: Create Secret with vaulted DB credentials                 # stores creds -- never plaintext in Git
  kubernetes.core.k8s:                                             # declarative apply module
    state: present                                                 # create-or-update
    definition:
      apiVersion: v1                                                # core API group
      kind: Secret                                                  # Secret object type
      metadata:
        name: "{{ app_name }}-db-secret"                              # e.g. payment-api-db-secret
        namespace: "{{ app_name }}-{{ environment }}"                  # app namespace only
      type: Opaque                                                   # generic key/value secret type
      stringData:                                                    # plaintext here -- module base64-encodes it server-side
        POSTGRES_USER: "{{ db_user }}"                                 # from vault.yml, decrypted at runtime only
        POSTGRES_PASSWORD: "{{ db_password }}"                         # never printed in logs (no_log below)
  no_log: true                                                       # suppresses task output so the password never hits the log

- name: Claim persistent storage for PostgreSQL data                # request durable disk from the cluster's StorageClass
  kubernetes.core.k8s:
    state: present
    definition:
      apiVersion: v1
      kind: PersistentVolumeClaim                                    # request object; cluster's CSI driver provisions the actual volume
      metadata:
        name: "{{ app_name }}-db-pvc"
        namespace: "{{ app_name }}-{{ environment }}"
      spec:
        accessModes: [ReadWriteOnce]                                  # one node can mount read-write at a time -- correct for a single DB pod
        resources:
          requests:
            storage: "{{ db_storage_size | default('5Gi') }}"           # env-tunable size, default 5Gi for dev/lab

- name: Deploy PostgreSQL                                            # the actual database workload
  kubernetes.core.k8s:
    state: present
    definition:
      apiVersion: apps/v1                                             # Deployment lives in the apps API group
      kind: Deployment
      metadata:
        name: "{{ app_name }}-postgres"
        namespace: "{{ app_name }}-{{ environment }}"
      spec:
        replicas: 1                                                    # single instance -- PVC ReadWriteOnce means we can't scale this naively
        selector:
          matchLabels: {app: "{{ app_name }}-postgres"}                 # must match template labels below exactly
        template:
          metadata:
            labels: {app: "{{ app_name }}-postgres"}                    # Service will select pods using this label
          spec:
            containers:
              - name: postgres
                image: "registry.redhat.io/rhel9/postgresql-15:latest"   # pinning a real tag is a PROD best practice, 'latest' is for lab only
                envFrom:
                  - secretRef: {name: "{{ app_name }}-db-secret"}         # injects POSTGRES_USER/PASSWORD as env vars
                ports:
                  - containerPort: 5432                                   # standard PostgreSQL port
                volumeMounts:
                  - name: data
                    mountPath: /var/lib/pgsql/data                        # where the image expects its data directory
                resources:                                                # prevents this pod from starving the namespace quota (Project 1)
                  requests: {cpu: 250m, memory: 512Mi}
                  limits: {cpu: 1, memory: 1Gi}
                readinessProbe:                                          # pod only receives traffic once this passes
                  exec: {command: ["pg_isready", "-U", "{{ db_user }}"]}
                  initialDelaySeconds: 10                                  # give postgres time to initialize before first check
                livenessProbe:                                            # restarts the container if it becomes unresponsive
                  exec: {command: ["pg_isready", "-U", "{{ db_user }}"]}
                  initialDelaySeconds: 30
            volumes:
              - name: data
                persistentVolumeClaim: {claimName: "{{ app_name }}-db-pvc"} # binds the PVC created above into the pod

- name: Expose PostgreSQL internally only                             # ClusterIP -- never a Route for a database
  kubernetes.core.k8s:
    state: present
    definition:
      apiVersion: v1
      kind: Service
      metadata:
        name: "{{ app_name }}-postgres"
        namespace: "{{ app_name }}-{{ environment }}"
      spec:
        selector: {app: "{{ app_name }}-postgres"}                       # routes traffic to pods with this label
        ports:
          - port: 5432
            targetPort: 5432

5.2 roles/backend/tasks/main.yml (key excerpt)

roles/backend/tasks/main.yml
---
# Backend API tier: stateless, talks to Postgres + Redis internally,
# never exposed via a Route directly.

- name: Deploy backend API                                           # stateless workload -- safe to run multiple replicas
  kubernetes.core.k8s:
    state: present
    definition:
      apiVersion: apps/v1
      kind: Deployment
      metadata:
        name: "{{ app_name }}-backend"
        namespace: "{{ app_name }}-{{ environment }}"
      spec:
        replicas: "{{ backend_replicas | default(2) }}"                  # 2+ for basic HA even in dev
        selector:
          matchLabels: {app: "{{ app_name }}-backend"}
        template:
          metadata:
            labels: {app: "{{ app_name }}-backend"}
          spec:
            containers:
              - name: backend
                image: "{{ backend_image }}"                              # passed in per environment/build
                envFrom:
                  - secretRef: {name: "{{ app_name }}-db-secret"}          # same DB creds, read-only usage here
                  - configMapRef: {name: "{{ app_name }}-baseline"}        # ENVIRONMENT/TEAM from Project 1's baseline
                ports: [{containerPort: 8080}]
                resources:
                  requests: {cpu: 200m, memory: 256Mi}
                  limits: {cpu: 500m, memory: 512Mi}
                readinessProbe:                                           # HTTP check -- only serve traffic once DB connection is healthy
                  httpGet: {path: /healthz, port: 8080}
                  initialDelaySeconds: 5
                livenessProbe:
                  httpGet: {path: /healthz, port: 8080}
                  initialDelaySeconds: 15

5.3 roles/frontend/tasks/main.yml (Route excerpt)

roles/frontend/tasks/main.yml
# Only the frontend gets a Route -- this is the single ingress
# point for the whole stack.
- name: Expose frontend externally via Route with TLS edge termination
  kubernetes.core.k8s:
    state: present
    definition:
      apiVersion: route.openshift.io/v1                                 # OpenShift-specific Route API
      kind: Route
      metadata:
        name: "{{ app_name }}-frontend"
        namespace: "{{ app_name }}-{{ environment }}"
      spec:
        to: {kind: Service, name: "{{ app_name }}-frontend"}              # backing Service for this Route
        tls:
          termination: edge                                              # TLS ends at the router; HTTP internally -- simplest, most common pattern
          insecureEdgeTerminationPolicy: Redirect                         # force HTTP -> HTTPS redirect

7. Live Incident — Backend CrashLoopBackOff

ReportAfter deploying to STAGE, the backend pods are stuck restarting.
oc get pods -n payment-api-stage
NAME                        READY   STATUS             RESTARTS
payment-api-backend-6f-x1   0/1     CrashLoopBackOff   6

oc logs payment-api-backend-6f-x1 -n payment-api-stage
FATAL: password authentication failed for user "payment_app"

Investigate: the backend Secret reference is correct, but STAGE's vault.yml was never created — Ansible fell back to an undefined variable that rendered as an empty string.

oc get secret payment-api-db-secret -n payment-api-stage -o jsonpath='{.data.POSTGRES_PASSWORD}' | base64 -d
# empty output
Root causeMissing environment-specific group_vars/stage/vault.yml — the DB password variable was undefined, Ansible defaulted it to an empty string instead of failing.

Fix: create the vaulted file for STAGE, add an assert that db_password | length > 0 before deploying, re-run.

# Add near the top of postgres/tasks/main.yml:
- name: Ensure DB password is actually set                          # fail loudly instead of deploying a broken secret
  ansible.builtin.assert:
    that:
      - db_password is defined
      - db_password | length > 0
    fail_msg: "db_password is missing -- check group_vars/{{ environment }}/vault.yml"

8. Additional Break-Fix Labs

Break-Fix — PVC stuck Pending 
oc get pvc -n payment-api-dev
NAME                STATUS    VOLUME   CAPACITY
payment-api-db-pvc  Pending

oc describe pvc payment-api-db-pvc -n payment-api-dev
Events: no persistent volumes available for this claim and no storage class is set

Root cause: no default StorageClass on the cluster. Fix: set storageClassName explicitly in the PVC definition or configure a cluster default StorageClass.

Break-Fix — readiness probe failing, Service has no endpoints 
oc get endpoints payment-api-backend -n payment-api-dev
NAME                   ENDPOINTS
payment-api-backend    <none>

Root cause: pods are Running but never pass readiness, so the Service never adds them as endpoints. Fix: check /healthz path matches the actual app route; check the app can reach Postgres/Redis from inside the pod with oc rsh.

10. Interview Preparation

Interviewer: "How do you handle secrets in your Ansible-driven OpenShift deployments?"

Answer: Sensitive values live in an Ansible Vault-encrypted file, never in plaintext in the repo. The playbook reads them at runtime and writes them into a Kubernetes Secret, with no_log: true on that task so the value never appears in Ansible's own output or CI logs.

Interviewer: "Backend pods are CrashLoopBackOff after a deploy to a new environment — how do you approach it?"

Answer: oc logs first — that's almost always the fastest signal. In this case it showed a DB auth failure, which pointed me at the Secret's actual decoded value, which was empty because that environment's vault file didn't exist. I added an explicit assert so this fails at plan time, not at pod-crash time.
