Multi-Environment Promotion Workflows: DEV → QA → STAGE → PROD

Building a single Ansible-driven promotion pipeline that moves one validated artifact through every environment with escalating safeguards, and resolving a "PROD got a version QA never actually tested" incident.

Difficulty: Advanced
Domain: Telecom / Platform Engineering

Ansible Core: 2.16 · AAP 2.4+ (Project 19)

1. The Production Story

Scenario Projects 5, 18, and 19 gave us safe deploys, a CI/CD pipeline, and governed execution — but each environment has effectively been deployed independently. Nothing guarantees the exact artifact that passed QA is the SAME artifact that reaches PROD. The compliance team wants provable promotion: one image, one Git SHA, moving through a defined sequence with evidence at each gate.
Business Problem Without a formal promotion chain, it's possible (and it has happened) for PROD to receive a rebuild from the same source that technically differs from what QA actually validated — different base image layer, different dependency resolution at build time, etc.
Our Mandate Build a promotion workflow where ONE immutable image, identified by digest (not just tag), moves through DEV → QA → STAGE → PROD, with each stage's validation results recorded as promotion evidence, and increasingly strict gates the closer we get to PROD.

3. Architecture

DEV: image built, tagged with Git SHA, deployed, smoke-tested │ promote.yml (dev→qa): records DEV's exact image DIGEST ▼ QA: SAME digest deployed (never rebuilt) + full test suite run │ promote.yml (qa→stage): requires QA promotion record to exist │ AND QA's recorded digest == what's being promoted ▼ STAGE: SAME digest + production-like load test │ promote.yml (stage→prod): requires STAGE record + MANUAL APPROVAL │ (Project 19's Workflow approval node) ▼ PROD: SAME digest, zero rebuilds anywhere in the chain
The core guaranteeEvery stage deploys the exact same image DIGEST that the previous stage validated — never a re-tagged or rebuilt version. Promotion literally means "point the next environment at the same immutable artifact," not "build again and hope it's equivalent."

QA → STAGEMediumFull QA test suite passed, digest match confirmed

4. The Playbooks — Fully Commented

4.1 playbooks/promote.yml

playbooks/promote.yml
---
# Promotes ONE immutable image digest from one environment to the
# next, refusing to proceed unless the source environment's own
# promotion record exists and digests match exactly.
- name: Promote {{ app_name }} from {{ from_env }} to {{ to_env }}
  hosts: localhost
  connection: local
  gather_facts: true

  tasks:
    - name: Get the currently-running image digest in the SOURCE environment    # the artifact we're about to promote
      kubernetes.core.k8s_info:
        kind: Deployment
        name: "{{ app_name }}-backend"
        namespace: "{{ app_name }}-{{ from_env }}"
      register: source_deploy                                                    # holds the live Deployment spec

    - name: Resolve the image reference to its immutable digest                   # tags can move; digests cannot -- this is the actual identity we promote
      ansible.builtin.command:
        cmd: "oc image info {{ source_deploy.resources[0].spec.template.spec.containers[0].image }} -o json"  # queries the registry directly
      register: image_info_raw                                                     # raw JSON output
      changed_when: false                                                            # read-only query

    - name: Extract the digest as a fact                                             # parse the JSON for just the digest field
      ansible.builtin.set_fact:
        source_digest: "{{ (image_info_raw.stdout | from_json).digest }}"              # the sha256:... immutable identifier

    - name: If promoting BEYOND dev, require the source env's OWN promotion record to exist  # prevents skipping a stage in the chain
      ansible.builtin.stat:
        path: "promotions/{{ app_name }}/{{ previous_env_lookup[from_env] }}-to-{{ from_env }}-latest.json"  # e.g. dev-to-qa-latest.json when promoting FROM qa
      register: source_record
      when: from_env != 'dev'                                                          # dev is the chain's starting point, has no prior record

    - name: Assert the source environment's own promotion record exists                  # hard stop -- can't promote from an environment that was never itself promoted-into
      ansible.builtin.assert:
        that: [source_record.stat.exists]
        fail_msg: "{{ from_env }} has no promotion record -- it may have been deployed directly, bypassing the chain"
      when: from_env != 'dev'

    - name: Confirm the digest matches what the source env was ITSELF promoted with        # catches a rebuild/re-tag that silently diverged
      ansible.builtin.assert:
        that:
          - (lookup('file', 'promotions/' + app_name + '/' + previous_env_lookup[from_env] + '-to-' + from_env + '-latest.json') | from_json).digest == source_digest
        fail_msg: "Digest running in {{ from_env }} does not match what was originally promoted into it -- investigate before proceeding"
      when: from_env != 'dev'

    - name: Deploy the SAME digest into the target environment                              # the actual promotion action -- never rebuilds, only re-points
      kubernetes.core.k8s:
        state: present
        definition:
          apiVersion: apps/v1
          kind: Deployment
          metadata:
            name: "{{ app_name }}-backend"
            namespace: "{{ app_name }}-{{ to_env }}"
          spec:
            template:
              spec:
                containers:
                  - name: backend
                    image: "{{ source_deploy.resources[0].spec.template.spec.containers[0].image.split(':')[0] }}@{{ source_digest }}"  # repo@digest form -- immutable, unambiguous
      register: promote_result                                                                # capture for assert

    - name: Assert promotion deploy succeeded
      ansible.builtin.assert:
        that: [promote_result is succeeded]
        fail_msg: "Failed to deploy promoted digest into {{ to_env }}"

    - name: Write the promotion record as evidence                                              # the audit trail this whole project exists to create
      ansible.builtin.copy:
        dest: "promotions/{{ app_name }}/{{ from_env }}-to-{{ to_env }}-{{ ansible_date_time.epoch }}.json"  # timestamped, permanent record
        content: "{{ {
            'app_name': app_name, 'from_env': from_env, 'to_env': to_env,
            'digest': source_digest, 'promoted_at': ansible_date_time.iso8601,
            'promoted_by': lookup('env', 'USER')
          } | to_nice_json }}"

    - name: Also write/overwrite the 'latest' pointer for this promotion pair                    # used by the NEXT stage's digest-match check
      ansible.builtin.copy:
        dest: "promotions/{{ app_name }}/{{ from_env }}-to-{{ to_env }}-latest.json"
        content: "{{ {'digest': source_digest, 'promoted_at': ansible_date_time.iso8601} | to_nice_json }}"

6. Live Incident — "PROD Got a Version QA Never Actually Tested"

ReportA bug reaches PROD that QA's test suite should have caught. QA insists they tested this version and it passed.
Step 1 — compare the actual running digests across environments
oc image info $(oc get deploy payment-api-backend -n payment-api-qa -o jsonpath='{.spec.template.spec.containers[0].image}') | grep Digest
Digest: sha256:aaa111...

oc image info $(oc get deploy payment-api-backend -n payment-api-prod -o jsonpath='{.spec.template.spec.containers[0].image}') | grep Digest
Digest: sha256:bbb222...   # DIFFERENT digest -- these are NOT the same artifact
Root cause candidatePROD is running a different image than what's currently in QA — meaning either PROD was deployed independently (bypassing promotion entirely) or the tag was rebuilt at some point after QA validated it.
Step 2 — check the promotion evidence trail
ls promotions/payment-api/
dev-to-qa-1723...json
# qa-to-stage and stage-to-prod records are MISSING entirely
Root causeSomeone deployed directly to PROD using Project 5's release playbook independently, with a freshly-built image from the same source branch — bypassing this project's promotion chain entirely. That rebuild picked up a newer base image layer with a subtly different behavior, which is exactly the class of drift the digest-based promotion chain exists to prevent.
Step 3 — remediate: promote the ACTUAL validated digest properly
ansible-playbook playbooks/promote.yml -e app_name=payment-api -e from_env=qa -e to_env=stage \
  -e previous_env_lookup='{"stage":"qa","prod":"stage"}'
# run the full chain properly, in order, from the last validated point
ansible-playbook playbooks/promote.yml -e app_name=payment-api -e from_env=stage -e to_env=prod \
  -e previous_env_lookup='{"stage":"qa","prod":"stage"}'
Step 4 — validate digests now match end to end
All three environments now report sha256:aaa111... -- the SAME artifact QA actually validated.
ResolvedPROD now runs the exact digest that passed QA's test suite, with a complete promotion record proving it.

7. Additional Break-Fix Labs

Break-Fix — digest mismatch caught mid-chain 
TASK [Confirm the digest matches what the source env was ITSELF promoted with] ***
fatal: [localhost]: FAILED! => {"msg": "Digest running in qa does not match what was originally promoted into it"}

Root cause: someone manually redeployed QA with a different image after the promotion record was written — QA itself drifted. Fix: this is the chain working exactly as designed — investigate why QA changed outside the promotion flow before proceeding, don't just override the check.

Break-Fix — promotion record directory not version controlled, lost on a container rebuild

Symptom: promotion history disappears after the Ansible control node's container is recreated.

Root cause: promotions/ was treated as scratch space instead of durable evidence. Fix: commit the promotions directory to Git (or write records to object storage) — this is compliance evidence and needs the same durability guarantees as the backup bundles from Project 14.

9. Interview Preparation

Interviewer: "How do you guarantee the version tested in QA is the exact version that reaches production?"

Answer: By promoting the image's immutable digest, not its tag, and never rebuilding between stages. My promotion playbook resolves the running image to its sha256:... digest, deploys that exact reference into the next environment, and writes a permanent record. Each subsequent promotion checks that the source environment's own record exists and that its running digest still matches what was originally promoted — so any drift or bypass is caught before it can propagate further.

Interviewer: "A bug reached PROD that QA's tests should have caught — how would you investigate?"

Answer: First question: are PROD and QA actually running the same artifact? Comparing image digests, not tags, answers that immediately. In a real case, they didn't match — PROD had been deployed directly with a freshly-built image, bypassing the promotion chain entirely, which is why the bug that QA's version didn't have showed up anyway. The fix wasn't just re-promoting the right digest; it was restricting direct-deploy access to PROD so that bypass path couldn't happen again.
